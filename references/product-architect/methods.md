# Product Architect · 方法库

> 这是 Product Architect 的「专业能力」参考。目标不是画一棵漂亮的 IA 树，是构建关于「用户如何组织信息」的可验证假设。

---

## 1. 理解使用时刻

### 先问四个问题

```
用户在什么时刻打开产品？ → 早上匆忙？晚上反思？中断后回来？
在那个时刻，认知状态是什么？ → 注意力分散？情绪脆弱？目标明确？
用户最经常找什么？ → 确认今天的任务？回顾进展？发现模式？
用户很少找什么？ → 设置？历史？账号？
```

### 输出

一段「使用时刻」描述，不是用户画像：
> 周五 18:30，写作者已经累了，只想用 3 分钟把「需要老板决定的事」写清楚；周一 9:30，管理者只有 10 分钟，想先看「哪几件事需要我」。

**IA 服务于这个时刻，不服务于内部业务分类。**

---

## 2. 竞争性心智模型

### 为什么至少 2–3 种

一种 LATCH = 没有竞争假说 = 设计师直觉。至少 2–3 种，才能知道「如果选错了，IA 要重做多少」。

### 五种组织方式（LATCH）

| 方式 | 按什么组织 | 例子 |
|---|---|---|
| **Location** | 地点/位置 | 家里/公司/路上 |
| **Alphabet** | 字母/名称 | 联系人 A-Z |
| **Time** | 时间 | 今天/本周/历史 |
| **Category** | 类别 | 工作/生活/学习 |
| **Hierarchy** | 层级/重要性 | 紧急/重要/其他 |

### 每种假说写

- 组织原则
- 用户行为依据（证据 ID）
- 在什么场景最优
- 在什么场景失效

### 关键检验

**如果 A 和 B 能产生相同的 IA 树，你没有真正的竞争假说。**

---

## 3. 快速区分检验（不靠真人）

### 四种检验

1. **用户原话语言模式**：用户更多用时间词（「今天」「最近」）、类别词（「工作」「生活」）、还是进展词（「坚持」「进步」）？
2. **竞品 IA 反推**：竞品用什么组织方式？用户已经被训练成什么习惯？（但不一定跟随——竞品可能都错了。）
3. **因果链时刻**：A2/Definer 的因果链中，产品在哪个时刻介入？那个时刻用户最需要什么信息？
4. **极端用户透镜**：高频用户 / 低频用户 / 流失用户，分别会怎么组织？

### 输出

一张对比表：假说 × 语言模式 × 竞品反推 × 因果链时刻 × 极端用户。

---

## 4. 骨架 IA

### 硬约束

- 一级区域 ≤5 个
- 每个一级下二级 ≤5 个
- 只做前两层，不展开细节
- 每个节点标 ✅/⚠️/🔮

### 结构

```
[产品名]
├── [一级区域 1] — 用户任务：[]
│   ├── [二级 1A]
│   └── [二级 1B]
├── [一级区域 2] — 用户任务：[]
└── ...
```

### 关键检验

一个完全不熟悉产品的人，看到这 5 个一级标签，能在 3 秒内决定点哪个吗？

---

## 5. 标签语言

### 铁律

| ❌ 内部术语 | ✅ 用户语言 |
|---|---|
| 洞察 | 我的进展 / 我发现了什么 |
| 管理 | 我的习惯 / 设置 |
| 仪表板 | 概览 / 今天 |
| 工作流 | 怎么走 |
| 资产 | 我的东西 |

### 来源

- 用户原话（A1/Research 证据 ID）
- 竞品惯例
- 🔮 设计师推断（必须标）

### 陌生人测试自检

给一个不熟悉产品的人看标签，让他猜下面有什么。≥80% 猜对 → 通过；否则重写。

---

## 6. 完整 IA + 内容模型 + 导航

### 完整 IA

- 展开到第 3 层（最深）
- 保持与骨架一致；如果展开时发现骨架要改，回第 2 步
- 每个第 3 层节点标 ✅/⚠️/🔮

### 内容模型

定义核心内容类型 + 关系 + 跨界面一致性约束：

```
内容类型：周报
字段：作者、周期、决策请求、风险、依赖、行动
关系：一条周报 → N 个请求；一个请求 → 一个行动
约束：同一请求不能出现在两个周报里
```

### 导航

- 一级区域用底部 Tab / 侧边栏 / 顶部导航？取决于平台和使用时刻。
- 二级导航与内容类型匹配。
- 不要因为竞品用了某个模式就用——先看用户是否已被训练。

## 7. 用户流

### 每个核心 Job 一条流

```
起点（用户在哪、什么状态、什么触发）
  → 入口
  → 决策点（≤3 个选项）
  → 操作点
  → 完成点
  → 错误恢复
  → 改主意路径
```

### 硬规则

- 每个决策点 ≤3 个选项。
- 错误恢复：不「返回重来」，是「在这里修复，继续前进」。
- 改主意路径：任何一步可以退出/回去。
- 非快乐路径：空/错误/离开-回来/放弃/成长/极端高频。

### 关键检验

一个设计师读完流，能开始画第一个线框图而不需要回来问问题吗？

---

## 8. 状态矩阵

### 每个一级界面 8 状态

| 状态 | 用户看到什么 | 用户能做什么 |
|---|---|---|
| 默认 | 有数据 | 正常操作 |
| 悬停 | 反馈 | — |
| 聚焦 | 焦点环 | 键盘操作 |
| 按压 | 按下反馈 | — |
| 禁用 | 为什么禁用 | 知道怎么解锁 |
| 加载 | 骨架屏 | 等待/取消 |
| 错误 | 具体错误 + 恢复建议 | 重试/离线/以后 |
| 空 | 引导行动 | 创建第一个 |

### 硬规则

- 每个状态标 ✅/⚠️/🔮。
- 空状态是「引导行动」，不是「暂无数据」。
- 错误状态是「具体错误 + 恢复」，不是「出错了」。

## 9. 验证工具

### 不做「建议做 card sorting」

做精确到「一个研究员明天就能执行」的工具包。

### Card Sorting 工具包

- 卡片列表（20–30 张，用用户语言）
- 类型：Open / Closed / Hybrid
- 参与者：核心画像 ×3 + 极端用户 ×1
- 任务描述（给参与者读的脚本）
- 成功标准：分组与 IA 匹配度 ≥70%
- 结果→行动映射表：

| 如果 | 则 |
|---|---|
| 匹配度 ≥70% | IA 骨架确认 |
| 40–70% | 调整二级分类 |
| <40% | 回第 1 步——心智模型假说可能错了 |

### Tree Testing 工具包

- 3–5 个核心任务（场景包装，不是操作指令）
- 每个任务：正确路径 + 常见错误路径 + 成功标准
- 参与者：核心画像 ×5
- 成功标准：成功率 ≥80%，直接性 ≥75%
- 结果→行动映射表（精确到回退到哪一步）

### 陌生人测试工具包

- 一级标签列表
- 标准问题：「猜猜这个标签下面有什么？」
- 成功标准：≥80% 猜测大致正确
- 如果失败：回 Research 找用户原话重写标签

## 10. 信心地图

### 每个节点标

| 标注 | 含义 |
|---|---|
| ✅ | 有用户行为/原话直接支持 |
| ⚠️ | 基于领域逻辑推断，间接支持 |
| 🔮 | 设计师直觉，无直接证据 |

### 汇总

```
✅ 已验证：N 个节点，占 X%
⚠️ 推断：N 个节点，占 X%
🔮 猜测：N 个节点，占 X%
```

### 硬规则

- 🔮 占比 >30% → 在简报中诚实声明「IA 基于大量推断，建议先做低保真原型 + card sorting」。
- 不许把所有节点都标 ⚠️——如果真是这样，在第一段说清楚。

### 合并项规则

如果某个节点的证据来自「A/B/C 合并项」（如「买菜/洗菜/洗碗太麻烦」），它不能被标 ✅——合并项只能证明「这段流程整体有问题」，不能证明「具体哪一步」。标 ⚠️/🔮，并写「待拆解」。

---

## 11. 致命假设 + 回退

### 4 个致命假设

每个：
- 假设内容
- 当前置信度
- 验证方式（引用工具包）
- 如果错了的后果
- 如果错了，回退到哪里

### 回退规则

| 验证结果 | 行动 |
|---|---|
| 匹配度 ≥70% | 骨架确认，进入 A4/Prototype |
| 40–70% | 调整二级分类，保留一级骨架 |
| <40% | 回第 1 步，重新做心智模型假说 |
| 陌生人测试 <80% | 回 Research 找用户原话，重写标签 |

---

## 12. 交接给 Prototype / UI

### 交付

- IA 树 + 导航 + 用户流 + 状态矩阵
- 信心地图：哪些可以大胆设计（✅），哪些要留退路（🔮）
- 验证工具包：研究员明天能执行
- 致命假设 + 回退规则

### 明确说

- 「这些节点是 ✅，可以做大胆设计」
- 「这些是 🔮，要留退路，等验证结果」
- 「这些假设如果错了，回退到第 X 步」

---

## 13. 输出原则

- 结构服务于赌注，不服务于内部逻辑。
- 标签来自用户语言，不是设计师语言。
- 先验证骨架，再展开完整 IA。
- 每个节点有置信度。
- 验证工具精确到可执行。
- 不假装 IA 是「正确」的——它是一个可验证的假设。
