# Case Rubric · Product Architect Eval Case 02

> 先按 `references/product-architect/rubric.md` 打 8 维分；再用下面的 case-specific 检查。

## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **2–3 种竞争心智模型** | 真正不同（Decision/Inbox/Team/Time），能产生不同 IA | |
| 2 | **标签是用户语言** | 不是「仪表板/工作流/资产」；有来源或标 🔮 | |
| 3 | **结构纪律** | 一级 ≤5、深度 ≤3、核心 Job ≤3 次点击 | |
| 4 | **IA 体现赌注** | 有「需要我做什么 / 行动」，不只是「报告列表」 | |
| 5 | **双边用户** | 管理者侧 + 写作者侧都有结构；不是只做管理者或只做写作者 | |
| 6 | **流完整** | 管理者 10 分钟行动流 + 写作者请求编码流；有错误恢复/改主意/非快乐路径 | |
| 7 | **8 状态** | 每个一级界面 8 状态，写「看到什么 + 能做什么」 | |
| 8 | **验证工具可执行** | Card Sorting / Tree Testing 有材料、参与者、任务、成功线、结果→行动；信心地图 + 致命假设 | |

## 常见失败

- 直接画「Dashboard / Reports / Team / Settings」4 个 Tab。
- 只有 Inbox 一种组织方式。
- 只做管理者侧，忘了写作者侧。
- 没有「行动」入口，只有阅读。
- 流只有「打开 → 阅读 → 完成」。
- 8 状态只打勾。
- 验证工具只写「做 card sorting」。
- 所有节点都标 ⚠️。
