# Case Rubric · Product Architect Eval Case 01

> 先按 `references/product-architect/rubric.md` 打 8 维分；再用下面的 case-specific 检查。

## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **2–3 种竞争心智模型** | 真正不同，能产生不同 IA 树；各带证据和失效场景 | |
| 2 | **标签是用户语言** | 不是「食谱/管理/仪表板」；有 E05/E07/E09 来源或标 🔮 | |
| 3 | **结构纪律** | 一级 ≤5、深度 ≤3、核心 Job ≤3 次点击 | |
| 4 | **IA 体现赌注** | 有「买多少/份量/剩菜去处」，不只是「食谱」 | |
| 5 | **流完整** | 决策点 ≤3、错误恢复、改主意、非快乐路径（空/错/离开-回来/放弃/成长/极端） | |
| 6 | **8 状态** | 每个一级界面 8 状态，写「看到什么 + 能做什么」 | |
| 7 | **验证工具可执行** | Card Sorting / Tree Testing 有材料、参与者、任务、成功线、结果→行动 | |
| 8 | **信心诚实 + 交接** | 每个节点 ✅/⚠️/🔮；3–4 个致命假设；明确哪些能大胆设计/哪些留退路 | |

## 常见失败

- 直接画「食谱/买菜/做饭/社区/我的/设置」6 个 Tab。
- 只有 Category 一种组织方式。
- 标签是设计师语言。
- 只有「选择 → 完成」的快乐路径。
- 8 状态只打勾，没写看到什么/能做什么。
- 验证工具只写「做 card sorting」。
- 所有节点都标 ⚠️。
- IA 里没有「剩菜/份量」，和赌注脱节。
