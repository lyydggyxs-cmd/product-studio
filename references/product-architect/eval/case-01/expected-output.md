# Expected Output · Product Architect Eval Case 01

> 一份合格产出必须包含以下内容。不要求选某个特定组织方式；要求结构成立、证据用对。

## 1. 竞争性心智模型

至少 2–3 种真正不同的组织方式，例如：
- **Time**：今天 / 本周 / 历史
- **Task**：决定 / 买 / 做 / 剩菜
- **Inventory**：冰箱里有什么 / 缺什么
- **Category**：按菜系/品类（应作为反例，说明为什么不够好）

每种：
- 组织原则
- 用户行为依据（证据 ID）
- 在什么场景最优
- 在什么场景失效

**必须**说明当前选择和最危险替代假说。

## 2. 骨架 IA

- 一级 ≤5 个
- 每个一级下二级 ≤5 个
- 每个节点标 ✅/⚠️/🔮
- 每个一级区域有明确用户任务
- 标签来自用户语言（E05/E07/E09），不是「食谱/管理/仪表板」

**必须**体现赌注：购买单位 vs 消费单位的错配。IA 里应该有「买多少 / 份量 / 剩菜去处」的位置，不能只有「食谱」。

## 3. 完整 IA + 内容模型 + 导航

- 展开到第 3 层
- 定义 ≥3 种内容类型（如：本周量单、一人份食谱、剩菜记录）
- 定义字段、关系、跨界面一致性约束
- 导航模式说明（为什么底部 Tab / 侧边栏 / 顶部）

## 4. 用户流

至少核心 Job 的完整流：
- 决定这周做哪 2 顿
- 按一人份买
- 做
- 剩菜处理

每条流：
- 起点（时间/状态/触发）
- 决策点 ≤3 个选项
- 错误恢复（就地修复，不返回重来）
- 改主意路径
- 非快乐路径：空/错/离开-回来/放弃/成长/极端

## 5. 状态矩阵

每个一级界面 8 状态：
- 默认/悬停/聚焦/按压/禁用/加载/错误/空
- 每个状态写「用户看到什么 + 用户能做什么」
- 空状态是引导行动，错误是具体恢复

## 6. 验证工具

- Card Sorting：卡片、参与者、任务、成功线、结果→行动
- Tree Testing：任务、正确路径、成功线、结果→行动
- 陌生人测试：标签列表、问题、通过线

**必须**精确到一个研究员明天能执行。

## 7. 信心地图 + 致命假设

- 每个节点标 ✅/⚠️/🔮，汇总占比
- 3–4 个致命假设，每个有验证方式、如果错了的后果、回退到哪一步
- 明确说：哪些节点可以大胆设计，哪些要留退路

## 8. 如果证据不足

如果 Architect 判断证据不足以确定骨架，**写「骨架待验证，先做 card sorting/tree testing」也是合格输出**——只要给出可执行的验证工具和回退规则。
假装确定才是失败。
