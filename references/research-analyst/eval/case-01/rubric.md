# Case Rubric · Eval Case 01

> 先按 `references/research-analyst/rubric.md` 打 8 维分；再用下面的 case-specific 检查。

## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **断裂点不是泛泛的「懒」** | 明确指出是哪一步（决策/买菜/备菜/做/收拾/剩菜），并有证据 | |
| 2 | **至少 2 条竞争假说** | 不只是「用户需要更方便」，而是可区分的解释 | |
| 3 | **区分「想」和「做」** | 有证据说明「想做饭」是行为还是身份愿望 | |
| 4 | **竞品覆盖 4 类** | 食谱 / 买菜 / 预制菜 / 社区团购，各自覆盖哪段、漏哪段 | |
| 5 | **回答「为什么装了多个 App 还是没做」** | 不是「功能不够」，而是链条断裂/摩擦 | |
| 6 | **食材浪费有证据** | 不是「用户怕浪费」，而是具体场景（买多了/不会保存/剩菜不知道怎么处理） | |
| 7 | **访谈问过去行为** | 没有「你会不会」「你觉得」 | |
| 8 | **反证存在** | 至少一条「有些人就是不想做饭」或「做饭不是优先级」 | |

## 常见失败

- 只写「用户想健康、方便、省钱」——这是常识，不是研究。
- 竞品只写食谱 App，漏买菜/预制菜/团购。
- 把「想做饭」当事实，不区分行为和愿望。
- 没有反证。
- 访谈问「你会用吗」。
- 缺口写「需要更多数据」。
