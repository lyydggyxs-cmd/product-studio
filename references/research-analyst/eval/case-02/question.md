# Research Question · Eval Case 02

## 主问题

周报从「要求写」到「有人认真读」之间，最大的断裂点是什么？现有工具分别解决了哪一段、漏了哪一段？

## 子问题

1. **谁在写、谁在读？** 写的人的动机和读的人的动机是否一致？
2. **周报为什么变成表演？** 什么信号让写的人觉得「写了也没人看」？
3. **现有工具各覆盖哪段？** 飞书文档 / Notion / Geekbot / Standuply / Excel / 邮件。
4. **什么情况下周报会被认真读、产生行动？** 异常、风险、跨团队依赖、管理者追问。
5. **管理者要的是「进度」还是「异常信号」？** 这决定产品是做摘要还是做聚合。
6. **远程/混合办公是否放大这个问题？** 有没有反证（有些团队不需要周报）？

## 决策依赖

- 目标用户是一线写作者，还是管理者？
- 先做「写得更快」「自动聚合」还是「管理者摘要」？
- 是否必须集成飞书/Notion/Slack，还是独立工具？

## 约束

- 不要求做一手访谈；产出访谈脚本 + 合成框架。
- 没有网络数据时标 🔮，不要编造。
- 证据 ≥12 条，≤120 行。
