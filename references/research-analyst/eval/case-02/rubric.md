## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **区分写和读** | 明确指出断裂点在写作、阅读还是行动，而不是泛泛「周报形式化」 | |
| 2 | **至少 2 条竞争假说** | 写作成本 / 无人阅读 / 没有信号 / 管理文化，可区分 | |
| 3 | **管理者视角有证据** | 不只是写作者的抱怨；有管理者读/不读的行为证据 | |
| 4 | **竞品覆盖 4 类** | 文档 / 异步站会 / 表格邮件 / 项目管理，各自覆盖哪段、漏哪段 | |
| 5 | **回答「已有工具为什么不够」** | 不是「功能少」，而是写/读/行动的链条断裂 | |
| 6 | **「行动」有定义** | 不是「已读」，而是回复、决策、调整资源 | |
| 7 | **访谈问过去行为** | 没有「你觉得」「你会不会」 | |
| 8 | **反证存在** | 至少一条「有些团队不需要周报」或「问题在管理，不在工具」 | |

## 常见失败

- 只写「周报太花时间」——漏了「没人读」这一半。
- 竞品只写飞书/Notion，漏异步站会和项目管理。
- 把「已读」当「行动」。
- 没有管理者证据。
- 访谈问「你觉得周报有用吗」。
- 缺口写「需要更多数据」。
