# Research Analyst · 正例与反例

> 每个例子都是「同一份材料，两种做法」。读完能判断自己的输出更像哪一边。

---

## 例 1：证据条目

### ❌ 反例

```
E03 · 用户需要更简单的记账方式
- 状态：✅ 已验证
- 来源：行业报告
- 说明：大家都觉得记账太复杂
```

**问题**：
- 「用户需要」是裸断言，不是证据。
- 「行业报告」不可追溯。
- 单源标 ✅。
- 没有「如果错了」。

### ✅ 正例

```
E03 · 自由职业者月底对账时，会因为「不知道哪笔钱到了」而放弃记账
- 状态：⚠️ 推断
- 来源：App Store 差评 12 条（2025-01 ~ 2025-09）+ 2 个 Reddit 帖
- 来源类型：primary（用户原话）
- 置信度说明：差评自选偏差；12 条中 8 条提到「对不上账」，但都是主动抱怨者
- 如果错了：如果用户其实知道哪笔到了，只是懒得记，产品应做「一键导入」而不是「到账提醒」
- 关联问题：Q02
```

**为什么好**：
- 具体到场景，不是「用户需要」。
- 来源可追溯，标了样本和偏差。
- 置信度和「如果错了」都写了。
- 结论指向下一步验证。

## 例 2：竞品拆解

### ❌ 反例

```
竞品 A：有记账、报表、预算、多币种
竞品 B：有记账、报表、预算
竞品 C：只有记账

结论：我们要做多币种 + 更好的报表
```

**问题**：功能对比表；没有战略逻辑、没有结构约束、没有「为什么他们做不了」。

### ✅ 正例

```
## 竞品 A — 「个人财务操作系统」

### 战略画布
- 核心假设：用户愿意为「财务全景」付费，而不是为「记账」付费
- 目标用户：有投资/多账户的中产
- 商业模式：订阅 + 金融服务导流
- 关键指标：连接账户数、月活、金融产品转化

### 体验审计
- Onboarding：强引导连接银行账户，60 秒内看到第一张图
- 核心循环：自动同步 → 分类 → 月度报告
- 中断体验：断连后邮件提醒，但恢复要重新授权
- 30 天后：报告变得重复，用户主要看余额

### 结构约束
- 产品架构：以「账户连接」为中心，手工记账是二等公民（✅ 公开文档）
- 商业模式：金融导流收入要求用户画像完整，因此强推连接（⚠️ 推断）
- 团队基因：金融背景，不擅长轻量工具（🔮 推断）

### 致命弱点
- 不想连接银行账户的用户会离开
- 手工记账体验差

### 可抄袭的
- 60 秒内看到第一张图的 onboarding
```

**为什么好**：战略逻辑、结构约束、致命弱点、可抄袭点；约束标了置信度。

## 例 3：访谈问题

### ❌ 反例

```
1. 你觉得记账 App 好用吗？
2. 你会用一个自动提醒到账的 App 吗？
3. 你愿意为这个功能付多少钱？
4. 你觉得什么颜色好看？
```

**问题**：问观点、问未来意愿、问假设价格、问无关偏好。

### ✅ 正例

```
1. 上一次你发现「有一笔钱没对上」，是什么时候？当时在做什么？
2. 你怎么发现的？先看了哪里，然后呢？
3. 你当时做了什么？用了什么工具/表格/截图？
4. 这件事花了你多久？最后怎么解决的？
5. 你试过别的办法吗？为什么没继续？
6. 如果当时有一个工具能帮你，你希望它在你做什么的时候出现？
```

**为什么好**：问最近一次具体事件、行为链、替代方案、时间成本；不问观点和意愿。

## 例 4：信息缺口

### ❌ 反例

```
## 信息缺口
无
```

**问题**：不可能没有缺口；这是「装全能」。

### ✅ 正例

```
## 信息缺口
| 缺口 | 为什么重要 | 最快补法 |
|---|---|---|
| 不知道自由职业者月收入分布 | 决定定价和付费意愿 | 找 3 个自由职业者问最近 3 个月收入区间 |
| 不知道「对不上账」发生在月初还是月末 | 决定提醒时机 | 5 个访谈追问最近一次的时间 |
| 没有竞品留存数据 | 判断「记账疲劳」是否真实 | 找公开的 App 数据/创始人访谈；找不到就标 🔮 |
```

**为什么好**：缺口具体、有影响、有补法；不假装知道。

## 例 5：决策简报

### ❌ 反例

```
我们调研了市场，发现用户需要更简单的记账工具。建议做一键记账。
```

**问题**：不是决策简报；没有选项、没有证据、没有建议。

### ✅ 正例

```
## 决策 1：先做「到账提醒」还是「一键导入」？

| 选项 | 支持证据 | 反对证据 | 风险 |
|---|---|---|---|
| A 到账提醒 | E03/E07（用户在对账时才发现） | E05（部分用户已知到账） | 银行通知权限 |
| B 一键导入 | E09（用户嫌手工记） | E11（导入格式复杂） | 银行覆盖 |

**建议**：先验证 A 的「对账时刻」，因为 E03 是 ⚠️ 但指向具体场景；B 的导入格式风险更高。
**最快验证**：5 个访谈问「最近一次对账」；2 周内可完成。
```

**为什么好**：决策 × 选项 × 证据 × 建议 × 验证方式；1 页内。
