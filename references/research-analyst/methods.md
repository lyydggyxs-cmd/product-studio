# Research Analyst · 方法库

> 这是 Research Analyst 的「专业能力」参考。开工前读一遍，按任务选方法。
> 原则：方法服务于决策，不服务于产出的完整性。

---

## 1. 证据分级

### 三级

| 标注 | 定义 | 例子 |
|---|---|---|
| **✅ verified** | 直接证据：目标用户真实行为/原话、同行评审 RCT、多个独立来源一致 | 家长访谈逐字稿；App Store 评论原话；Berkowitz 2015 RCT |
| **⚠️ assumed** | 间接证据：类似场景、理论推理、小样本、单一来源 | 「6–8 岁孩子应该能…」；一篇样本很小的研究 |
| **🔮 guess** | 未经实证的推断 | 「家长应该愿意付费」 |

### 来源类型

| 类型 | 说明 |
|---|---|
| **primary** | 一手：用户原话、行为数据、访谈记录、客服工单、自有数据 |
| **secondary** | 二手：论文、行业报告、竞品公开资料、新闻报道 |
| **inference** | 逻辑推断：从已有证据推出，但没有直接观察 |
| **none** | 无来源：必须标 🔮 |

### 硬规则

- 没有来源 → 🔮，不得写成 ✅。
- 单源结论 → ⚠️，即使来源权威。
- 二手引用 → 标「未读原文」，不得写成「研究证明」。
- 每个重要结论写「如果错了会怎样」。

## 2. 三角验证与反证

### 三角验证

一个结论至少两个**独立**来源：
- 不同平台（App Store + Reddit + 访谈）
- 不同方法（访谈 + 行为数据 + 文献）
- 不同人群（核心用户 + 极端用户）

**独立** = 不是同一篇文章被转载三次。

### 反证搜索

每个重要假设，主动搜：
- 「X 失败」「X 不适合谁」「X 的批评」
- 「X 无效」「X 副作用」
- 竞品差评、用户流失原因

**输出**：一条「反证记录」——你找了什么、找到了什么、没找到什么。

## 3. JTBD 与切换访谈

### 核心问题

用户「雇佣」这个产品来完成什么任务？不是「用户需要什么功能」。

### 四力量（Moesta）

| 力量 | 问什么 |
|---|---|
| **推力（Push）** | 现状哪里让他不舒服？什么挣扎时刻？ |
| **拉力（Pull）** | 新方案吸引他的是什么？功能之外的「被理解」？ |
| **焦虑（Anxiety）** | 换方案的担忧：学习成本、数据、看起来蠢、隐私？ |
| **惯性（Habit）** | 为什么留在旧方案？习惯、沉没成本、身份？ |

**判断**：推力 + 拉力 是否显著大于 焦虑 + 惯性？

### 切换访谈

问**最近一次**切换/考虑切换的具体事件：
- 「上一次你因为什么开始找新办法？」
- 「你当时在做什么？几点？在哪？」
- 「你试了什么？为什么没继续？」
- 「最后怎么解决的？」

**不要问**：「你会不会用…」「你觉得…好不好？」

## 4. The Mom Test

### 三条规则

1. **问过去的行为，不问未来的意愿。**
2. **问具体的事，不问泛泛的观点。**
3. **少说，多听；不要推销你的想法。**

### 好问题 vs 坏问题

| ❌ 坏问题 | ✅ 好问题 |
|---|---|
| 「你会用这个功能吗？」 | 「上一次你遇到这个问题时，你做了什么？」 |
| 「你觉得这个想法怎么样？」 | 「最近一次你为这件事花了多少钱/时间？」 |
| 「你需要 X 吗？」 | 「你现在怎么解决 X？哪里最烦？」 |

### 危险信号

- 用户夸你的想法 → 不是证据，是礼貌。
- 用户说「我会买」→ 不是证据，是意愿。
- 用户说「朋友可能会用」→ 不是证据，是转移。

## 5. 竞品拆解

### 不做功能对比表

竞品分析的核心是**战略逻辑**和**结构约束**，不是「他有 A，我也有 A」。

### 每个竞品一页

```
## [竞品名] — 一句话

### 战略画布
- 核心假设（赌什么是对的？）
- 目标用户（为谁设计？）
- 价值主张（一句话承诺）
- 商业模式（怎么赚钱？）
- 关键指标（优化什么？）

### 体验审计
- Onboarding（前 60 秒）
- 核心循环（日常使用）
- 中断体验（中断后发生什么？）
- 30 天后（新鲜感消退后剩下什么？）

### 结构约束（为什么他们做不了我们做的事？）
- 产品架构 / 商业模式 / 品牌认知 / 团队基因

### 致命弱点
- 什么用户会离开？什么场景失效？

### 可抄袭的
- 他们做得最好的一件事
```

### 硬规则

- 每个约束标 ✅/⚠️/🔮——大多数约束分析是 🔮。
- 「可抄袭的」是力量，不是弱点。
- 至少 3 个竞品，覆盖直接/间接/替代方案（包括「用户什么都不做」）。

## 6. 学术检索

### 顺序

1. **Semantic Scholar / OpenAlex**：找 citation-ranked canonical papers。
2. **arXiv**：预印本，注意未同行评审。
3. **PubMed**：医学/心理学。
4. **Google Scholar**：兜底，注意引用链。

### 读什么

- 摘要 → 方法 → 样本 → 效应量 → 局限。
- 不要只读摘要就引用「研究证明」。
- 记录：作者、年份、期刊、样本、效应量、与假设的关系。

### 引用链

- 找到一篇核心论文 → 看它引用了谁（backward）→ 看谁引用了它（forward）。
- 优先读被引用最多的 2–3 篇。

## 7. 评论挖掘

### 来源

- App Store / Google Play（按「最新」+「低分」看）
- Trustpilot / G2 / Capterra
- Reddit / 知乎 / 小红书 / 豆瓣
- 客服工单 / 社群聊天记录

### 提取

- **用户原话**（逐字，不改写）
- **痛点模式**（反复出现的场景）
- **情绪信号**（愤怒、羞耻、惊喜）
- **替代方案**（他们现在怎么解决）
- **流失原因**（为什么不用了）

### 硬规则

- 区分「评论者」和「目标用户」——评论者可能有偏。
- 差评放大，好评沉默；标注样本来源和偏差。
- 不要用一条评论代表「用户都说」。

## 8. 机会评分

### 公式

```
机会分数 = Importance × (1 − Satisfaction)
```

- Importance：这个 Job 对用户多重要（1–5）
- Satisfaction：现有方案满足程度（1–5）

### 用途

- 排序「先验证哪个机会」。
- 不是「开发优先级」；是「验证优先级」。

### 硬规则

- 分数是判断，不是测量；标注 🔮。
- 识别**矛盾区**（两个高重要性 Job 互相冲突）和**完全空白区**（没人服务）。
- 不要用分数掩盖证据不足。

## 9. 访谈设计与合成

### 招募

- 核心用户 ×3–5
- 极端用户 ×1–2（高频/低频/流失）
- 排除：朋友、同事、只想夸你的人

### 脚本结构

1. 热身（2–3 分钟）：背景，建立信任
2. 最近事件回放（15–20 分钟）：具体场景，逐字追问
3. 替代方案（5–10 分钟）：现在怎么解决，为什么
4. 收尾（5 分钟）：还有什么我没问到的？

### 合成

每场 24 小时内：
- 事实时间线（只写发生的）
- 原话摘录（≥5 句）
- 假说编码（拒绝位置/错误反应/家长角色/证据偏好）
- **反例登记**（这一场哪里不符合预期？必填）
- 新问题

### 跨案例

- 模式：≥3/5 一致
- 个案：单独列出，不当结论
- 反例：必须报告

## 10. 置信度校准

### 常见通胀

| 通胀 | 表现 | 修正 |
|---|---|---|
| 把推断写成事实 | 「用户需要 X」没有来源 | 标 🔮 + 写推断依据 |
| 把单源写成共识 | 「研究表明…」只有一篇 | 标 ⚠️ + 写样本局限 |
| 把意愿写成行为 | 「用户说会买」 | 标 ⚠️ + 找支付行为 |
| 把相似场景写成目标场景 | 「成人拖延研究说明 6 岁孩子…」 | 标 ⚠️ + 写年龄外推 |
| 把二手引用写成读过原文 | 「Lally 2010 发现…」 | 标「未读原文」 |
| 合并项拆解 | 把「买菜/洗菜/洗碗太麻烦」写成「洗碗是最大断裂点」 | 合并项只能作为整体证据；具体环节需要同变量证据，找不到就写假设句 |
| 单源主结论 | 8 个管理者 → 「最大瓶颈是读者侧」 | ≤10 人单源只能写「优先验证」，不能写「最可能」；写翻转条件 |

### 校准问句

- 「这条结论，如果被追问来源，我能打开吗？」
- 「如果这条错了，哪个决策会变？」
- 「我有没有只收集支持初始假设的证据？」
- 「我的信息缺口是空的吗？如果是，为什么？」

---

## 11. 输出原则

- **证据库**：一条一行，带 ID、来源、置信度、如果错了。
- **机会图**：Job 层次 + 矛盾区 + 空白区 + 机会评分。
- **访谈工具**：脚本 + 招募 + 合成框架，不是访谈结果。
- **决策简报**：1 页，5–7 个决策 × 选项 × 证据。
- **不写解决方案**：那是 Product Definer 的事。
- **不假装做过访谈**：没有一手数据就诚实标注。
