# UI Designer · 方法库

> 目标不是把结构「涂好看」，是把已验证的结构变成**有观点、可使用、可评审**的产品界面。
> 本方法库把 2026-08-14 审美层研究（六门流水线）适配到纯设计岗：UI Designer 不写生产代码，但同样要过来源、锚定、快照、状态、工艺五道门，并明确哪些判断必须交给人眼。

---

## 0. 工作顺序（不可倒置）

```
参考板 → 设计意图 → 来源过滤 → 轴锚定 → 令牌 → 组件 → 状态 → 快照自检 → 工艺 → 交接
```

**铁律**：工艺（抛光）永远最后。状态未覆盖就抛光，是在错误的地板上打蜡。
**第二铁律**：没有参考板，不动手。凭文字想象做设计，产出一定是均值。

---

## 0.5 参考板（硬步骤）

### 0.5.1 选参考

- 选 **2–3 个**顶级产品，至少一个来自不同品类。
- 只看**真实产品界面**：App Store 截图里的设备框内 UI、产品录屏、官方产品博客里的界面图。
- 营销页的设备框外内容（标题、奖项、渐变背景、口号）不是设计证据。
- 参考可以来自：Things 3、Streaks、Structured、Habitify、Routinery、Bear、Craft、Apple Fitness/Health、Sunsama、Linear、Raycast。

### 0.5.2 拆什么

每个参考写四列：

| 参考 | 学什么（结构 / 工艺参数） | 不学什么（品牌资产 / 营销层） | 用在哪一屏 |
|---|---|---|---|

拆解维度：

1. **构图**：首屏是什么形状？圆环网格、时间轴、卡片流、统计仪表、侧栏+详情？
2. **排版**：大数字多大？标题与正文的字号比？字重上限？字距符号？有没有 serif 角色？
3. **色彩**：主强调色几处？习惯色几个？中性色是暖纸白还是冷灰？完成态怎么编码？
4. **组件**：圆环、打卡按钮、连续天数 chip、热力图、统计卡、空状态、庆祝时刻——各自什么状态？
5. **动效**：打卡反馈时长？庆祝是一次性还是循环？

### 0.5.3 纪律

- **抄结构、抄工艺参数；不抄品牌资产**：构图、密度、字阶、状态处理、组件组合可以学；logo、专属插画、商标、逐像素复刻不碰。
- **参考不是拼贴**：最终只能有一个视觉方向；参考是采样来源，不是设计本身。
- **每个核心屏至少一个视觉锚点**：圆环 / 大数字 / 图表 / 图像卡片 / 图标系统。没有锚点的屏，是文档，不是产品。

### 0.5.4 输出

工作区写 `reference-board.md`：参考表 + 从参考提炼的「本产品视觉语法」+ 明确不学的部分。
已有参考图：`references/ui-designer/reference-board/`（顶级个人工具，8 张产品界面）。

## 1. 设计意图五问

画任何界面前，先用文字回答，不画图：

| 问题 | 取值 | 它决定什么 |
|---|---|---|
| **品牌温度** | 冷 / 中 / 暖 | 灰阶色相、圆角、阴影风格 |
| **信息密度** | 松弛 / 标准 / 紧凑 / 极紧凑 | 基准字号、间距、行高、输入框高度 |
| **动效目的** | 静态 / 反馈 / 引导 | 动效预算与时长 |
| **布局复杂度** | 简单 / 标准 / 复杂 | 导航模式、分栏策略 |
| **参考系统** | 学什么、避免什么 | 采样来源 |

每条都要写「为什么」，并给置信度：✅ 来自上游证据 / ⚠️ 从场景推断 / 🔮 设计直觉。

### 1.1 四刻度盘

| 刻度盘 | 1–3 | 4–6 | 7–9 | 10 |
|---|---|---|---|---|
| 布局复杂度 | 单层导航、≤2 内容区 | 2 层导航、3–5 内容区 | 3 层+、多面板 | 可配置仪表板 |
| 信息密度 | 16–18px 基准、24–32px 卡片间距 | 15–16px、16–24px | 13–14px、8–16px | 12–13px、4–8px |
| 动效目的 | 静态 | 反馈驱动 | 引导增强 | ❌ 产品 UI 禁止 |
| 品牌温度 | 冷：蓝灰 220–240°、圆角 2–4px | 中：纯灰/微暖、4–8px | — | 暖：暖灰 30–60°、6–12px |

**产品类型预设**（未指定时的默认）：

| 类型 | 布局 | 密度 | 动效 | 温度 |
|---|---|---|---|---|
| B2B SaaS Dashboard | 6–8 | 6–8 | 2–4 | 中/冷 |
| Admin Panel | 7–9 | 7–9 | 1–3 | 中 |
| Consumer App | 3–5 | 3–5 | 4–6 | 暖 |
| Developer Tool | 5–7 | 6–8 | 2–3 | 冷 |
| Community Tool | 4–6 | 4–6 | 3–5 | 暖 |

### 1.2 刻度盘 → 令牌（起点，不是答案）

```
DENSITY 1–3: base-font 16px, card-gap 24px, section-pad 48px, input 44px
DENSITY 4–6: base-font 15px, card-gap 16px, section-pad 32px, input 40px
DENSITY 7–9: base-font 14px, card-gap 12px, section-pad 24px, input 36px
DENSITY 10 : base-font 13px, card-gap 8px,  section-pad 16px, input 32px

TEMP 冷: gray-hue 220, radius 2/4px, sharp+minimal shadow
TEMP 中: gray-hue 30,  radius 4/6px, standard shadow
TEMP 暖: gray-hue 45,  radius 6/10px, soft+deep shadow

MOTION 1–2: 无自定义过渡
MOTION 3–5: hover 150ms, active 100ms, skeleton
MOTION 6–7: + 列表 50ms/项, 页面进入 300ms
MOTION 8+ : ❌ BLOCKED
```

**刻度盘给的是默认值，不是设计观点。** 下一节的锚定门负责把「默认」变成「这个产品的选择」。

## 2. 门 1 · 来源过滤

消费任何参考系统、DESIGN.md、抓取令牌表、品牌资产时：

### 2.1 给每个区块打层标签

`marketing | product | docs | brand-identity`。无标签默认视为 marketing。

### 2.2 层间转移规则

| 内容 | 能否跨层转移 | 规则 |
|---|---|---|
| 色板、字体族、字重纪律 | ✅ 可转移 | 标 brand-identity；色彩与排版承载品牌意图 |
| spacing / radius / shadow-elevation / density / display 字号 | ❌ 禁止转移 | 来自 marketing 层的一律丢弃，**不是缩放** |

**为什么**：营销面与产品面的空间语域可以系统性相反。Raycast 公开页是 spacious / rounded / 86px pill，官方产品层是 tight / compact / sharp。把 86px pill 喂进产品 UI 推导，是这条门要防的头号事故。

### 2.3 反转签名测试

凡抽取自公开 URL、且自述 `spacious / rounded / friendly / generous` 的规格，其空间值必须与产品面证据（官方截图、应用 UI 博客、真实产品录屏）交叉核对后才能使用。

### 2.4 没有产品层证据时

回落到产品 UI 结构默认：紧凑间距、4–8px 圆角、分层阴影或发丝线高程。营销规格只作色彩与字体参考。

## 3. 门 2 · ≥5/8 轴锚定

任何可发布界面，8 根可测轴中至少 **5 轴**必须携带**论证过的非默认值**。任何留在默认值的轴，就是 AI 脸出现的地方。

### 3.1 九轴矩阵（开放列表，不是闭合清单）

| 轴 | Stripe | Vercel | Raycast | Linear |
|---|---|---|---|---|
| 强调色纪律 | 品牌紫仅交互元素 | 无强调色，单墨承载 CTA | 红仅作标点 | 七色语义，限制 chrome 蓝 |
| 字距符号 | 负，约 −2% 字号 | 负，−2.4px 扁平 | 正，+0.1–0.8px | — |
| 字重上限 | 300（低语） | 600 封顶 | 400–700 | Inter Display 标题 |
| mono 角色 | 无 | eyebrow 眉题 | 键帽/快捷键 | — |
| 圆角压缩 | 4/5/6px，无 pill | 6px nav + 100px 营销 pill 永不混屏 | 产品层 sharp | tight/sharp |
| 高程机制 | 营销零阴影；产品多层大 blur | 4–12% 黑叠影 + 发丝内环 | 5 级堆叠含白内高光 + 1px 环 | shadow token 随 contrast 缩放 |
| 密度 | 杂志跨页式留白 | 双尺度间距 | 密度即特性 | 提高层级与密度 |
| 暗色优先 | light-first | light-first | 身份暗 #07080a | 对称双模式 |
| 动效 | 色移 + opacity 0.6，无 transform | — | — | — |

**读法**：不是抄某一家，是看「同轴反号 = 不同人格」。Stripe/Vercel 负字距 vs Raycast 正字距；300 字重 vs 600 封顶——差异常常只在一根轴的极性。

### 3.2 两父推导图

```
品牌父 → 强调色政策 / 字重上限 / 字距符号 / mono 角色 / 圆角姿态
语境父 → 密度 / 暗色优先 / 高程机制 / 焦点优先级
```

- **密度从受众与产品类型取，不从品牌人格取。**
- 强调色政策 ← 品牌声量、圆角姿态 ← 自我定位，这两条是解释性归纳，置信度中，锚定时不得当高置信使用。
- 动效轴证据不足，暂不计入 8 轴锚定。

### 3.3 三种失效模式

1. 把语境驱动轴误当品牌驱动轴（密度从人格取）。
2. 只锚定色彩轴凑够 5/8，其余 7 轴全默认——门被形式满足，实质绕过。
3. 把单来源的低置信规格当高置信使用。

### 3.4 输出

一张锚定表：轴 × 取值 × 论证来源 × 置信度。至少 5 行是非默认值。

## 4. 令牌系统

### 4.1 三层结构

```
primitive  →  raw values（oklch / px / ms）
semantic   →  bg-page / text-primary / border-subtle / accent ...
component  →  button-primary-bg-hover / card-shadow ...
```

- **目的命名，永不用 50–900 阶梯号。**
- 页面里不允许裸 hex / 裸 px；所有值引用令牌。

### 4.2 色彩

- 用 OKLCH / LCH 等感知均匀空间推导。
- **染色中性**：不要纯灰纯黑，给中性色加极低彩度（约 0.01 chroma）。纯灰是廉价感的来源之一。
- 语义色：success / warning / error / info，最多四类；颜色只作信息，不作装饰。
- 强调色配给：一个系统只允许一种配给政策——仅交互元素 / 单墨 / 红作标点 / 七色语义。不允许「到处都用一点」。
- 对比度：正文 ≥4.5:1，大字与 UI 元素 ≥3:1。
- 暗色模式与亮色成对映射，组件只引用语义令牌。

### 4.3 排版

- 8px 网格与间距步进；字号阶梯从语义角色出发（display / title / body / caption / mono）。
- 字重上限是一个**人格决策**：300 是低语，600 是克制，700+ 是叫喊。选一个，并全站遵守。
- 字距符号是人格轴上最便宜的差异化：负字距（约 −2% 字号）偏精确、克制；正字距（+0.1–0.8px）偏工具、开发者语境。
- 行长 45–75ch；正文行高 1.5–1.7。
- **禁 Inter 默认参数状态，不是禁 Inter 家族。** 家族是输入，tell 在默认字阶 / 2–3 个默认字重 / 默认字距里。

### 4.4 间距、圆角、阴影

- 间距阶梯：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96，按密度刻度取子集。
- 圆角是家族，不是单值：同一系统内可以有 4/6px 产品圆角与 100px 营销 pill，但**永不同屏混用**。
- **高程不是「用不用阴影」，是语境匹配的工程化阴影**：

| 表面 | 机制 |
|---|---|
| 暗画布（近黑） | 硬阴影 blur 0.5–2.5px + opacity 25–40% + 1px 白内高光 + 1px 环 |
| 亮产品表面 | 4–12% 黑叠影 + 发丝内环，或 50–100px blur 大阴影 |
| 亮营销表面 | 边框 tint + ≥2% 表面亮度差 + 零 box-shadow |

反 slop 的推论：slop 签名是**失控的阴影 + 圆角堆叠**，不是阴影本身。禁阴影会把设计推向另一种错误。

### 4.5 动效

- 仅反馈 / 引导 / 关系；产品 UI 禁止装饰性动效。
- 150–300ms，ease-out-quart / quint / expo；禁 bounce / elastic。
- 只动 transform 与 opacity。
- 每个异步动作必须有 loading + disabled + 标签切换，防止双击提交。

### 4.6 视觉资产（每个核心屏至少一个）

**产品不是文字的容器。** 每个核心屏至少有一个视觉锚点：

| 资产类型 | 用在哪 | 规则 |
|---|---|---|
| **统一图标系统** | 习惯图标、导航、状态 | 同一个 stroke 宽度 / 圆角 / 尺寸；24px 基准；不混用实心与线性 |
| **数据可视化** | 进度、连续天数、周/月回顾 | 圆环、折线、柱状、热力图；一屏最多一个主图；直接标注，不要图表垃圾 |
| **大数字** | 连续天数、完成率、本周次数 | 字号 ≥ 正文 3 倍；tabular-nums；一个屏只让一个数字抢注意力 |
| **图像卡片** | 内容型产品、日记、错题本 | 统一裁切比例；避免 stock photo 感；个人工具优先用插画/图标而非照片 |

**禁止**：

- emoji 当图标（Routinery 的 emoji 是它的选择，不是你的）。
- 纯文字列表 + 分隔线撑满整屏。
- 灰色占位块当「设计稿」。
- 每个资产风格不同（线性图标 + 拟物插画 + 3D 渲染混用）。

**完成态多重编码**：形状（填充/对勾）+ 颜色 + 数字/文字，不只靠颜色。色盲友好，也让「完成」更有仪式感。

## 5. 组件美学规则（10 条）

| 组件 | 规则 | 检查点 |
|---|---|---|
| 卡片列表 | 按信息层级选分隔方式：同级只用间距；主次用背景分层；可交互用 1px border + hover 阴影 | 有没有 border+shadow+背景色三件套堆叠？嵌套 ≤2 层？ |
| 数据表格 | 扫描效率优先：列宽内容驱动、数字右对齐 + tabular-nums、行分隔单线、表头非全大写 | 列宽不是等宽？数字右对齐？ |
| Badge | 传达状态，不装饰：语义色 ≤4 种、同行 ≤2 个彩色 badge、辅助信息用灰度文字 | 有没有装饰性 badge？ |
| 空状态 | 引导行动：首次使用给场景说明 + 行动按钮；无结果给下一步；错误给重试 | 文案是不是「暂无数据」？ |
| 表单 | 标签在上不在左；一个输入框只做一件事；placeholder 不是标签；输入框 ≥40px；主按钮左对齐 | 无 placeholder-as-label？ |
| 导航 | 按重要性分权重；当前页有明确指示；≤5 项顶部导航，≥8 项侧边导航；移动端 ≤5 项底部 Tab | 当前页指示清楚？ |
| 按钮 | 每屏 ≤1 个 primary；每个按钮 ≥5 状态；破坏性操作用 outline/ghost 红，不用实心 primary | 有没有两个实心主按钮？ |
| 列表项 | 一行扫描：主标题最左、状态紧跟、元信息灰度靠右；同类项不用分割线 | 最重要信息在最左？ |
| 模态框 | 除非必要不用：确认/独立任务才用；遮罩可关闭、ESC 可关闭；宽度 320–560px | 是否真有必要？ |
| Toast | 瞬时，不打断：success/info 3–5s 自动消失；warning/error 需确认；移动端在拇指区 | 内容 ≤2 行？ |

## 6. 门 5 · 状态覆盖（在快照和工艺之前）

### 6.1 每个核心组件 ≥5 态

`default / hover / focus / active / disabled / loading / error / empty`（按组件取子集，按钮至少 5 态）。

### 6.2 每个核心界面覆盖非快乐路径

| 状态 | 要求 |
|---|---|
| 空 | 引导行动，不是「暂无数据」 |
| 错误 | 具体错误 + 就地恢复，不是「出错了」 |
| 加载 | 骨架屏或进度，不是白屏 |
| 禁用 | 说明为什么禁用、怎么解锁 |
| 极端数据 | 超长文本、零数据、100+ 列表、部分失败、离线 |

### 6.3 三条硬检查

- **零 affordance 谎言**：看起来能点的必须能点；不能点的不能做成长得像按钮。
- **零双击提交路径**：每个异步动作在请求期间必须有 disabled / loading / 标签切换。
- **状态必须在渲染里可见**：加载 / 错误 / 离线 / 空 / 中断后，至少各有一张实际屏幕或状态页；只在规格里写「已覆盖」不算覆盖。

## 7. 门 4 · 快照自检

每输出一屏，做一次「第一眼」检查。品质判断先在第一眼形成，第一眼失败，后面所有层都不会被公正评价。

### 7.1 四项 slop-tell

1. 渐变滥用（尤其紫色渐变 + 大面积背景）
2. Inter 默认参数状态（默认字阶、2–3 个默认字重）
3. 统一卡片网格（四张等宽等高卡片反复排列）
4. 统一圆角 + 阴影堆叠（所有元素同一个圆角、同一种阴影）

### 7.2 三改动地板

至少改三样：主色 / 圆角家族 / 字体配对。只换主色 = 只做了 1/3。

### 7.3 通过测试

5 秒模糊 / squint 快照，不能指纹化为 shadcn / Tailwind 默认页。如果截图缩小后看起来像任何一个 AI 生成的 SaaS 模板，不通过。

### 7.4 边界

内部工具 / 原型场景此门可整体降级——泛化在这个语境里是恰当的。对外产品面不可降级。

## 8. 门 6 · 工艺门 + 人类检查点

### 8.1 工艺永远最后

只在快照与状态两门通过后，才投资工艺：非默认字体配对、更暖的中性色、有呼吸感的动效时序。

### 8.2 人类检查点的形状

- **≤3–5 个评估屏**（核心流程的主屏），不是全部页面。
- **3 个变量**：字体配对 / 中性色暖度 / 动效时序。总抛光精力封顶约 15–20%。
- **通过标准**：与两个参考系统的专家比较，而不是「我觉得好看」。
- 签名层（定制字体、OpenType 风格集、拒绝性决策）只能由人指定，生成侧不进入。

### 8.3 UI Designer 必须诚实列出的「需人眼」项

- 品牌感 / 温度是否成立
- 字体配对与字距曲线
- 中性色暖度与染色程度
- 动效时序的「呼吸感」
- 任何「看起来高级但说不出为什么」的地方

**这些必须标 ⚠️/🔮，不能标 ✅。** 假装 AI 能判断美，是最严重的信心通胀。

---

## 9. 门 3 · 令牌生成引擎（可选）

**触发条件**：>20 个主题组件，或多主题场景。**单主题小应用手挑更优，不要过度工程化。**

### 9.1 骨架 × taste vector

- **骨架**（硬编码，不随品牌变）：感知均匀色彩空间全程运算、输入 = base / accent / contrast 三个值、敏感度排序不变（表面 > 控件 > 边框 > 文本反相关）、目的命名、递归高程。
- **taste vector**（每次运行推导）：敏感度除数与符号、中性色调旋转、降彩速率、强调色配给、圆角家族、排版参数向量。

### 9.2 两条警告

- Linear 的常数（除数 30/70/10 等）是**默认模板，不是普适常量**——它之外没有独立证据。
- 引擎输出是 90% 基线，不是成品；最后 10% 归工艺门与人类检查点。

### 9.3 状态变体配方（可选参考）

若需要系统化推导状态变体：hover 提亮 / 降彩、sub 明显分层、shade 压暗；边框在明暗两套配方下取值不同；文本由理想前景色（黑/白）加 contrast 缩放推导。**这些是配方，不是普适真理**；单主题项目手挑即可。

## 10. 参考系统学习法

- 学**结构**，不抄**皮**：学信息层级、间距节奏、状态设计、令牌结构，不抄具体色值、圆角、阴影。
- 每个参考写清：学什么、避免什么、证据来自产品层还是营销层。
- 竞品都用的模式不等于最优——先判断用户是否已被训练，再决定跟随或逆着。
- 至少一个参考来自**不同品类**，防止同品类均值化。

## 11. 边界条件决策表

| 变量 | 取值 | 调整 |
|---|---|---|
| 密度带 | Polished Standard 产品 UI | 全门满血 |
| 密度带 | 消费 / 展示 / 编辑型 | 地板规则的承载比例下降，尾部变宽；人类检查点从「可选」升级为主路径 |
| 产品档位 | MVP / 内部工具 | 来源过滤 + 快照即可；快照门可降级；引擎不启用；无人类检查点 |
| 产品档位 | flagship | 六门全开 + 人类尾部校准（3 变量 × ≤5 屏） |
| 竞品仍 slop | — | 快照门单独捕获大部分差异化，工艺预算可缩减 |
| 竞品全 premium | — | 快照门是入场券，剩余方差在工艺门，预算必须花满 |
| 文化敏感维度 | — | 不套用西方默认；色彩语义 / 装饰密度交人判断 |
| 引擎规模 | >20 主题组件 | 引擎启用 |
| 引擎规模 | 单主题 | 引擎关闭，手挑 + 轴锚定 |

## 12. 交接

### 给 Design Critic

- 设计系统 + 高保真界面 + 设计理由
- 明确说：这轮重点设计了什么、没设计什么、哪些是假设
- 自检结果用结构化格式：`{维度, 严重度 info/warn/fail, 区域, 可观察证据, 置信度}`——**不给聚合分**，聚合分会被优化成新的局部均值

### 给 Prototype Designer

- 哪些结构已验证、哪些还要验
- 哪些视觉决策会反过来影响结构

### 给 Product Architect / Definer 反哺

- 「这个 IA 节点在真实界面里放不下 / 找不到」
- 「状态矩阵缺了一个关键状态」
- 「用户必须先完成 X 才能到核心价值，但 X 不在本期范围」

### 交接时必须回答

1. 哪些可以大胆设计（✅）
2. 哪些要留退路（🔮）
3. 哪些等验证结果
4. 哪些审美判断需要人眼确认

## 13. 输出原则

- 没有参考板不动手；参考是采样来源，不是拼贴。
- 每个核心屏至少一个视觉锚点；没有锚点的屏是文档，不是产品。
- 系统先于页面；令牌先于组件；组件先于界面。
- 每个关键决策能追溯到赌注 / IA / 场景 / 刻度盘。
- 状态不是清单，是「用户看到什么 + 能做什么」。
- 空状态引导行动，错误状态就地恢复。
- 不假装能判断美；把需要人眼的部分诚实地交出去。
- 不做生产代码；HTML/CSS 只作为设计件与可点击原型。
