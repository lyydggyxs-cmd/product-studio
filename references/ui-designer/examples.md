# UI Designer · 正例与反例

> 每个例子都是「同一份材料，两种做法」。读完能判断自己的输出更像哪一边。
> 案例语境：个人工具（习惯养成 / 错题本）；个别例子沿用做饭语境，但方法通用。

---

## 例 1：设计意图

### ❌ 反例

> 品牌温度：暖。信息密度：标准。动效：适度。
> 整体追求高级感、呼吸感和氛围感，让用户感到舒适。

**问题**：每一句都正确，但每一句都不能指导任何具体决策。「高级感」不是设计意图，是形容词。

### ✅ 正例

| 维度 | 取值 | 为什么 | 置信度 |
|---|---|---|---|
| 品牌温度 | 暖，但克制（暖灰 40°，不用暖黄背景） | 用户是独居青年，做饭是照顾自己的行为，不是亲子/社区场景；暖度要够但不甜 | ⚠️ 从 bet-book 场景推断 |
| 信息密度 | 标准偏紧凑（15px 基准、16px 卡片间距） | 核心任务在周末 30 分钟内完成，用户注意力在「买多少 / 做几顿」，不在浏览 | ✅ ia-flows 的核心 Job |
| 动效目的 | 仅反馈（150ms） | 工具型任务，动效不承载引导；剩菜提醒用一次性提示而非循环动画 | ⚠️ 推断 |
| 布局复杂度 | 简单（一级 4 区、单列为主） | IA 只有 4 个一级区域，核心 Job 3 次点击 | ✅ ia-flows：一级 4 个 |
| 参考系统 | 学 Linear 的令牌纪律与 Raycast 的密度；避免 Stripe 营销页的大留白 | 产品 UI，不是营销页 | ⚠️ 方法库默认 |

**反模式（至少 3 条）**：紫色渐变 hero、统一四卡网格、emoji 当标题、营销式 96px 段间距。

## 例 2：空间语域

### ❌ 反例

> 首页 hero 上下 padding 96px，标题 48px，卡片间距 32px，营造呼吸感。

**问题**：这是营销页的空间语域。产品界面首屏是工作区，用户来这里是为了「这周吃什么 / 买多少」，不是为了被打动。

### ✅ 正例

> 首屏不需要 hero。顶部是本周状态条（第 1 行：这周 2 顿的进度；第 2 行：还缺什么），下面直接是 4 个任务入口。
> 页面 padding 24px，标题 24px，卡片间距 16px，正文 15px。
> 唯一的大留白在空状态——因为空状态需要把注意力收束到「创建第一顿」这个动作上。

**为什么好**：空间值跟着任务走，不跟着「风格」走；留白被当成注意力工具，不是装饰。

## 例 3：轴锚定

### ❌ 反例

> 主色：#FF7A45（暖橙）。圆角 8px。字体 Inter。阴影 0 2px 8px rgba(0,0,0,0.1)。
> 8 个轴全部使用默认值，只把主色从蓝改成橙。

**问题**：只锚定了一根轴，而且是最不具差异性的色彩轴；其余 7 轴全是默认值——这就是 AI 脸。

### ✅ 正例

| 轴 | 取值 | 论证 |
|---|---|---|
| 强调色纪律 | 暖橙仅用于「买多少」与主操作；剩菜状态用琥珀文字，不用色块 | 品牌温度 + 任务优先级 |
| 字距符号 | 正文 −0.01em，标题 −0.02em | 精确、克制的工具感 ⚠️ |
| 字重上限 | 600（不用 700+） | 低语式层级，避免喊叫 |
| mono 角色 | 数字与份量用 tabular-nums；不用 mono 字体族 | 量单需要纵向对齐 |
| 圆角家族 | 输入/按钮 8px，卡片 12px，不用 pill | 产品圆角，不做营销 pill |
| 高程机制 | 亮产品表面：4–8% 黑叠影 + 发丝内环；列表项不用阴影 | 语境匹配 |
| 密度 | 标准偏紧凑（15px/16px） | 来自 ia-flows 的任务节奏 |
| 暗色优先 | light-first，但给暗色令牌映射 | 使用场景多在白天/厨房 |

**为什么好**：8 轴里 8 轴都有取值和论证，其中 6 轴明确非默认；色板只是其中一根轴，且配给被写死。

## 例 4：令牌纪律

### ❌ 反例

```css
.card { background: #FFFFFF; border-radius: 12px; padding: 20px; box-shadow: 0 2px 8px #0000001a; }
.title { font-size: 22px; color: #1A1A1A; }
```

**问题**：页面里发明了 4 个新值（#FFFFFF、12px、20px、22px），令牌系统形同虚设；下一屏会出现 14px 和 18px，系统开始漂移。

### ✅ 正例

```css
.card { background: var(--color-bg-surface); border-radius: var(--radius-card); padding: var(--space-5); box-shadow: var(--shadow-card); }
.title { font-size: var(--text-title); color: var(--color-text-primary); }
```

**为什么好**：所有值来自令牌；改密度或温度时只改一层；页面里没有裸值。

## 例 5：状态覆盖

### ❌ 反例

> 状态：默认、悬停、聚焦、禁用。✅ 完成。

**问题**：只打了勾，没有设计每个状态「用户看到什么、能做什么」；加载、错误、空状态全部缺席。

### ✅ 正例

| 状态 | 用户看到什么 | 用户能做什么 |
|---|---|---|
| 默认 | 「这周量单」4 项，含份量与价格 | 勾选、替换、少买一道 |
| 空（第一次） | 「还没有量单。先定 1 道菜，量单才有东西算。」+ 基础三样（米/油/盐） | 选一道菜 / 用模板 |
| 加载 | 3 行骨架屏 + 「正在算份量」 | 等待，可取消 |
| 错误（缺货） | 「五花肉缺货。3 个替代：梅花肉 / 鸡腿 / 少做一顿。」 | 就地替换，不返回重来 |
| 错误（起送差 10 元） | 「还差 10 元起送：少买一道 / 去菜场补 / 只做一顿。不推荐凑单。」 | 三选一 |
| 极端（一个人吃不完） | 「这道菜 4 人份，你一个人。改成 2 人份？」 | 改份量 / 留着下周 |

**为什么好**：每个状态都有「看到什么 + 能做什么」；错误是就地修复；空状态引导行动。

## 例 6：快照自检

### ❌ 反例

> 首页：紫色渐变背景，居中大标题，下面 4 张等宽等高卡片，每张一个 emoji 图标 + 标题 + 两行说明，圆角 16px，阴影 0 4px 16px。

**问题**：四项 slop-tell 中了四项；squint 一下就是任何一个 AI 生成的 SaaS 模板；三改动一项都没做。

### ✅ 正例

> 首页不是卡片网格，而是一条「本周状态条 + 三个任务入口」的非对称布局：
> 左侧是本周进度（2 顿 / 还缺 3 样），右侧是主操作「继续买」；下面是三条不同权重的任务行（买多少 / 做多了怎么办 / 这周记一笔），用分隔线而非卡片。
> 主色只在「继续买」和份量数字上出现；圆角家族 8/12px；标题字重 600、负字距；无渐变。

**为什么好**：布局形状本身承载任务优先级；颜色有配给；squint 后能认出这是「做饭数量闭环」，不是通用模板。

## 例 7：人类检查点

### ❌ 反例

> 我认为这套设计已经达到顶级产品 UI 水准，审美上没有问题。

**问题**：假装 AI 能判断美；没有列出任何需要人眼确认的项；把审美判断标成了 ✅。

### ✅ 正例

> **已完成且可自动检查**：对比度（正文 6.1:1）、触控目标（44px）、令牌一致性（0 个裸值）、状态覆盖（4 个核心界面 × 8 态）、快照 slop-tell（4 项均未命中）。
>
> **需要人眼确认（未验证）**：
> - 暖灰 40° 是否「暖得刚好」——当前是 ⚠️ 推断，可能在厨房光线下偏黄。
> - 标题字重 600 + 负字距的组合是否有「精确但不冷」的感觉——🔮。
> - 动效 150ms 的节奏是否够「轻」——🔮，建议在真机上做一次 3 人盲评。
>
> **签名层（不由我决定）**：字体配对最终选型、是否使用定制字体、品牌图形语言。

**为什么好**：把可自动检查的和必须人眼的分开；审美判断诚实标 🔮；不越权决定签名层。

## 例 8：交接

### ❌ 反例

> 附件是设计稿和设计系统，请查收。

**问题**：Critic 不知道重点看什么；Prototype 不知道哪些结构已验证；下游可能把假设当事实。

### ✅ 正例

> **这轮设计了什么**：4 个一级区域的默认态与空态、量单主流程、剩菜处理流。
> **没设计什么**：设置页、账号体系、社区（不在本期范围）。
> **可以大胆设计（✅）**：量单的份量计算与「不凑单」提示——有 bet-book 与 ia-flows 的直接支持。
> **要留退路（🔮）**：「卡在哪」的 6 阶段分类界面——架构师明确标为待验证，这轮只做了最小可切换版本。
> **等验证结果**：首屏默认入口是「这周吃什么」还是「买多少」——T2 树测结果出来前不要锁死。
> **需 Critic 重点看**：空状态是否真的引导行动；错误恢复是否就地；颜色配给是否守住了。

**为什么好**：下游能直接按交接信息排优先级；哪些能大胆、哪些留退路、哪些等验证一目了然。

## 例 9：参考系统

### ❌ 反例

> 参考 Linear，所以我们用深色背景 + 紫色强调色 + 细边框。

**问题**：抄了皮，没学结构；Linear 的核心是令牌纪律、状态覆盖、配给政策，不是「深色 + 紫色」。

### ✅ 正例

> 从 Linear 学三件事：①三值输入 → 令牌族的推导方式；②状态覆盖作为 go/no-go 门；③强调色只在交互元素上出现。
> 不学：具体的深色底与紫色、具体的圆角数值、具体的阴影参数——那些是 Linear 的 taste vector，不是普适规则。
> 从 Raycast 学：密度是特性，焦点状态是硬 bug。不学：mono 键帽——本产品没有键盘优先场景。

**为什么好**：学的是可迁移的结构与纪律；明确写出不学什么，防止皮相抄袭。

## 例 10：参考板

### ❌ 反例

> 参考 Things 3，所以用它的蓝色侧边栏和三个栏目布局。

**问题**：没有参考板；只记住了「产品名 + 一个视觉特征」；实际做出来既不像 Things 3，也没有自己的方向。

### ✅ 正例

| 参考 | 学什么 | 不学什么 | 用在哪一屏 |
|---|---|---|---|
| **Streaks** | 2 列圆环网格；每个习惯一个图标；圆环内显示连续数字；完成态三重编码 | 高饱和渐变背景、品牌红、粗白描边 | 今天 / 总览 |
| **Things 3** | 列表工艺：极细分隔线、复选框、层级靠字重与留白；侧边栏低饱和色点 | Mac 三栏布局、品牌蓝、桌面端密度 | 习惯列表 / 详情 |
| **Structured** | 时间轴：彩色节点 + 时间标签 + 右侧完成圆环；日期条显示当天负荷 | 糖果色全家桶、emoji 图标 | 一天的时间轴 |

**提炼出的本产品视觉语法**：

- 构图：今天屏 = 圆环网格；习惯详情 = 卡片流；回顾 = 统计仪表。
- 排版：连续天数用 48px 大数字；标题 24px / 正文 15px；数字 tabular-nums。
- 色彩：暖纸白底 + 一个主强调色；每个习惯 4–6 个低饱和色之一；完成态 = 填充圆 + 对勾 + 数字。
- 资产：统一 24px 线性图标；不使用 emoji。
- 动效：圆环填充 250ms；连续里程碑一次性庆祝。

**为什么好**：参考被拆成可执行的参数，且明确不学品牌资产；最终只有一个方向。

## 例 11：视觉锚点

### ❌ 反例

> 今天
> ——————
> 跑步 3/6 km
> 阅读 0/30 min
> 拉伸 未完成
> ——————

**问题**：纯文字 + 分隔线；没有视觉锚点；用户看不到「进度」，只能读到「状态」；和系统备忘录没有区别。

### ✅ 正例

> **今天**屏：
> - 顶部：本周完成率 **78%**（48px 大数字）+ 连续 **12 天**（chip）
> - 主体：2 列圆环网格，每个习惯一个图标 + 圆环进度 + 圆环内数字
> - 底部：7 日热力图，今天高亮
> - 完成：圆环填充 + 对勾 + 数字三重编码；打卡时圆环 250ms 填充
> - 空状态：一个习惯也没有时，显示「从一个小到不可能失败的习惯开始」+ 3 个模板
>
> **回顾**屏：
> - 一个折线图（本周完成率）+ 一个柱状图（按天）+ 最佳连续天数
> - 大数字只留一个：本周完成率

**为什么好**：每屏都有视觉锚点；数据是主角；完成态多重编码；空状态引导行动。

## 例 12：个人工具不是企业后台

### ❌ 反例

> 顶部工具栏 + 左侧导航 + 数据表格 + 筛选器 + 分页；每屏都是「标题 + 列表 + 分隔线」。

**问题**：把个人工具做成了 B2B 后台；密度过高、没有情绪、没有庆祝时刻；用户每天打开它不会有任何愉悦感。

### ✅ 正例

> - 一屏只做一件事：今天 / 习惯 / 回顾，三个一级区域，不堆功能。
> - 密度 4–6，不是 7–9；留白用于聚焦，不是营销。
> - 有庆祝时刻：完成全部习惯、连续 7 天、连续 30 天各一次；可关闭。
> - 有「人味」：文案具体、有温度但不甜腻；空状态是邀请，不是报错。
> - 工具型纪律保留：令牌、状态、对比度、焦点态一个不少。

**为什么好**：个人工具的高级感来自「克制的功能 + 有温度的细节 + 数据可视化」，不是来自更多面板。
