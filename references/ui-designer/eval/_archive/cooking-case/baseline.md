# Baseline · UI Designer Eval Case 01

> 一个**没有能力包**的通用 Agent 通常会产出什么。评分时先读这个，避免把「页面更多、截图更漂亮」误判为「能力包有效」。

## 典型产出

1. **视觉方向**：「温暖、友好、简约」；配色是紫色渐变或暖橙 + 白底。
2. **布局**：顶部大标题 hero + 四张等宽等高卡片（食谱推荐 / 买菜清单 / 做饭步骤 / 剩菜利用），每张一个 emoji。
3. **导航**：6 个底部 Tab（首页 / 食谱 / 买菜 / 做饭 / 社区 / 我的）——直接照抄 Architect 可能画出的通用 IA。
4. **令牌**：有颜色 / 字号表，但页面里仍然出现裸 hex 和临时 px；没有语义层。
5. **组件**：按钮只有 default / hover；卡片全是 16px 圆角 + 同一阴影；没有空 / 错 / 加载设计。
6. **状态**：「默认、悬停、点击、禁用」4 个，打勾即完成。
7. **空状态**：「暂无数据」。
8. **设计理由**：「采用温暖的配色和圆角设计，营造舒适、高级的体验。」
9. **置信度**：全部 ⚠️，或没有标注。
10. **交接**：只交设计稿，没有说明哪些是假设、哪些待验证。

## 它缺什么

- 没有设计意图的可执行版本（「温暖」不落到灰阶色相 / 圆角 / 字重）。
- 没有来源过滤：把营销页的空间值（大留白、48px 标题）用于产品 UI。
- 没有轴锚定：只换主色，其余 7 轴全默认。
- 没有令牌纪律：页面里裸值漂移。
- 状态覆盖不全，空 / 错 / 加载缺失或公式化。
- 密度是营销页的，不是任务型产品的。
- 审美判断全部标 ✅，没有人类检查点。
- 和赌注脱节：界面里没有「买多少 / 份量 / 剩菜去处」的核心位置。
- 交接没有「哪些大胆 / 哪些退路 / 哪些等验证」。

## 评分提示

如果产出和 baseline 的差别只有「页面更精致、截图更多、文案更暖」，以上缺项仍在 → 能力包没有生效。
