# Brief · UI Designer Eval Case 01（周末做饭助手）

## 产品

面向一线城市独居青年（22–30 岁）的「周末做饭」助手：帮用户决定做什么、买什么、怎么不浪费，让周末真的做上 1–2 顿饭。

## 本次任务

上游已经完成调研、定义、需求与 IA：

| 输入 | 来自 | 你要从中读什么 |
|---|---|---|
| `evidence-base.md` | Research Analyst | 用户场景、原话、约束 |
| `bet-book.md` | Product Definer | 核心赌注、成功信号、kill 信号 |
| `prd.md` | Product Definer | 活 PRD：范围、Anti-goal、当前版本 |
| `ia-flows.md` | Product Architect | 4 个一级区域、用户流、状态矩阵、信心地图、哪些能大胆设计 |
| `validation-toolkit.md` | Product Architect | 哪些结构待验证、验证工具与回退规则 |

把这些结构变成产品 UI。

## 要产出什么

在工作区写四个产物：

1. **`design-system.md`**
   - 设计意图五问（品牌温度 / 信息密度 / 动效目的 / 布局复杂度 / 参考系统）
   - 令牌系统（颜色 / 字体 / 间距 / 圆角 / 阴影 / 动效）
   - 组件定义（用途 / 结构 / 状态 / 可访问性 / 禁止用法）
   - 页面清单
   - 不确定与需人眼确认
2. **`ui-spec.md`**
   - 每个核心页面的结构、状态、交互、文案、响应式
3. **`screens/`**
   - ≥3 屏高保真 HTML/CSS（设计件，不是生产代码）
   - 至少覆盖：主流程默认态 + 一个空状态 + 一个错误状态
4. **`design-rationale.md`**
   - 关键视觉决策的理由（追到赌注 / IA / 场景 / 刻度盘）
   - 哪些 ✅ 可以大胆设计 / 哪些 🔮 要留退路 / 哪些等验证
   - 哪些审美判断需要人眼确认
   - 没有设计什么

## 约束

- 只做产品 UI：不做品牌识别、logo、营销页
- 不写生产代码：HTML/CSS 只作为设计件与可点击原型
- 页面里不允许裸 hex / 裸 px，所有值引用令牌
- 先系统，后页面
- 状态覆盖先于工艺抛光
- 每个关键决策带置信度（✅ / ⚠️ / 🔮）

## 什么算成功

- 界面能追溯到核心赌注（「买多少 / 份量 / 剩菜去处」在界面上有位置）
- 不是通用食谱 App 的模板：4 个一级区域围绕数量闭环
- 8 轴中至少 5 轴有论证过的非默认值
- 核心组件 ≥5 态；核心界面覆盖空 / 错 / 加载 / 极端
- 下游（Critic / Prototype）能看懂哪些大胆、哪些留退路、哪些等验证

## 明确不做

- 账号体系、设置页、社区、课程
- 外卖 / 餐厅 / 预制菜供应链
- 品牌视觉、营销页、logo
- 生产级前端工程

## 时间盒

45–60 分钟。先跑通「意图 → 令牌 → 组件 → 3 屏 + rationale」，不要追求页面数量。
