# Expected Output · UI Designer Eval Case 01

> 一份合格产出必须包含以下内容。不要求选某个特定视觉风格；要求「意图可追溯、系统先于页面、非默认性、状态覆盖、密度正确、工艺达标、信心诚实、交接清楚」。

## 1. 设计意图

- 五问全部回答：品牌温度 / 信息密度 / 动效目的 / 布局复杂度 / 参考系统
- 每一项有「为什么」和置信度（✅ / ⚠️ / 🔮）
- 至少 3 条明确的反模式（禁止的视觉做法）
- 意图能指导具体令牌选择，不是「高级感 / 呼吸感」这类形容词

## 2. 来源过滤与轴锚定

- 说明参考系统里哪些来自 marketing 层、哪些来自 product 层
- marketing 层的 spacing / radius / shadow / density / display 字号被丢弃，而不是缩放
- 一张锚定表：≥5/8 轴有论证过的非默认值
- 每轴写：取值 / 论证来源 / 置信度
- 至少一根排版轴和一根结构轴，不是只锚定颜色

## 3. 令牌系统

- 三层结构：primitive / semantic / component（或等价分层）
- 颜色：感知均匀空间推导；染色中性（非纯灰）；语义色 ≤4 类；强调色配给政策明确
- 字体：字号阶梯 / 行高 / 字重上限 / 字距符号 / mono 角色
- 间距：8px 网格与阶梯
- 圆角：家族，不是单值；不混屏
- 阴影：语境匹配的工程化阴影（暗画布 / 亮产品 / 亮营销三套逻辑）
- 动效：150–300ms、ease-out、只动 transform/opacity、禁装饰性
- 页面里零裸 hex / 裸 px

## 4. 组件

- ≥6 个核心组件（按钮 / 输入 / 卡片 / 列表 / 导航 / 状态标签 / 空状态等）
- 每个组件：用途 / 结构 / 状态（≥5）/ 可访问性 / 禁止用法
- 组件美学规则落实：卡片分隔不过度、表单标签在上、每屏 ≤1 primary、Badge 非装饰、Toast 不打断

## 5. 页面与状态

- ≥3 屏高保真 HTML/CSS
- 至少覆盖：主流程默认态 + 一个空状态 + 一个错误状态
- 每个核心界面覆盖 8 态（或说明为什么某些态不适用）
- 每个状态写「用户看到什么 + 用户能做什么」
- 空状态引导行动；错误就地恢复；异步动作有 loading + disabled + 标签切换
- 极端数据：超长文本 / 零数据 / 大列表 / 部分失败至少各有一个处理

## 6. 密度与工艺

- 信息密度是产品 UI 的，不是营销页的（没有 hero、没有 96px 段间距）
- 对比度：正文 ≥4.5:1，大字 / UI ≥3:1
- 触控目标 ≥44px
- 焦点可见；键盘可达
- 行长 45–75ch；行高与字阶一致
- 快照检查：四项 slop-tell 未命中；5 秒 squint 不指纹化为通用模板

## 7. 信心诚实与人类检查点

- 明确分开「可自动检查」与「需人眼」
- 审美判断（温度 / 字体配对 / 中性色暖度 / 动效时序 / 签名层）标 ⚠️ 或 🔮，不标 ✅
- 人类检查点写成形状：≤3–5 屏 / 3 个变量 / 通过标准 / 预算
- 不越权决定签名层（定制字体 / OpenType 风格 / 品牌图形）

## 8. 交接与边界

- 给 Critic：重点看什么、自检结果（维度 / 严重度 / 区域 / 证据 / 置信度），不给聚合分
- 给 Prototype：哪些结构已验证、哪些还要验
- 给 Architect / Definer 反哺：至少一条真实的结构反馈（放不下 / 缺状态 / 入口不自然）
- 明确说：重点设计了什么、没设计什么、哪些 ✅ 大胆、哪些 🔮 留退路、哪些等验证
- 没有生产代码；HTML/CSS 标注为设计件

## 9. 如果证据不足

如果 UI Designer 判断视觉方向证据不足，**写「方向待验证，先做 2–3 个方向快照对比」也是合格输出**——只要给出对比维度、通过标准和回退规则。假装确定才是失败。
