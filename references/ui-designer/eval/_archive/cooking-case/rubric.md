> 先按 `references/ui-designer/rubric.md` 打 8 维分；再用下面的 case-specific 检查。

## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **设计意图可执行** | 五问有「为什么」；意图能指导令牌；不是「高级感」 | |
| 2 | **赌注在界面上有位置** | 首屏 / 一级区域能看到「买多少 / 份量 / 剩菜去处」；不是通用食谱 App | |
| 3 | **来源过滤 + 轴锚定** | marketing 空间值被丢弃；≥5/8 轴有论证的非默认值；至少一根排版轴 + 一根结构轴 | |
| 4 | **令牌纪律** | 三层令牌；页面零裸 hex / 裸 px；状态变体有定义 | |
| 5 | **状态覆盖** | 核心组件 ≥5 态；≥3 屏含默认 + 空 + 错误；空状态引导行动、错误就地恢复 | |
| 6 | **密度与工艺** | 产品 UI 密度；对比度 / 触控 / 焦点 / 行高达标；动效纪律 | |
| 7 | **快照不 slop** | 四项 slop-tell 未命中；三改动地板；squint 能认出「数量闭环」 | |
| 8 | **信心诚实 + 交接** | 可自动检查与需人眼分开；审美判断标 ⚠️/🔮；交接有大胆 / 退路 / 等验证 | |

## 常见失败

- 直接画通用食谱 App：6 Tab（首页 / 食谱 / 买菜 / 做饭 / 社区 / 我的）。
- 紫色渐变 + 四张等宽卡片 + emoji 标题。
- 用营销页的 48px 标题、96px 段间距做产品首屏。
- 只换主色，其余 7 轴全默认。
- 令牌表存在，但页面里裸 hex / 裸 px 漂移。
- 状态只打勾，没有「看到什么 + 能做什么」。
- 空状态「暂无数据」；错误「出错了」。
- 设计理由全是「高级感 / 呼吸感 / 舒适」。
- 把审美判断全部标 ✅，没有人类检查点。
- 交接只说「请查收」，没有大胆 / 退路 / 等验证。
- 交付 React 生产代码。
