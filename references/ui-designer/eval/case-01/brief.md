# Brief · UI Designer Eval Case 01（个人习惯工具）

## 产品

一个给个人用的习惯养成工具：1–3 个习惯，每天一次轻量打卡，按「触发 → 微小行动 → 意义 → 体感 → 身份」的四维模型设计。
移动端优先，个人使用，不做社交、不做排行榜、不做企业后台。

## 本次任务

上游已经完成调研、定义、需求与 IA：

把这些结构变成**顶级个人工具**的产品 UI。

## 设计前必须处理（2026-11-25 新增）

`requirements.md` 是本次新增的跨岗输入。它带来两件事：

1. **R05 暂停是 P0**：暂停入口必须可达；暂停后该习惯不在今天出现、已有记录保留、可恢复；不能只给「删除」。AC5.1 / AC5.2 必须能在设计里被执行。
2. **C1–C3 未决冲突**：中断态默认档（C1）、回顾计数语义（C2）、体感步骤是否计入 3 次点击（C3）。**不要把任一选项写死**；设计要留可切换的实现或明确标注「待裁决」，并在 `design-rationale.md` 里写清「如果裁决为 X，哪个决策要重做」。

这份 requirements 的下游禁令：C1–C5 未决前，不要把默认档、计数语义、体感步骤位置、提醒、连续天数写死进 IA / 原型 / 设计。

## 视觉方向（硬要求）

- 参考方向：**Apple 原生精致**——暖、克制、微交互、留白；Things 3 / Streaks / Apple Fitness 的语言。
- 开工前必须读参考板：`references/ui-designer/reference-board/README.md`（相对插件根目录）
- 必须写 `reference-board.md`：选 2–3 个参考，写「学什么 / 不学什么 / 用在哪一屏」。
- 每个核心屏至少一个视觉锚点：圆环 / 大数字 / 图表 / 图像卡片 / 统一图标系统。
- 禁止：emoji 当图标、纯文字堆叠、把所有屏做成「标题 + 列表 + 分隔线」、企业后台密度。

## 要产出什么

在工作区写五个产物：

1. **`reference-board.md`**
   - 2–3 个参考，每个写：学什么（构图/排版/色彩/组件/动效）、不学什么、用在哪一屏
   - 从参考提炼的「本产品视觉语法」
2. **`design-system.md`**
   - 设计意图五问（品牌温度 / 信息密度 / 动效目的 / 布局复杂度 / 参考系统），每项带「为什么」和 ✅/⚠️/🔮
   - 来源过滤说明 + 轴锚定表（≥5/8 轴非默认，每轴写取值/论证/置信度）
   - 三层令牌系统（primitive / semantic / component）：颜色、字体、间距、圆角、阴影、动效
   - ≥6 个核心组件定义：用途 / 结构 / 状态（≥5）/ 可访问性 / 禁止用法
   - 视觉资产清单（图标系统 / 图表 / 大数字 / 图像）
   - 页面清单
   - 不确定与需人眼确认
3. **`ui-spec.md`**
   - 每个核心页面的结构、状态、交互、文案、响应式
4. **`screens/`**
   - ≥4 屏高保真 HTML/CSS（设计件，不是生产代码）
   - 必须覆盖：今天（默认 + 完成态）+ 回顾（数据可视化）+ 一个空状态或庆祝时刻
   - 页面样式只通过 `var(--token)` 引用令牌；原始值只出现在 :root 的令牌定义里
5. **`design-rationale.md`**
   - 关键视觉决策理由（追到赌注 / IA / 场景 / 参考板）
   - 哪些 ✅ 可大胆设计 / 哪些 🔮 要留退路 / 哪些等验证
   - 哪些审美判断需要人眼
   - 没有设计什么

## 约束

- 只做产品 UI：不做品牌识别、logo、营销页
- 不写生产代码：HTML/CSS 只作为设计件与可点击原型
- 页面里不允许裸 hex / 裸 px
- 先系统，后页面
- 状态覆盖先于工艺抛光
- 每个关键决策带置信度（✅ / ⚠️ / 🔮）
- 打卡反馈不能制造羞耻感：中断不是红色警报，补记不等于失败

## 什么算成功

- 首屏让人想打开：有视觉锚点、有进度感、有温度，不是一张待办清单
- 完成态是多重编码（填充 + 对勾 + 数字），不只靠颜色
- 中断/回归路径在设计上被平等对待，不渲染焦虑
- 回顾页有真正的数据可视化，不是文字统计
- 参考板被真正使用：构图 / 排版 / 色彩 / 组件能在产出里找到来源
- **R05 暂停路径可达**：暂停入口可找到；暂停/恢复不出现失败语义；已有记录保留
- **C1–C3 没有被写死**：设计留了可切换实现或明确标注待裁决，rationale 写了裁决后的重做点
- 下游（Critic / Prototype）能看懂哪些大胆、哪些留退路、哪些等验证

## 明确不做

- 社交、排行榜、好友、社区
- 付费墙、订阅、增长机制
- 健康数据接入（Apple Health 等）
- 多用户 / 企业 / 团队
- 品牌视觉、营销页、logo

## 时间盒

60–75 分钟。优先保证「参考板 → 意图 → 令牌 → 组件 → 4 屏 + rationale」完整。
