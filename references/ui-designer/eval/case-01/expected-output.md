# Expected Output · UI Designer Eval Case 01（个人习惯工具）

> 一份合格产出必须包含以下内容。不要求选某个特定视觉风格；要求「参考板成立、意图可追溯、系统先于页面、视觉有锚点、状态覆盖、密度正确、信心诚实、交接清楚」。

## 1. 参考板

- 2–3 个顶级个人工具参考，每个写：学什么（构图 / 排版 / 色彩 / 组件 / 动效）、不学什么、用在哪一屏
- 至少一个参考来自不同品类
- 从参考提炼出「本产品视觉语法」：构图、排版、色彩、组件、动效
- 不是「参考 Linear，所以深色紫」这种标签式引用

## 2. 设计意图

- 五问全部回答：品牌温度 / 信息密度 / 动效目的 / 布局复杂度 / 参考系统
- 每一项有「为什么」和置信度（✅ / ⚠️ / 🔮）
- 至少 3 条明确的反模式
- 意图能指导具体令牌与构图，不是「高级感 / 呼吸感」

## 3. 来源过滤与轴锚定

- 说明参考里哪些来自产品层、哪些来自营销层
- 营销层的 spacing / radius / shadow / density / display 字号被丢弃，而不是缩放
- 一张锚定表：≥5/8 轴有论证过的非默认值
- 每轴写：取值 / 论证来源 / 置信度
- 至少一根排版轴和一根结构轴

## 4. 令牌系统

- 三层结构：primitive / semantic / component
- 颜色：感知均匀空间推导；染色中性；语义色 ≤4 类；强调色配给政策明确
- 字体：字号阶梯 / 行高 / 字重上限 / 字距符号 / 数字排版
- 间距：8px 网格与阶梯
- 圆角：家族，不是单值
- 阴影：语境匹配的工程化阴影
- 动效：150–300ms、ease-out、只动 transform/opacity、禁装饰性
- 页面里零裸 hex / 裸 px

## 5. 视觉资产

- 一个统一图标系统（同一 stroke 宽度 / 圆角 / 尺寸；24px 基准）
- ≥1 种数据可视化：圆环 / 折线 / 柱状 / 热力图
- ≥1 个大数字作为视觉锚点（连续天数 / 完成率 / 本周次数）
- 每个核心屏至少一个视觉锚点
- 没有 emoji 当图标；没有纯文字堆叠

## 6. 组件与状态

- ≥6 个核心组件（打卡按钮 / 习惯卡 / 圆环 / 统计卡 / 空状态 / 庆祝时刻 / 导航 / 输入）
- 每个组件：用途 / 结构 / 状态（≥5）/ 可访问性 / 禁止用法
- 打卡：完整 / 简化 / 微型三级，视觉平等；完成态多重编码（填充 + 对勾 + 数字）
- 中断/回归：不显示红色警报；「回来也算数」；补记不等于失败
- 空状态：首次 / 无数据 / 错误，各有引导行动
- 异步动作有 loading + disabled + 标签切换

## 7. 屏幕与构图

- ≥4 屏高保真 HTML/CSS
- 必须覆盖：今天（默认 + 完成态）+ 回顾（数据可视化）+ 空状态或庆祝时刻
- 至少两屏使用不同构图（例如今天 = 圆环网格 / 卡片，回顾 = 统计仪表，习惯详情 = 时间轴或列表 + 详情）
- 每屏 5 秒 squint 能认出「习惯工具」，不是通用待办模板

## 8. 密度与工艺

- 密度 4–6（个人工具），不是企业后台的 7–9
- 对比度：正文 ≥4.5:1，大字 / UI ≥3:1
- 触控目标 ≥44px
- 焦点可见；键盘可达
- 行长 45–75ch；数字 tabular-nums
- 动效：打卡反馈 200–300ms；庆祝一次性；无循环装饰

## 9. 信心诚实与人类检查点

- 明确分开「可自动检查」与「需人眼」
- 审美判断（温度 / 字体配对 / 中性色暖度 / 动效时序 / 签名层）标 ⚠️ 或 🔮，不标 ✅
- 人类检查点写成形状：≤3–5 屏 / 3 个变量 / 通过标准 / 预算
- 不越权决定签名层

## 10. 交接与边界

- 给 Critic：重点看什么、自检结果（维度 / 严重度 / 区域 / 证据 / 置信度），不给聚合分
- 给 Prototype：哪些结构已验证、哪些还要验
- 给 Architect / Definer 反哺：至少一条真实的结构反馈
- 明确说：重点设计了什么、没设计什么、哪些 ✅ 大胆、哪些 🔮 留退路、哪些等验证
- 没有生产代码；HTML/CSS 标注为设计件

## 11. 如果证据不足

如果 UI Designer 判断视觉方向证据不足，**写「方向待验证，先做 2–3 个方向快照对比」也是合格输出**——只要给出对比维度、通过标准和回退规则。假装确定才是失败。
