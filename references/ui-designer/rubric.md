# UI Designer · 评分标准

> 用于评审 UI Designer 的产出，或用于 eval。
> 0–4 锚点；不是打分游戏，是诊断工具。

---

## 评分维度

| # | 维度 | 核心问题 |
|---|---|---|
| 1 | **设计意图可追溯** | 每个关键视觉决策能追到赌注 / IA / 场景 / 刻度盘吗？ |
| 2 | **系统先于页面** | 先令牌后组件再页面？页面里有没有裸值？ |
| 3 | **非默认性与设计观点** | ≥5/8 轴锚定了非默认值吗？快照能认出这是谁吗？ |
| 4 | **状态覆盖** | 核心组件 ≥5 态？核心界面覆盖空 / 错 / 加载 / 极端？ |
| 5 | **信息密度与空间语域** | 是产品 UI 的密度，还是营销页的留白？ |
| 6 | **工艺与视觉表现力** | 排版、对比度、触控、对齐达标吗？每个核心屏有视觉锚点吗？构图有观点吗？ |
| 7 | **信心诚实与人类检查点** | 哪些审美判断需人眼？有没有假装能判断美？ |
| 8 | **交接与设计理由** | 下游知道哪些大胆、哪些留退路、哪些等验证吗？ |

---

## 0–4 锚点

| 分 | 含义 | 通用表现 |
|---|---|---|
| **0** | 缺失 | 完全没有这个维度 |
| **1** | 提名 | 提到概念，但没有执行 |
| **2** | 部分 | 有执行，但明显不足 / 不一致 |
| **3** | 合格 | 达到标准，可用于决策 |
| **4** | 示范 | 不仅达标，还能作为模板 |

### 1. 设计意图可追溯

| 分 | 表现 |
|---|---|
| 0 | 直接出图，没有设计意图 |
| 1 | 有「高级感 / 呼吸感 / 舒适」这类不可执行形容词 |
| 2 | 写了意图，但只是套刻度盘默认值，没有「为什么」 |
| 3 | 每个关键视觉决策能追到赌注 / IA / 场景 / 刻度盘，并带置信度 |
| 4 | 还写了「如果赌注/IA 变了，哪个决策要重做」 |

### 2. 系统先于页面

| 分 | 表现 |
|---|---|
| 0 | 没有令牌，直接画页面 |
| 1 | 有令牌表，但页面大量裸 hex / 裸 px |
| 2 | 页面大多引用令牌，但令牌不成体系（缺语义层 / 命名混乱） |
| 3 | 三层令牌结构（primitive / semantic / component），页面无裸值 |
| 4 | 令牌还覆盖了状态变体、暗色映射、密度切换，且说明了推导方式 |

### 3. 非默认性与设计观点

| 分 | 表现 |
|---|---|
| 0 | 全套默认：默认蓝、默认圆角、默认字体、默认间距 |
| 1 | 只换主色，其余全默认；四项 slop-tell 中 ≥3 项 |
| 2 | 有 1–2 轴非默认，但只是措辞级差异（如换个暖色），快照仍像模板 |
| 3 | ≥5/8 轴有论证过的非默认值；四项 slop-tell 全避开；三改动地板通过 |
| 4 | 还写出了「最危险的默认选择」和边界条件（在什么语境下可以回到默认） |

### 4. 状态覆盖

| 分 | 表现 |
|---|---|
| 0 | 只有默认态 |
| 1 | 4 个状态当清单打勾，没有「看到什么 / 能做什么」 |
| 2 | 覆盖 5–6 态，但空 / 错 / 加载 / 极端路径缺失或公式化 |
| 3 | 核心组件 ≥5 态；核心界面覆盖空 / 错 / 加载 / 极端，且每个状态写清看到什么 + 能做什么；关键态有实际渲染（至少空 / 错 / 加载 / 中断后） |
| 4 | 空状态引导行动、错误就地恢复；零 affordance 谎言、零双击提交路径；所有非快乐路径都有渲染证据 |

### 5. 信息密度与空间语域

| 分 | 表现 |
|---|---|
| 0 | 营销页式 hero、巨大标题、96px 段间距 |
| 1 | 明显过松或过紧，与任务节奏不匹配 |
| 2 | 密度大体合理，但局部用营销页空间值 |
| 3 | 密度与产品类型 / 任务节奏匹配；刻度盘有论证 |
| 4 | 密度本身承载任务优先级（哪些区域该松、哪些该紧，有理由） |

### 6. 工艺与视觉表现力

| 分 | 表现 |
|---|---|
| 0 | 纯文字堆叠，没有视觉资产；对比度 / 触控 / 对齐多项不达标 |
| 1 | 有基本样式，但没有视觉锚点；或工艺有明显缺陷（灰字彩底、行长失控、无焦点态） |
| 2 | 工艺基本达标，但每个屏都是「标题 + 列表 + 分隔线」；资产风格不统一 |
| 3 | 工艺达标（对比度 ≥4.5:1、触控 ≥44px、焦点可见、动效 150–300ms）；每个核心屏至少一个视觉锚点；至少一屏构图不是垂直堆叠；有排版签名 |
| 4 | 视觉系统有辨识度：资产、构图、排版共同服务赌注；暗色映射、光学对齐、染色中性、极限数据都处理过；可作为模板 |

### 7. 信心诚实与人类检查点

| 分 | 表现 |
|---|---|
| 0 | 声称「审美上没问题」，没有任何不确定性 |
| 1 | 把审美判断全部标 ✅；或全标 ⚠️ 等于没标 |
| 2 | 列了需人眼项，但混在已完成项里，下游分不清 |
| 3 | 明确分开「可自动检查」与「需人眼」；审美判断标 ⚠️/🔮；不越权决定签名层 |
| 4 | 还给出人类检查点的形状：≤3–5 屏、3 个变量、通过标准与预算 |

### 8. 交接与设计理由

| 分 | 表现 |
|---|---|
| 0 | 只交文件，没有理由 |
| 1 | 有理由，但下游不知道哪些能大胆设计、哪些要留退路 |
| 2 | 部分交接信息，缺「等验证」或「没设计什么」 |
| 3 | 说明重点设计了什么 / 没设计什么 / 哪些 ✅ 大胆 / 哪些 🔮 留退路 / 哪些等验证 |
| 4 | 还给 Critic 结构化自检结果（维度 / 严重度 / 区域 / 证据 / 置信度），并给 Architect / Definer 反哺 |

---

## 门控规则

以下任意一条触发，**退回重做**：

- **维度 3 ≤ 1**：只换主色 / 全默认 → 这不是设计，是模板套壳。
- **维度 4 = 0**：没有状态覆盖 → 界面只存在于快乐路径，不可交付。
- **维度 7 ≤ 1**：信心通胀或假装能判断美 → 下游会把审美假设当事实。
- **视觉表现力门**（独立于 8 维评分，pass/fail）：
  - 核心屏没有任何视觉锚点（纯文字堆叠加分隔线）→ 退回。
  - 用 emoji 当图标，或资产风格不统一 → 退回。
  - 所有屏都是同一种垂直堆叠结构 → 退回。

## 总分参考

| 总分（8 维，满分 32） | 判断 |
|---|---|
| 28–32 | 可作为模板 |
| 22–27 | 可进入下游 |
| 16–21 | 需修正后重审 |
| < 16 | 退回 |

> 总分只作参考；门控优先。
