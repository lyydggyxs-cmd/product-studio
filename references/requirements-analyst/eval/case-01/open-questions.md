# Open Questions · 个人习惯工具（Eval Case 01）

> 与需求相关的未决问题。Requirements Analyst 需要判断：哪些必须在本轮需求里定死，哪些可以留给下游或标为待验证。

| ID | 问题 | 为什么影响需求 | 当前状态 |
|---|---|---|---|
| OQ1 | 「三级完成度视觉平等」具体指哪些维度？颜色、尺寸、位置、顺序、默认值、命名、完成反馈 | 不操作化，就无法写可测 AC；不同维度可能导致相反实现 | 未定义；PRD 只写「不用颜色区分高低」 |
| OQ2 | 中断态是「三档平等 + 文案引导」还是「预选微型」？ | 预选 = 默认推荐，可能与 A2 的平等原则冲突；影响 R02 的 AC | 未定义；IA 两处表述不一致（但本轮不读 IA） |
| OQ3 | 计数语义：记录次数（三档都算）还是完整次数？ | 决定回顾页需求、完成态文案、身份阶段的判断 | 未定义 |
| OQ4 | 体感步骤是否按档位调整？微型档是否精简？ | 影响「3 次点击内完成」的 AC；微型档接完整体感可能过重 | 未定义；PRD 只说「可跳过」 |
| OQ5 | 多习惯今天屏：1–3 个习惯如何组织？主习惯 + 支持行，还是每个习惯一张卡？ | 影响点击次数、决策负担、AC 的分母 | 未定义；PRD 写 1–3 个习惯，IA 写单数主习惯卡 |
| OQ6 | 提醒是否在本期范围？语气/频率？ | 影响「中断不焦虑」与「不打扰」的需求；可能是 P0 或 Anti-goal | 未定义 |
| OQ7 | 暂停/放弃是否需要？如何与「不制造羞耻」一致？ | 影响边界条件与不做清单；没有暂停会让用户只能「删除」 | 未定义 |

## 使用规则

- 能自己从 B1/证据推出答案的，写进需求并标置信度。
- 推不出的，写成「需要 Definer 决策」或「本轮不写死，留给验证」。
- 不要把未决问题默默选一个答案，也不要把它们全部丢给下游。
