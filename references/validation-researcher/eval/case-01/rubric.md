## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **模拟数据声明** | 开头明确「模拟数据，不是真人」；不用「用户说/用户做」 | |
| 2 | **验证问题** | 主问题 A2 设计前提；次问题产品级完成率；写清不能回答什么 | |
| 3 | **预注册** | 引用/确认 S1–S4 / R1–R4 / U1–U5；不事后改线；灰区明确 | |
| 4 | **逐会话编码** | S1–S5 的行为/原话/编码完整；区分 S4 理解问题与 S5 视觉编码问题 | |
| 5 | **频率正确** | 4/5 选非完整档 = 模式；3/5 合法性 = 灰区；1/5 个案不写成「用户普遍」 | |
| 6 | **类型分流** | S2 价值/合法性；S4 结构/理解；S5 交互视觉；路由正确 | |
| 7 | **偏差与无法判断** | 模拟/n=5/单臂/单主持人/demo/社会赞许；写清不能判什么 | |
| 8 | **总判断** | 支持/挑战/停止/需要更多数据；不能判「A2 已验证」；迭代建议分紧急/下版/探索 | |

## 常见失败

- 把 4/5 选非完整档写成「4/5 认为它算完成」。
- 把 3/5 写成支持（预注册 S2 是 ≥4/5）。
- 把 S4 的「哪个是推荐」写成「用户普遍困惑」。
- 把 S5 的「像只做了三分之一」直接当 R1（不算/偷懒）的证据。
- 不声明模拟数据，写「用户 S3 说」。
- 没有偏差声明，写「证明用户接受」。
- 只报支持，隐藏 S2/S5 的反证。
- 总判断「整体积极」；没有支持/挑战/停止/需要更多数据。
- 给方案（「建议改默认档」）。
