# Brief · Validation Researcher Eval Case 01（个人习惯工具）

## 背景

Prototype Designer 为 A2「三级完成度视觉平等」做了一个灰框可点击原型，并写了预注册标准（S1–S4 支持 / R1–R4 反驳 / U1–U5 测不了）。现在有 **5 份模拟会话记录**，需要合成一份验证报告。

## 重要声明

**5 份会话是模拟数据，不是真人访谈。** 报告必须明确声明，不能写「用户说/用户做」，只能写「模拟会话 S1 显示……」。模拟数据只用于验证合成流程，不能当产品证据。

## 输入

| 输入 | 说明 |
|---|---|
| `prototypes/index.html` | 被测原型（灰框，A 平等版 / B 对照臂） |
| `test-notes.md` | Prototype Designer 的预注册标准、编码表、任务脚本；**只用预注册部分**，不把其「做后最大的发现」当用户证据 |
| `bet-book.md` | B1、成功/kill 信号、A1–A5 |
| `requirements.md` | P0、AC、边界、C1–C5 冲突 |
| `ia-flows.md` | 结构、状态矩阵、信心地图 |
| `sessions/session-01..05.md` | 5 份模拟会话记录（行为 + 原话 + 编码） |

## 任务

写两个文件：

### 1. `validation-plan.md`

- 这轮验证回答哪个问题（A2 设计前提 / 产品级完成率 / 其他）
- 预注册标准：直接引用或确认 `test-notes.md` 的 S/R/U；如果要改，写清为什么、改了什么
- 样本/条件/任务/主持人纪律/偏差控制
- **判定线先于数据**：支持/挑战/停止/需要更多数据

### 2. `validation-report.md`

- **模拟数据声明**（开头）
- 信号卡：结论方向、置信度、翻转前提
- 验证问题 → 结果 → 证据
- 每条发现：现象 + 证据（S1–S5 行为/原话）+ 频率（≥3/5 模式 vs 1–2/5 个案）+ 严重度 + 类型 + 路由
- 区分：价值 / 可用性 / 结构 / 交互视觉 / 需求不可测
- 模式 vs 个案
- 无法判断 / 偏差声明
- 迭代建议：紧急 / 下版 / 探索
- 总判断：支持 / 挑战 / 停止 / 需要更多数据

### 3. `open-questions.md`

- 这轮关闭了哪些问题、新增了哪些问题

## 硬规则

- **模拟数据必须声明**；不得写「用户说」，写「模拟会话 S1 显示」。
- **行为优先于言语**；言语/行为不一致时按行为判，并记录原话。
- **≥3/5 才是模式**；1–2 人是个案，不写成「用户都」。
- **按预注册标准判**；灰区不硬判；不事后改线。
- **区分价值/可用性/结构**；路由到正确岗位。
- **不给方案**；只描述问题、影响、路由。
- **小样本诚实**：n=5 只做方向性判断；不做效应量/外推。
- **偏差声明**：模拟数据、样本、主持、demo、顺序、社会赞许。

## 什么算成功

- 正确使用预注册 S/R/U，不把「选择非完整档」直接等同于「认为它算完成」
- 正确区分 S4 的「哪个是推荐」（理解/IA 个案，不是 A2 模式）和 S5 的「像没做完」（视觉编码个案，不是 A2 反驳）
- 频率判对：4/5 选择非完整档是模式；3/5 合法性语言是灰区；2/5「像没做」不自动等于 R1
- 总判断与证据一致（支持 / 挑战 / 需要更多数据）
- 路由正确：Definer / Architect / UI / Requirements
- 偏差与模拟数据声明完整

## 明确不做

- 不假装做过真人访谈
- 不改设计文件、不给方案
- 不替代产品决策
- 不把模拟数据当产品证据

## 时间盒

45–60 分钟。优先保证「计划 → 逐会话编码 → 模式/个案 → 总判断 → 路由」完整。
