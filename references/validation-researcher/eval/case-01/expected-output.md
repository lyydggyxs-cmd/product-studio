# Expected Output · Validation Researcher Eval Case 01（个人习惯工具）

> 一份合格产出必须包含以下内容。不要求总判断与某个答案完全一致；要求「预注册、行为优先、频率正确、类型分流、偏差声明、模拟声明、判断明确」。

## 1. 模拟数据声明

- 报告开头明确：「5 份会话是模拟数据，不是真人访谈」
- 不用「用户说/用户做」；用「模拟会话 S1 显示」
- 结论只用于合成流程验证，不当产品证据

## 2. 验证问题

- 主问题：A2 的设计前提——用户是否把非完整档读成合法完成？
- 次问题：产品级完成率（只作描述，不归因 A2）
- 明确「这轮不能回答」：14 天动机、长期习惯、真实羞耻感积累

## 3. 预注册判定线

- 直接引用 `test-notes.md` 的 S1–S4 / R1–R4 / U1–U5
- 不改线；如果要改，写清为什么、改了什么
- 明确灰区：支持/挑战/需要更多数据

## 4. 逐会话编码

至少覆盖：
- S1：选简化，2 次点击，18 秒，说「算」→ 支持 S1/S2/S4
- S2：先简化后改完整，说「像没做/偷懒」→ 挑战 S3/R1
- S3：选微型，12 秒，说「算」→ 支持 S1/S2/S4
- S4：问「哪个是推荐」，犹豫 42 秒 → U1 理解/IA 个案，不是 A2 模式
- S5：选简化，说「算吧，但像只做了三分之一」→ 支持 S2；同时暴露视觉编码问题，不是 R1 的直接证据

## 5. 频率与模式

- 4/5 选非完整档（S1/S3/S4/S5）→ **模式**，支持 S1
- 3/5 说非完整档算完成（S1/S3/S5）→ **灰区**；S2 的支持线是 ≥4/5，不能判支持
- 2/5 出现「像没做/偷懒/像只做了三分之一」（S2/S5）→ 需按编码规则区分「偷懒/不算」与「看起来像没做完」；不能自动判 R1
- S4 的「哪个是推荐」是 1/5 个案；S5 的「1/3 环」是 1/5 个案
- 反证与支持并列，不只报支持

## 6. 类型分流

- S2 的「像没做/偷懒」：价值/合法性感知 → Definer（A2 的设计前提）+ UI（文案/默认档）
- S4 的「哪个是推荐」：结构/理解 → Architect（C1 默认档/三档关系）+ Definer（C1 决策）
- S5 的「1/3 环」：交互视觉 → UI/Architect（迷你环编码）
- 产品级完成率：不是 A2 证据；如需判断，另设基线/对照
- 14 天动机：本轮不可测 → Validation 下一轮/纵向研究

## 7. 偏差与无法判断

- 模拟数据（最大偏差）
- n=5，方向性判断，不外推
- 单主持人、A 版单臂（没有 B 对照臂的会话）
- 无极端用户/边缘用户
- demo 效应、社会赞许
- 无法判断：真实羞耻感、长期动机、真实中断后的回归、真实设备上的 1/3 感知

## 8. 总判断

可接受的判断（需证据支撑）：
- **混合/需要更多数据**：选择行为支持，但合法性感知 3/5（灰区）+ 2/5 负向表述，不能判支持；建议下一轮加样本 + B 对照臂
- **挑战（部分）**：若把 S2/S5 编码为 R1 触发，则 A2 设计前提被部分挑战；需说明编码依据
- **不能判「支持」**：3/5 未达到 S2 的 ≥4/5；「4/5 选非完整档」不等于「4/5 认为它算完成」
- **不能判「A2 已验证」**：模拟数据 + n=5 + 单臂

## 9. 迭代建议

- 紧急：C1 默认档决策（S4 的「哪个是推荐」）；迷你环 1/3 编码（S5）
- 下版：加 B 对照臂会话；加极端用户；加 390px 以外设备
- 探索：14 天纵向研究；真实中断后的回归

## 10. 路由

- Definer：C1/A2 设计前提、C2 计数语义
- Architect：三档关系/默认档、习惯列表入口
- UI：迷你环 1/3 编码、文案
- Requirements：AC1.2 的「平等」操作化；AC4.1 计数口径
- Validation 下一轮：加样本、B 臂、纵向

## 11. 如果数据不足

如果某条判断样本不足，**写「需要更多数据」并说明缺什么**，不要硬判。把 3/5 写成支持、把模拟数据写成真人、把「选非完整档」写成「接受平等」，都是失败。
