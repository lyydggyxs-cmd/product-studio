## 信号卡（≤10 行）

- **结论方向**：选 A2，做**验证模式**灰框可点击原型；本轮只回答「微型会不会被读成一种合法完成」，不回答「14 天后还会不会用」。
- **置信度**：中。问题选择与保真度匹配有把握；A2 的长期动机结论**测不了**，只能测前置的「理解 / 合法性」层。
- **如果前提错了**：如果用户根本不想要「每天三选一」这个交互，A2 的视觉平等问题就不成立——应先测选择结构（IA）。
- **与上游的矛盾**：IA 状态矩阵写中断后「+ 微型版」，而 J2 写三个平等选项；如果「+ 微型版」被实现成预选，就是默认值，与 A2 的「三级平等」直接冲突。
- **已发现的需求缺口**：「视觉平等」没有操作化定义（颜色？尺寸？顺序？默认值？命名？完成反馈？）；PRD 只写了「不用颜色区分高低」。

## 1. 问题卡

```
检验的赌注/假设：B1 → A2「三级完成度视觉平等不降低完成动机」
最不确定的点：在低能量时刻，把「微型」和「完整」画得一样重，
              用户会读成「这也算完成」，还是「做少了也没关系 / 这是偷懒」？
原型能回答什么：三档同时出现时，用户选什么、说什么、是否把微型当完成；
                平等版 vs 有差异版（对照）在单次使用中的语言/选择差异。
原型不能回答什么：14 天回访率、真实长期动机、羞耻感随时间的变化、
                  会不会最终只做微型、真实中断后的回归行为。
```

### 1.1 为什么是 A2（不确定性 × 决策影响）

| 候选 | 不确定性 | 决策影响 | 原型可回答性 | 结论 |
|---|---|---|---|---|
| **A2 三级视觉平等** | 高：反直觉，可能同时降低羞耻和降低动机 | **最高**：是 B1 反馈回路的核心；PRD 已把它写成硬约束 | 中：可测「合法性理解 / 选择 / 完成反馈」，不可测 14 天动机 | **选它** |
| A4 阶段标签可理解 | 中：大概率能改成行为描述 | 低：改名即可，已有明确回退 | 高：5 秒测试 | 本轮不做；已有回退，不是最贵的不确定性 |
| A5 中断不焦虑 | 高：可能被读成放任 | 中：失败后加轻量提醒即可 | 低：核心指标是 48h 回归率，原型测不了 | 本轮不做；只能测即时情绪，容易过度推断 |
| IA 今天优先 vs 习惯优先 | 中高：最危险替代已识别 | 高：影响整个骨架 | 高：首次任务可测 | 本轮不做；与 A2 不是同一个问题，且会混淆三档选择 |

**选择理由**：A2 是唯一一个「视觉处理本身就是假设」的赌注。A4 改词、A5 加提醒，成本都低；A2 如果错了，B1 的因果链（不再用层级制造羞耻）要重写。原型虽然测不了长期动机，但能先把「用户是否把微型读成合法完成」这个前置层筛掉——如果这一层都不过，长期动机不用测。

## 2. 模式与保真度

| 项 | 选择 | 为什么 |
|---|---|---|
| 模式 | **验证模式**（Look & Feel 层） | 结构（今天屏 + 三个档位）已由 IA 选定为 ⚠️；本轮变量是「平等怎么呈现、完成后像不像完成」，不是重新探索 IA 骨架 |
| 保真度 | **灰框可点击 HTML**（单文件、系统字体、纯灰度、无品牌） | 能回答问题的最低保真：需要被试真实点击「选档 → 完成 → 体感/跳过 → 撤销」的连续反馈；纸面无法让人体验「完成后的一秒」 |
| 版本 | 1 个原型，内含 **A 平等版 / B 有差异版（对照）** | 验证工具包 V1 明确要求 A/B；对照版只用于基线比较，不单独判定 A2 |
| 不做的 | 高保真视觉、品牌、动效、后端、完整四页 | 过度抛光会让被试评价「好不好看」，而不是「我卡在哪」 |

**为什么不是纸面**：A2 的关键瞬间不是「看到选项」，而是「选完之后看到什么」。纸面可以让 facilitator 手动换一张完成卡，但被试的「这算完成吗」会被 facilitator 的换卡动作污染；灰框 HTML 让这条反馈由界面自己给出，成本仍然很低。

**为什么不是更高保真**：本轮的因变量是「合法性 / 理解」，不是审美偏好。视觉越完整，被试越可能说「挺好的」，越不敢说「这不算完成」。灰框是刻意的——它让被试评价结构，而不是评价我的设计。

**过度抛光风险**：如果原型看起来像成品，被试会把「微型算不算完成」当成产品设定来接受，而不是表达自己的真实反应。所以原型保持：无插画、无品牌色、无阴影、无精细动效、单一灰度。

### 2.1 为什么不是探索模式（以及下一轮会探索什么）

A2 的问题是「同一结构下，平等呈现会不会改变理解」——它需要一个**受控的呈现变量**，不是三个不同的结构。用探索模式会同时改变结构和视觉，无法隔离 A2。以下三个结构方向是下一轮的候选，本轮不建：

| 方向 | 结构假设 | 如果对，观察到什么 | 如果错，观察到什么 |
|---|---|---|---|
| **A 三张等权卡片**（本轮） | 用户愿意在低能量时刻做一次三选一；平等呈现足以让微型合法 | 用户能快速选、说「都算」；不找推荐 | 用户说「太多了/我该选哪个」；选择时间明显变长 |
| **B 单主行动 + 可展开降级** | 用户想要一个默认动作；忙的时候才展开降级 | 用户直接做默认动作；少数忙日才展开 | 用户说「我不知道还能降级」；或找不到微型 |
| **C 先选情境，再只给一档** | 用户先判断「今天有多少时间」，再看到唯一一档；没有比较就没有层级 | 用户觉得「不用选」；微型被自然接受 | 用户觉得「被系统安排」；或想自己控制档位 |

**本轮不建 B/C 的原因**：它们会改变选择结构（默认值、选项数量、决策顺序），与 A2 的视觉变量混在一起。如果 A2 通过，下一轮再用探索模式比较 A/B/C；如果 A2 不通过，B 或 C 可能才是正确的方向——这也是「如果全错」里的第一条。

## 3. 做之前写死的标准（先于数据）

> **写作顺序声明**：以下支持 / 反驳 / 测不了标准写于 2026-11-18 12:09 CST，**在原型制作之前**。原型完成后只补「做之后发现」，不回改阈值。

### 3.1 样本与场景

- **样本**：5 名成年人；有过「想养成习惯但失败」的经历；每天使用手机；1–3 个想养成的习惯。
- **排除**：产品团队成员；已经有稳定每日习惯且不需要工具的人（不是目标用户）。
- **单独标注**：完全没用过任何打卡工具的人可以参加，但分析时标注——他们可能不理解「打卡」的既有语境。
- **场景**：「现在是周三晚上 9:40。你刚洗完碗，水壶还热着。明天要早起，你只有 2 分钟。你会怎么做？」
- **施测**：20–25 分钟/人；先做 5 秒快照，再做任务，再做中性追问；最后才做 A/B 对比。
- **A/B 与顺序平衡**：5 人分两组——3 人先看 A 平等版（顺序「大→小」），2 人先看 A 平等版（顺序「小→大」）；每组随后看 B 有差异版，顺序与首轮一致。主判定只用首轮 A 版；本轮 asc 组 n=2，只作方向性守卫；下一轮做 5 人双 block 被试内平衡（每个人两种顺序都看）。**顺序进入编码表；如果首轮 A 在两种顺序下结果翻转，A2 判「未定」，不能判支持或反驳。**
- **告诉被试**：「这是灰框原型，不是最终产品，很多地方是假的。我们想看你会怎么做，不是评价好不好看。没有正确答案。」
- **施测时只让被试看手机框**：用 `index.html?participant=1&version=A&order=desc&state=default` 打开；`participant=1` 隐藏顶部控制台、右侧笔记、底部说明，其余 URL 参数注入版本/顺序/状态，保证每个状态可复现。主试另开一份完整页面做控制。

### 3.2 支持 A2（全部满足才判支持）

| # | 观察到什么 | 阈值 | 观察方法 |
|---|---|---|---|
| S1 | 在「忙、只有 2 分钟」场景里，选择简化或微型 | ≥4/5 | 任务中记录点击；不提示选哪档 |
| S2 | 被问「刚才这个算完成吗？」时，用「算 / 也是完成 / 只是做少一点」描述所选的低档位；若选了完整，则在微型完成态暴露后对微型说同样的话 | ≥4/5 | 中性追问，原话编码 |
| S3 | 主动用「偷懒 / 作弊 / 不算 / 失败」描述微型 | 0/5 | 全程原话；不主动提这些词 |
| S4 | 在同样忙的情况下，表示明天还会打开 | ≥4/5 | 「如果明天同样忙，你还会打开吗？」（意图，不是行为） |

### 3.3 反驳 A2（任一触发即判反驳）

| # | 观察到什么 | 阈值 | 观察方法 |
|---|---|---|---|
| R1 | 用「偷懒 / 作弊 / 不算 / 失败」描述微型 | ≥2/5 | 原话编码；区分「被试自己说」与「追问带出来的」 |
| R2 | 在忙场景里仍选完整，并解释「选小的像没做 / 不算完成」 | ≥3/5 | 选择 + 理由编码 |
| R3 | 看完平等版的微型完成态后，仍无法判断是否算完成（问「这是完成了吗」/「看起来像没做完」） | ≥2/5 | 完成态暴露后的第一反应 |
| R4 | 平等版在合法性上明显差于对照版（说「不算」的人多 ≥2 人） | 方向存疑 | A/B 对比；即使绝对阈值未触发也标记 |

### 3.4 测不了 / 本轮无效（任一触发即不能判 A2）

| # | 观察到什么 | 判定 | 处理 |
|---|---|---|---|
| U1 | ≥3/5 反复问「这三个有什么区别 / 我该选哪个」，30 秒内无法选择 | 理解/IA 问题先于平等 | 记录为理解失败，A2 标记「未测」；先修标签/结构 |
| U2 | 被试主要在评价「好不好看 / 像不像真产品」 | demo 效应 | 该段数据作废；记录原话，换任务重新问 |
| U3 | 被试因为原型只有一个习惯、找不到另外两个而无法进入任务 | 原型范围对 TA 无效 | 记录为 IA 证据；A2 不用这个样本判定 |
| U4 | 被试没有睡前阅读/散步等习惯，场景不可信 | 场景效度失败 | 记录；换更贴近 TA 的习惯场景，或换被试 |
| U5 | 所有选择都集中在完整，且理由是「我本来就会做完整」 | 天花板效应 | 不能判 A2；需要「忙到只能做一点」的更真实场景 |

**其余结果判为「混合」**：支持条件没有全部满足，但也没有触发任何反驳条件——标记为「方向未定」，不能写成支持，也不能写成反驳；需要更大样本或下一轮。

### 3.5 机制归因规则（先写，防止事后解释）

| 结果 | 能说什么 | 不能说什么 |
|---|---|---|
| A 版通过，B 版不通过 | 支持「平等呈现包」（视觉权重 + 完成文案）有效；小样本、被试内，需谨慎 | 不能单独归因到视觉权重——B 版的完成文案也不同；不能说 14 天动机一定提高 |
| A 版通过，B 版也通过 | 只能说「本样本中视觉层级没有改变反应」 | **不能说「视觉平等有效」**——文案「选哪一档都算今天完成」两版都有，可能是文案在做功 |
| B 版更好（被试说 B 更清楚/更有动力） | 反驳 A2 的方向；**复合对照臂**（卡片视觉权重 + 完成文案 + 圆环深度）可能影响阅读 | 不能归因到单一变量（视觉权重/文案/圆环各改了什么没有拆开）；不能直接推出「常规层级有激励作用」；不能回到「红叉/连续天数」 |
| A 版通过，但被试说「因为上面写了都算」 | 主动成分可能是文案，不是视觉 | 不能把功劳归给视觉；下一轮做文案 × 视觉 2×2 |

### 3.6 编码表（现场用）

| 字段 | 取值 |
|---|---|
| 呈现顺序 | desc（大→小）/ asc（小→大） |
| 首档选择 | 完整 / 简化 / 微型 |
| 到第一次点击的秒数 | 秒 |
| 澄清问题数 | 次；记录原话 |
| 合法性语言 | 算 / 不算 / 含糊；偷懒 / 失败 / 作弊 / 程度不同 |

| 明天再来意图 | 会 / 不会 / 不确定 |
| 主动比较 A/B | A 更平等 / B 更清楚 / 没差别 / 其他 |
| IA 线索 | 问多习惯 / 问习惯列表 / 问回顾 / 其他 |
| demo 效应 | 有 / 无；原话 |

### 3.7 任务脚本（现场照读）

1. **5 秒快照**：展示 A 版默认态 5 秒，移开屏幕后问：
   - 「这个产品是做什么的？」
   - 「这三个选项分别是什么？」
   - 「你现在想点哪里？」
2. **忙场景任务**：把屏幕交回被试，读：
   - 「现在是周三晚上 9:40。你刚洗完碗，水壶还热着。明天要早起，你只有 2 分钟。你会怎么做？」
   - 让 TA 自己点；不提示选哪档。
3. **中性追问**（先开放，后具体；不主动提「偷懒/不算/失败」）：
   - 「刚才这个算完成吗？为什么？」
   - 「如果明天同样忙，你还会打开吗？」
   - 「你会怎么向朋友描述这三个选项？」
   - 「如果今天只做了最小那个，你会怎么跟朋友说？」
   - 「你注意到这三个选项有什么区别？」
   - **编码规则**：被试自发说出「偷懒/不算/失败」→ 计入 S3/R1；由追问带出 → 只作参考，不计入主判定。
4. **微型完成态暴露**：如果 TA 选了完整，用原型切到「完成态 · 微型」，问：
   - 「如果今天选的是『读一句话』，看到这个，你是什么感觉？这算完成吗？」
5. **B 版对照**：切到 B 版，重复忙场景 + 中性追问；最后问：
   - 「这两个版本，你用起来有什么不同？」
   - （只在最后）「如果只能留一个，你留哪个？为什么？」
6. **收尾**：
   - 「这轮原型没有覆盖什么？你有什么想问的？」
   - 记录多习惯/回顾/提醒等 IA 线索，但不展开。

## 4. 原型做了什么

**文件**：`prototypes/index.html` — 单文件、无依赖、无后端；双击或用任意静态服务器打开即可。
**验证截图**：`prototypes/verify/` — 默认、微型完成态、对照版、空、中断、离线、保存失败、第 30 次、tab 边界、顺序反转。
**验证方式**：Playwright 打开 `http://localhost:8765/index.html`，走核心流与全部状态；除 favicon 404 外无 JS 错误。

### 4.1 两个版本，一个仪器

| 版本 | 是什么 | 只用于 |
|---|---|---|
| **A · 三级平等** | 三张卡等宽、等高、同字号、同边框、无默认、无推荐；三档完成态的圆环/对勾/「今天算数」/计数完全一样 | A2 的主判定 |
| **B · 有差异（对照）** | 完整=实心黑卡；简化=浅灰卡；微型=虚线卡；微型完成态显示「部分完成」、圆环 30% | 基线比较，不单独判定 A2 |

**只变什么**：视觉权重、完成态圆环深度、完成文案。
**不变**：文案「选哪一档都算今天完成」、三档动作、体感步骤、记录计数语义。
这样 A/B 的差异才能归因到「视觉层级」，而不是文案或计数。**这是设计上的取舍，也是局限**：文案两版都有，所以如果 A/B 相同，不能反推「视觉平等有效」。

### 4.2 状态覆盖

| 状态 | 用户看到什么 | 能做什么 |
|---|---|---|
| **默认** | 习惯名、锚点、三档动作、时间估计、「选哪一档都算今天完成」 | 选任意一档 → 完成态 |
| **首次空** | 「还没有习惯」+ 三个真实建议（晚读 / 早起散步 / 睡前静坐） | 选一个 → 默认态 + toast |
| **中断后** | 中性 banner「昨天没有记录。今天从哪一档开始都算数。」+ 三档平等 | 选任意一档 → 「回来了。今天算数。」 |
| **加载** | 骨架屏 +「正在读取今天的记录…」 | 1.6 秒后自动进入默认；无加载失败状态（这轮不测） |
| **离线** | 顶部「记录会先保存在本机」+ 三档 | 选一档 → 完成态 +「已记在本机，联网后自动同步」 |
| **保存失败** | 「没有保存成功。刚才那次打卡还在…」 | 再试一次 → 完成态；稍后再说 → 完成态 + 排队 |
| **第 30 次** | 一次性反思条「不是连续 30 天，是 30 次这样的小事」+ 三档 | 收起；选一档 → 第 30 次记录 |
| **完成态** | 圆环 + 对勾 + 完成文案 + 所选动作 + 第 N 次记录 + 体感 chip + 跳过 + 改一下 | 选体感/跳过 → 最终态；改一下 → 回到来源状态 |
| **最终态** | 「记下了。」+ 完成文案 + 所选动作 + 体感 | 撤销这次记录 / 回到今天 |
| **tab 边界** | 点习惯/回顾/我 →「这轮原型只覆盖『今天』屏」 | 回到今天 |

**这轮不测的状态**：加载失败/超时、真实同步冲突、多习惯今天屏、回顾页、提醒通知、撤销后的服务端一致性。原型里没有，是因为它们不属于 A2 的问题；不做的状态明确写在这里，不假装覆盖。

### 4.3 为什么这些内容是真的

- **习惯**：晚读 / 早起散步 / 睡前静坐
- **锚点**：洗完碗，水壶还热着 / 送完孩子，绕小区一圈 / 手机放到客厅充电后
- **动作**：读 10 页《万历十五年》/ 读 1 页 / 读一句话；绕小区走 20 分钟 / 走到小区门口再回来 / 下楼站 3 分钟，晒到太阳；静坐 10 分钟 / 静坐 3 分钟 / 关灯后做 3 次深呼吸
- **时间估计**：10 分钟 / 1 分钟 / 10 秒；20 分钟 / 6 分钟 / 3 分钟；10 分钟 / 3 分钟 / 30 秒
- **体感词**：肩膀松了 / 呼吸变慢 / 脑子安静一点 / 有点累但踏实
- **错误与中断文案**：按 IA 的状态语气写的具体文案，不是 Lorem Ipsum

### 4.4 刻意不做

- 不做完整四页；习惯/回顾/我只做边界提示。
- 不做多习惯布局（这是 IA 缺口，不是 A2 的问题；见信号 1）。
- 不做视觉打磨、品牌色、插画、动效。
- 不接后端；状态是硬编码的。
- 不做「提醒」「同步」「账号」等下游功能。

## 5. 学习日志

### 5.1 做之前以为（写于 12:09，原型之前）

1. 三张等权卡片在灰框里会显得「没有重点」，用户可能不知道先看哪个；这本身可能是 A2 的成本。
2. 「完整/简化/微型」这三个词会泄露层级；即使用户界面只写具体动作（读 10 页/读 1 页/读一句话），「10 页 vs 一句话」仍然自带高低。
3. 有时间压力时，用户更可能选中间档（简化），微型可能被读成「敷衍」。
4. 完成态的圆环/对勾如果三档完全一样，用户可能会问「那我何必做完整」——这正是 A2 的核心风险。
5. 中断态的「+ 微型版」如果被实现成预选，会直接破坏平等；IA 在这里没有说清。

### 5.2 做之后发现（构建 + Playwright 走查，尚无人证据）

1. **平等是「去掉层级」做出来的，但它同时去掉了焦点。** 默认态里三张卡确实平等，但屏幕的视觉重心落在习惯名和「今天做哪一档？」上，三张卡本身没有主次。真正让「微型算完成」成立的不是卡片，而是那行「选哪一档都算今天完成」。这直接支持了预注册的机制归因警告：如果 A 版通过，可能是文案在做功，不是视觉平等。
2. **「视觉平等」和「语义平等」是两件事。** UI 里我没有写「完整/简化/微型」，只写具体动作；但「读 10 页」和「读一句话」本身就有语义高低。即使三张卡像素级相等，用户仍可能按词义排序。PRD 的「不用颜色区分高低」只覆盖了视觉，没覆盖命名、数量词和顺序。这是 A2 需求的操作化缺口。
3. **三档完成态相同，读起来是自洽的，但留下一个产品问题：如果微型和完整的反馈完全一样，用户为什么还要做完整？** 这正是 A2 要赌的东西（内在动机而不是外部层级）。原型让它第一次可见；但答案只能来自真人，不能来自走查。
4. **多习惯缺口是构建时才暴露的最大结构问题。** IA 写「主习惯卡」（单数），PRD 写 1–3 个习惯。如果按 3 个习惯 × 3 档来画，今天屏会变成 9 个选项；如果只画一个，就不能回答多习惯用户的首屏。原型选择了后者（只放一个习惯），因此 A2 的结论只对「单习惯今天屏」成立。
5. **中断态的「+ 微型版」和平等原则可能无法同时满足。** 原型选择了三档平等 + 中性文案；IA 状态矩阵写「+ 微型版」，但没有说清这是文案提及还是预选。预选是一个默认值，等于在平等卡片里插了一个推荐；如果不预选，回归摩擦怎么降低又没有定义。这是 IA 必须做的取舍，不是原型能替它决定的。
6. **体感步骤在微型档上显得过重。** 用户刚选了「读一句话」（约 10 秒），下一屏却问「身体有什么感觉？」并给四个 chip。这个仪式与行动不成比例，尤其发生在用户最忙的时候。PRD 说体感是每日核心仪式、可跳过，但没定义是否按档位调整。A3 的 V4 也没有分档位统计。
7. **第 30 次反思条仍然是一个数字。** 文案明确说「不是连续 30 天」，但「第 30 次」本身仍可能被读成「不能断」。反 streak 不等于反数字；这是 A5/反游戏化的一个细节，需要真人反应才能判断。
8. **顺序是一个独立的层级通道。** 把顺序从「大→小」切到「小→大」，三张卡仍然视觉平等，但阅读顺序完全变了。A2 如果只说「视觉平等」，没有说顺序是否中立；如果顺序固定，它就在暗示优先级。原型提供了顺序切换，测试时可以验证这个通道。
9. **完成态的文案必须贯穿到最终态。** 第一版对照版在完成态写「部分完成」，最终态却写「今天算数」——两句话互相矛盾，会污染 A/B。已改为版本一致（B 版最终态也写「完成/部分完成」）。这说明「平等」不是一个组件的属性，而是整条流的属性。
10. **离线排队完成的计数语义是模糊的。** 原型显示「第 12 次记录」+「待同步」；这个 12 是已经算进去了，还是同步后才算？IA 没有定义。用户可能不关心，但回顾页会关心。

### 5.3 如果这个方向全错了，可能是因为……

1. **每天三选一本身就是摩擦。** 用户想要的是一个默认动作；忙的时候自动降级，而不是每天在低能量时刻做一次选择。三级平等把决策负担放回了用户身上。
2. **平等抹掉了「完整」的回报。** 「完成」的意义来自难度和成就感；把微型和完整在视觉上等同，会让完整失去奖励，最终用户只做微型，或者离开。
3. **羞耻感不是来自视觉层级，而是来自「被记录」本身。** 打卡、数字、历史都在提醒「你在被衡量」；视觉平等只是表面，真正的问题是打卡范式。
4. **语义现实大于视觉平等。** 用户心里的自我叙事是「我今天只读了一句话，没读书」；无论界面怎么画，这句话都不会因为圆环满了而变成「完成」。
5. **效应量太小。** 14 天回访主要由提醒、生活事件、习惯本身的价值决定；三级视觉平等的效应可能小到单次原型和 5 人试点都测不出来。
6. **目标用户可能不是「失败过的人」。** 如果真正会用这个产品的是已经有稳定习惯、只需要记录的人，那「不制造羞耻」的前提就不成立，B1 的因果链要重写。

### 5.4 原型是毒药 / demo 效应

- **能 work ≠ 是最好的。** 三档平等在灰框里能跑通，不代表它比「一个默认动作 + 可展开降级」更好；后者甚至可能更便宜、更少决策。原型没有比较这两种交互结构，只比较了同一结构下的视觉处理。
- **用户是在评价原型，还是评价我的设计？** 灰框是刻意的，但它也可能让被试觉得「这只是个草稿，不用认真」。测试时明确说「结构是真的，视觉是假的；请按你真实生活里的反应来」。
- **Facilitator 效应**：不要解释假设、不要引导选微型、不要在被试面前用控制台。所有人先 A 后 B 是一个顺序偏差，已写在限制里。
- **环境效应**：实验室/会议室里的「忙」是演的；真实晚上 9:40 的疲惫、孩子在旁边、手机电量低，这些都不在原型里。结论只能迁移到「理解/合法性」层，不能迁移到真实行为。

## 6. 回灌信号

> 以下证据均来自「构建/走查原型」与「读上游文档」，不是用户测试结果。发信号的目的是让上游在真人测试前先修结构，不是宣布赌注被证伪。

### 🔄 信号 1：IA_REVISIT

**目标**：Product Architect

**证据**：PRD 范围写 1–3 个习惯；IA 骨架和状态矩阵只写「主习惯卡」（单数），没有「2–3 个习惯」的今天屏状态。构建默认态时必须二选一：只放一个习惯（本轮做法），或 3 张卡 × 3 档 = 9 个选项。后者在 390px 屏幕上会让「3 次点击内完成」和低能量时刻的决策负担同时失效。IA 也没有定义今天屏的三档与习惯详情「三级阶梯」的数据关系。

**建议**：在 IA 中定义多习惯今天屏——a) 一天只推一个「主习惯」（选择逻辑：用户置顶/按锚点时间/轮换）；b) 所有习惯折叠成一行，点开一个再显示三档；c) 每个习惯一张卡，但只显示一个默认动作，三档放在详情。补状态矩阵「2–3 个习惯」「主习惯切换」；明确今天卡与习惯详情阶梯是同一份数据。

### 🔄 信号 2：IA_REVISIT

**目标**：Product Architect

**证据**：中断态有两处表述不一致——IA 状态矩阵写「『回来也算数』+ 微型版」；IA 用户流 J2 写「微型版 / 简化版 / 完整版（3 个）」。如果「+ 微型版」被实现成预选，它就是一个默认值/推荐，等于在平等卡片里插了一个优先级，违反 A2 的视觉平等；如果只是文案提及，则没有定义如何降低回归摩擦。

**建议**：明确中断态是「三档平等 + 文案引导」还是「微型预选」。如果是后者，A2 的适用范围要写成「除中断态外」，并单独验证预选是否被读成推荐；如果是前者，补一个降低摩擦的机制（例如文案，而不是默认值）。

### 🔄 信号 3：MISSING_STATE

**目标**：Product Architect

**证据**：状态矩阵的「完成」只有「圆环填充+对勾+数字」，没有区分三档；回顾屏只写「本周概览+图表」「体感高光」，没有定义微型记录如何计入。原型完成态中，微型得到与完整相同的圆环/对勾/计数；如果回顾页用「完成次数」或只显示完整档，平等在第二天就破了。离线/保存失败的「排队完成 + 重开 + 同步」也没有状态条目；撤销没有定义体感是否删除、计数是否回退。

**建议**：补状态矩阵——完成态 × 三档；回顾/历史 × 三档；离线排队 + 重开 + 同步成功/冲突；撤销 × 体感/计数。明确计数语义：记录次数（三档都算）还是完整次数（只有完整算）。如果是前者，回顾页不能用不同视觉暗示高低。

### 🔄 信号 4：REQUIREMENT_UNTESTABLE

**目标**：Product Definer / Requirements Analyst

**证据**：PRD 的关键约束只写「三种完成度在视觉上平等，不用颜色区分高低」。它没有定义「平等」作用于哪些维度：颜色、尺寸、位置、顺序、默认值、命名（完整/简化/微型 vs 具体动作）、完成反馈（圆环/文案/计数）。原型必须在「三张等权卡片 / 单主行动+降级 / 先选情境再给一档」之间选一种操作化；每种都是「平等」的不同解释，结果可能不同。验证工具包 V1 的「平等版选择率 ≥60%」也没有定义场景（忙/闲）、分母、选择对象（选微型还是非完整档），以及「动机」如何测量。

**建议**：把 A2 拆成可操作变量，指定本轮只测哪一个，其余固定。把 V1 写成可观察的 2×2 场景（忙/闲）和明确分母；把「动机」拆成「本次选择 / 明天再来意图 / 14 天行为」三层，原型只负责第一层。把「无人报告『做少了也没关系所以不做完整版』」改成结构化追问 + 编码，而不是等待用户自发说出。

### 🔄 信号 5：BET_ASSUMPTION_BROKEN

**目标**：Product Definer

**证据**：B1 的因果链把「三级完成度」当作打卡反馈的视觉属性；但在界面上，三档首先是每天要做的三选一决策。原型默认态把三个选项同时摆出来，用户必须在低能量时刻做一次选择；这个决策负担不在 B1 的因果链里。如果用户因为「每天要选」而放弃，A2 的视觉平等就不是关键变量。这不是用户证据，是构建原型暴露的前提问题。

**建议**：明确 B1 的干预点是「选择结构」还是「完成反馈」。如果是前者，把「默认档 / 自动降级 / 上下文推荐」纳入赌注；如果是后者，先固定选择结构（例如一个默认动作 + 可展开的降级），再测反馈的视觉平等。否则 A/B 会混淆「选择负担」和「完成反馈」。

### 🔄 信号 6：REQUIREMENT_UNTESTABLE

**目标**：Product Definer / Requirements Analyst

**证据**：PRD 说体感记录是每日核心仪式、但可以跳过；没有定义是否按档位调整。原型完成态在「读一句话」之后仍显示完整的体感步骤（四个 chip + 跳过）。对微型档，这个步骤的负担与 10 秒的行动不成比例，可能正好在用户最忙的时候增加摩擦。验证工具包 V4 只测「一周写 ≥3 次」，没有分档位统计。

**建议**：明确体感步骤是否三档一致。如果不一致，定义微型档的精简版（一个词/直接跳过）；在 A3 的验证中按档位统计体感完成率，避免把「完整档写得多」误判为「体感仪式有效」。

## 7. 这个原型测不了什么

### 7.1 测不了（必须用别的工具）

| 问题 | 为什么测不了 | 该用什么 |
|---|---|---|
| 14 天回访率 | 单次原型没有时间维度 | 5 人试点行为日志 |
| 真实长期动机 / 习惯是否养成 | 一次会话测不到 | 纵向日记研究 / 试点 |
| 羞耻感随时间的积累 | 实验室场景抽掉了真实情绪 | 半结构化访谈 + 试点 |
| 用户会不会最终只做微型 | 需要真实选择重复发生 | 试点期选择分布 |
| A5 的 48h 回归率 | 中断后的真实行为不在原型里 | 试点行为日志 |
| A4 阶段标签可理解性 | 原型刻意不显示阶段标签 | 5 秒理解测试 |
| A3 体感记录的长期意愿 | 原型只走一次流程 | 一周日记 |
| 多习惯首屏 | 原型只放一个习惯 | 单独的 IA 探索原型 |
| 回顾页三档呈现 | 没有做回顾页 | 单独的回顾页原型 |
| 提醒/通知效果 | 不在范围内 | 试点 |
| 意图-行为差距 | 「明天会打开」不等于真的打开 | 行为日志 |

### 7.2 能测（但仅限第一层）

- 用户是否理解三档是同一件事的三种大小。
- 用户在「忙」的叙述场景里，是否把微型读成合法完成。
- 平等版 vs 对照版在单次选择/语言上的差异（小样本、被试内，需谨慎）。
- 三档完成态是否被读成「完成」还是「部分完成」。
- 空/错/加载/极端状态是否可操作、有没有 dead end。
- 文案「都算完成」是否可能是主动成分（通过追问，不是通过 A/B 隔离）。

### 7.3 边界声明

> 这轮原型是**仪器**，不是证据。它能筛掉「用户根本不理解 / 把微型读成偷懒」这一层；它不能证明「视觉平等提高 14 天回访」。后者需要试点。任何把本次结果写成「A2 被验证」的结论，都是过度推断。

### 8.2 按 anti-patterns 自检

- [x] 不是「完整 App」：只做今天屏 + 必要状态；习惯/回顾/我只做边界。
- [x] 没有过度抛光：纯灰度、系统字体、无品牌、无插画、无精细动效。
- [x] 不是 Markdown 描述：`prototypes/index.html` 可打开、可点、可读。
- [x] 没有 Lorem Ipsum：真实习惯、锚点、动作、时间、体感词、错误文案。
- [x] 不是只有快乐路径：空/错/加载/极端/离线/中断都覆盖。
- [x] 保真度没有超过问题：灰框足以回答合法性层；高保真会污染结构反馈。
- [x] 探索阶段没有颜色/品牌：全程灰度；对照版的黑色填充是灰度，不是品牌色。
- [x] 不是只做一个方向：验证模式做 1 个聚焦原型 + 1 个对照臂；没有伪装成探索。
- [x] 标准不是事后写的：第 3 节是 12:09 的 pre-registration；文件在 12:15 追加第 4–8 节，未回改任何阈值或判定线。
- [x] 没有发现上游问题却沉默：6 个信号。
- [x] 不是生产代码：硬编码、无后端、无部署；明确标注抛弃式。
- [x] 不是展品：给任务和观察点，不给「你觉得怎么样」。
- [x] 没有在屏幕上假装测真实场景：明确写了环境效应和迁移边界。
- [x] 说了「测不了什么」：第 7 节。

### 8.3 交接

**给 UI Designer**

- 可以拿去做的：三档等权卡片的**结构**已证明在 390px 下放得下、可点、可读；完成态的圆环/对勾/文案可以做到三档一致。但这些是**原型级验证**，不是用户验证。
- 要留退路的：三档的**命名**（完整/简化/微型 vs 具体动作）、**顺序**（大→小是否暗示推荐）、**默认值**（中断态是否预选微型）、**多习惯布局**。这四个都还没有答案。
- 不要做的：不要把「平等」做成只有卡片平等、完成态/最终态/回顾页却偷偷分级；A/B 走查已经证明这种不一致会立刻出现。

**给 Validation Researcher**

- 可测原型：`prototypes/index.html`；测试脚本、成功线、编码表在本文第 3 节。
- 样本：5 人，有过习惯失败经历、每天用手机、1–3 个习惯；排除团队成员和稳定习惯者。
- 已知偏差：所有人先 A 后 B（顺序偏差）；灰框可能让被试不认真；实验室场景不是真实晚上；5 人不是统计样本。
- 要验证的问题：S1–S4 / R1–R4；U1–U5 是一票否决的「测不了」条件。

**给 Product Architect**

- 先看信号 1–3：多习惯今天屏、中断态默认值、微型在回顾/离线/撤销中的状态。这三个是结构缺口，不是视觉问题。

**给 Product Definer**

- 先看信号 4–6：A2 的操作化、B1 的「选择 vs 反馈」前提、体感步骤与微型档的负担匹配。这三个会影响赌注的写法，不是 UI 能修的。

**验证状态一句话**：这轮没有验证任何用户-facing 结论；它把 A2 从「一个抽象赌注」变成了「一个可以拿给 5 个人点的仪器」，并暴露了 6 个上游问题。
