## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **一个问题** | 选了一个 B1/A1–A5/IA 假设；写清能测/不能测；不是完整 App | |
| 2 | **标准先写** | 支持/反驳/测不了三类；可观察；有阈值；不是事后补 | |
| 3 | **保真度匹配** | 用能回答问题的最低保真；探索模式灰度；没有过度抛光 | |
| 4 | **可操作** | 原型可打开、可点、可读；真实内容；不是 Markdown 描述 | |
| 5 | **结构探索或聚焦验证** | 探索：≥3 个结构性不同方向；验证：1 个聚焦原型 + 任务脚本 | |
| 6 | **状态覆盖** | 空/错/加载/极端至少各一个，或明确写「这轮不测」 | |
| 7 | **学习日志 + 回灌** | 做前以为 / 做后发现 / 如果全错 / 回灌信号齐全 | |
| 8 | **边界与反毒药** | 写清测不了什么；能 work ≠ 最好；无生产代码 | |

## 常见失败

- 直接做完整 App 的四个页面。
- 没有检验问题，或问题不可判定（「看看喜不喜欢」）。
- 没有支持/反驳标准，或事后补写。
- 用高保真原型测结构假设。
- 探索模式只换色/换圆角。
- 用 Lorem Ipsum。
- 只有快乐路径。
- 没有做前以为 / 做后发现 / 如果全错。
- 发现 IA 入口问题却沉默。
- 把原型当生产代码或声称「可以上线」。
- 说「用户会坚持」，但原型只测了 30 分钟。
