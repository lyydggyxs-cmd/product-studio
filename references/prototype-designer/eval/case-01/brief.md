# Brief · Prototype Designer Eval Case 01（个人习惯工具）

## 产品

一个给个人用的习惯养成工具：1–3 个习惯，每天一次轻量记录，按「触发 → 微小行动 → 意义 → 体感 → 身份」的四维模型设计。
移动端优先，个人使用，不做社交、排行榜、企业后台。

## 本次任务

上游已完成调研、定义、需求与 IA。你的任务**不是**做完整 App，而是：

> **选一个 B1 中最不确定、且原型能回答的假设，用最低成本的原型，让它第一次可以被看见、被点击、被否定。**

然后写清：这轮原型能回答什么、不能回答什么、观察到什么算支持/反驳、做之前以为什么、做之后发现什么、需要向上游回灌什么。

## 输入

| 输入 | 来自 | 读什么 |
|---|---|---|
| `evidence-base.md` | Research Analyst | 四维模型、三个真实案例、MVP 设计约束 |
| `bet-book.md` | Product Definer | B1、成功/kill 信号、致命假设 A1–A5 |
| `prd.md` | Product Definer | 范围、Anti-goal、核心 Job |
| `ia-flows.md` | Product Architect | 4 个一级区域、用户流、状态矩阵、信心地图 |
| `validation-toolkit.md` | Product Architect | 哪些假设待验证、验证工具与回退规则 |

## 要产出什么

1. **`prototypes/`**
   - 探索模式：≥3 个结构性不同方向（纸面/灰框 HTML 均可；禁止颜色/品牌）
   - 或验证模式：1 个聚焦的可点击原型（真实内容；核心流可点通；覆盖空/错/加载/极端）
   - 原型必须是**可打开、可点、可读**的东西，不能只有 Markdown 描述
2. **`test-notes.md`**
   - 检验的赌注/假设 + 为什么选它
   - 模式（探索/验证/模拟）+ 保真度 + 为什么是这个保真度
   - 做之前写的支持 / 反驳 / 测不了三类标准
   - 做之前以为 / 做之后发现 / 如果这个方向全错了可能是因为
   - 回灌信号（IA_REVISIT / BET_ASSUMPTION_BROKEN / MISSING_STATE / REQUIREMENT_UNTESTABLE）
3. **`open-questions.md`**
   - 原型暴露的新问题，按「结构 / 赌注 / 需求 / 状态」分类

## 硬规则

- 一个原型只回答一个问题；不要做完整 App。
- 保真度用能回答问题的最低保真；探索阶段禁止颜色与品牌。
- 用真实内容，不用 Lorem Ipsum。
- 支持/反驳标准必须先写，不能事后补。
- 不写生产代码（无后端 / 部署 / 完整架构）；原型是抛弃式的。
- 明确写「这个原型测不了什么」。
- 发现上游问题必须发回灌信号，不能沉默。

## 什么算成功

- 这轮真的回答了一个问题，而不是「做了几个页面」
- 保真度匹配：没有过度抛光，也没有不可操作
- 有可观察的支持/反驳标准，且先于数据
- 结构探索有真正的结构差异（如果你选探索模式）
- 原型覆盖非快乐路径，或明确写「这轮不测」
- 学习日志有意外、有「如果全错」、有回灌
- 诚实地划出原型的能力边界

## 明确不做

- 完整 App 的四个页面
- 视觉打磨、品牌、设计系统
- 生产代码、后端、部署
- 替代真人研究去证明「长期能坚持」

## 时间盒

45–60 分钟。优先保证「问题 → 标准 → 低保真原型 → 学习日志」完整，不要追求页面数量。
