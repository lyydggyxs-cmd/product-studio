# Prototype Designer · 评分标准

> 用于评审 Prototype Designer 的产出，或用于 eval。
> 0–4 锚点；不是打分游戏，是诊断工具。

---

## 评分维度

| # | 维度 | 核心问题 |
|---|---|---|
| 1 | **检验问题** | 这轮原型回答哪个具体赌注/假设？一个问题还是「做个完整 App」？ |
| 2 | **支持 / 反驳标准** | 观察到什么算支持、什么算反驳？标准是先写的吗？ |
| 3 | **保真度匹配** | 用的是能回答问题的最低保真吗？有没有过度抛光？ |
| 4 | **可操作性** | 人能打开、能点、能读吗？真实内容还是 Lorem Ipsum？ |
| 5 | **结构探索** | 探索模式有 ≥3 个结构性不同方向吗？不是换色？ |
| 6 | **状态覆盖** | 空 / 错 / 加载 / 极端覆盖了吗？还是只有快乐路径？ |
| 7 | **学习日志与回灌** | 做前以为 / 做后发现 / 如果全错 / 回灌信号都有吗？ |
| 8 | **反毒药与边界** | 有没有「能 work ≠ 最好」的反思？说清原型测不了什么？ |

---

## 0–4 锚点

| 分 | 含义 | 通用表现 |
|---|---|---|
| **0** | 缺失 | 完全没有这个维度 |
| **1** | 提名 | 提到概念，但没有执行 |
| **2** | 部分 | 有执行，但明显不足 / 不一致 |
| **3** | 合格 | 达到标准，可用于决策 |
| **4** | 示范 | 不仅达标，还能作为模板 |

### 1. 检验问题

| 分 | 表现 |
|---|---|
| 0 | 没有检验问题，直接做完整设计 |
| 1 | 说「看看用户喜不喜欢」，不可判定 |
| 2 | 有一个问题，但太宽或与赌注脱节 |
| 3 | 一个问题，追到具体赌注/假设，写清能测/不能测 |
| 4 | 还写了「为什么这个问题最不确定、最值得先测」 |

### 2. 支持 / 反驳标准

| 分 | 表现 |
|---|---|
| 0 | 没有标准，做完再说 |
| 1 | 只有「支持」没有「反驳」，或标准不可观察 |
| 2 | 有标准，但阈值模糊或事后补写 |
| 3 | 做之前写：可观察的支持 / 反驳 / 测不了三类 |
| 4 | 还给每条标准配了观察方法（任务、访谈问题、行为日志） |

### 3. 保真度匹配

| 分 | 表现 |
|---|---|
| 0 | 没有原型，只有文档描述 |
| 1 | 保真度严重超过或低于问题需要（如用高保真测结构） |
| 2 | 保真度大体合适，但有明显过度抛光或不可操作 |
| 3 | 用能回答问题的最低保真；探索阶段无颜色/品牌 |
| 4 | 还写了「为什么不是更高/更低保真」以及过度抛光的风险 |

### 4. 可操作性

| 分 | 表现 |
|---|---|
| 0 | 只有 Markdown 描述，没有可打开的东西 |
| 1 | 有 HTML/纸面，但核心流点不通或大量 dead end |
| 2 | 能点通主路径，但内容假、状态少 |
| 3 | 可点击；真实内容；核心流无 dead end；每个交互有反馈 |
| 4 | 还标注了「这是原型不是产品」，并记录已知不可测部分 |

### 5. 结构探索

**模式感知**：探索模式按「≥3 个结构性不同方向」评分；验证模式不要求做 3 个方向，但要求说明「为什么这轮不做结构探索」+ 下一轮的结构候选（含假设 / 支持反驳）。验证模式下只写 N/A 不得分；给出候选表和选择规则可得 3–4。

| 分 | 表现 |
|---|---|
| 0 | 只有一个方向，且没说为什么 |
| 1 | 多个方向，但只是换色/换圆角 |
| 2 | 2 个方向结构不同，但差异不足 |
| 3 | 探索：≥3 个结构性不同方向；各有假设、支持/反驳条件。验证：说明为什么不做结构探索 + 下一轮候选与选择规则 |
| 4 | 还给每个方向写了「它假设用户是谁、在什么时刻、怎么组织信息」和取舍表；或验证模式的候选已做成可点方向 |

### 6. 状态覆盖

| 分 | 表现 |
|---|---|
| 0 | 只有默认态 |
| 1 | 只有快乐路径 |
| 2 | 覆盖空/错/加载中的 1–2 个 |
| 3 | 空 / 错 / 加载 / 极端至少各一个；每个写「看到什么 + 能做什么」 |
| 4 | 还明确写「这轮不测哪些状态、为什么」；非快乐路径是重点 |

### 7. 学习日志与回灌

| 分 | 表现 |
|---|---|
| 0 | 只交原型，没有学习日志 |
| 1 | 有「发现」，但没有「做前以为 / 如果全错」 |
| 2 | 有学习日志，但没有回灌信号 |
| 3 | 做前以为 / 做后发现 / 如果全错 / 回灌信号齐全 |
| 4 | 回灌信号带证据、目标岗位、具体建议；还记录了意外发现 |

### 8. 反毒药与边界

| 分 | 表现 |
|---|---|
| 0 | 声称「这个方向就是对的」；没有反思 |
| 1 | 只有「能 work」的结论，没有「如果全错」 |
| 2 | 有反思，但没有说原型测不了什么 |
| 3 | 写了「能 work ≠ 最好」、如果全错的可能原因、原型的测试边界 |
| 4 | 还区分了「用户评价原型」与「用户评价设计」的 demo 效应，并给出缓解方式 |

---

## 门控规则

以下任意一条触发，**退回重做**：

- **维度 1 = 0**：没有检验问题 → 这不是原型，是提前做完整设计。
- **维度 2 = 0**：没有支持/反驳标准 → 结果无法判定，做完也不知道学到什么。
- **维度 3 ≤ 1**：只有文档描述，或保真度严重错配 → 原型不可操作或反馈被污染。
- **维度 7 = 0**：没有学习日志 → 下一轮不知道改哪里。

## 总分参考

| 总分（8 维，满分 32） | 判断 |
|---|---|
| 28–32 | 可作为模板 |
| 22–27 | 可进入下游 |
| 16–21 | 需修正后重审 |
| < 16 | 退回 |

> 总分只作参考；门控优先。
