# Product Definer · 方法库

> 这是 Product Definer 的「专业能力」参考。目标不是写更多文档，是做一个可证伪、可执行、可停止的产品赌注。

---

## 1. 问题框定

### 先写「决定什么」

```
我们这轮要决定的是：______
不是：______
如果这轮不做决定，会怎样：______
```

### 好框定 vs 坏框定

| ❌ 坏框定 | ✅ 好框定 |
|---|---|
| 「设计一个做饭助手」 | 「先验证『一人份准备成本』还是『决策成本』是断裂点，决定先做哪个环节」 |
| 「优化周报体验」 | 「决定先服务写作者还是管理者，验证『写了没人读』还是『不知道写什么』是主因」 |

**原则**：框定的是**决策**，不是**方案**。

---

## 2. 竞争因果假说

### 为什么要竞争

一个假说不是分析，是信念。至少 2 条真正不同的因果链，才能知道「什么证据能杀死我们」。

### 结构

```
触发事件 → 产品介入 → 用户状态转变 → 行为改变 → 结果
```

每条：
- 一句话机制
- 证据 ID + 置信度
- 最薄弱环节
- 如果这条成立，观察到什么
- 如果这条不成立，观察到什么

### 好假说的标准

- 两条假说的**预测不同**——不是措辞不同。
- 能指出**区分性证据**——什么观察能分开它们。
- 能被**一个实验**在 2 周内证伪。

---

## 3. 区分性证据

### 核心问题

> 什么观察，能区分假说 A 和假说 B？

如果找不到，说明你没有真正的竞争假说，只是用不同语言说了同一件事。

### 例子

| 假说 | 区分性观察 |
|---|---|
| H1 流程成本 | 给「明确菜单 + 洗净切好的食材」，一个人吃仍不做 → H1 弱 |
| H2 决策过载 | 有菜单仍卡在选择 → H2 强 |
| H3 意义感缺失 | 一个人吃 vs 有人一起吃，行为差异显著 → H3 强 |

### 输出

写进 bet-book 的「竞争假说」表：
| 假说 | 因果链 | 预测 | 区分性证据 | 证据强度 |

## 4. JTBD 四力量

| 力量 | 问什么 | 在本产品里 |
|---|---|---|
| **推力（Push）** | 现状哪里不舒服？ | 买菜/洗菜/洗碗太麻烦；外卖吃腻 |
| **拉力（Pull）** | 新方案吸引什么？ | 掌控感；健康；省钱；一次成功 |
| **焦虑（Anxiety）** | 换方案的担忧？ | 做砸；浪费；时间；洗碗 |
| **惯性（Habit）** | 为什么留在旧方案？ | 外卖习惯；泡面；便利店 |

**判断**：推力 + 拉力 是否显著大于 焦虑 + 惯性？

如果优势不明显 → 赌注的前提需要重审。

## 5. 赌注构造

### 格式

```
如果 [产品做什么 / 用户处于什么条件]，
那么 [用户行为/状态发生什么改变]，
因为 [因果机制]。
```

### 一个赌注，不是 5–7 个

- 5–7 个赌注 = 你在列功能，不是在下注。
- 一个赌注 = 如果错了，产品方向需要根本改变。
- 其他假设写成「条件」或「风险」，不写成并列赌注。

### 赌注必须可证伪

- 有成功信号
- 有 kill 信号
- 有 Plan B
- 有信心度 + 理由
- 有证据 ID（支持 + 反对）

---

## 6. 信心度校准

### 0–10 怎么打

| 分数 | 含义 |
|---|---|
| 0–2 | 纯猜测；只有直觉 |
| 3–4 | 有邻近证据，但核心动作未验证 |
| 5–6 | 有直接证据，但样本/场景有限 |
| 7–8 | 多个独立证据支持，且在本场景验证过 |
| 9–10 | 已被本产品/本场景反复验证 |

### 写什么

- 为什么不是更低
- 为什么不是更高
- 最薄弱的 1–2 个环节
- 如果这个环节错了，赌注会变成什么

---

## 7. 成功信号 / Kill 信号

### 成功信号

具体、可观察、可测：
- 「≥2/3 孩子在无人提示下主动发起第 2 次」
- 「≥2/3 家长在一周内第二次使用」
- 「≥2/3 管理者因为周报做出一个行动」

### Kill 信号

每个 kill 指向不同病灶，不是同一个「失败」的四种说法：
- K1 杀死前提（主因不是 X）
- K2 杀死方案（X 有害）
- K3 杀死形态（交付方式不可行）
- K4 杀死价值（用户看不出价值）

### 硬规则

- 判定线先于数据。
- 不可事后修改。
- 小样本只能定方向，不能证明效应量。

### 判定线纪律

- **同一尺度**：所有 kill 阈值必须在同一指标/尺度上；不能一条用绝对人数、一条用比例、一条没有阈值。
- **中间带**：定义「既不支持也不 kill」的区间；否则结果落在中间时，团队会事后解释。
- **可归因**：如果干预是组合包，不要叫「单变量」；加归因测量（哪个成分导致了变化）。

## 8. 范围与 Anti-Goals

### 范围

只写验证赌注所需的最小闭环，不写完整产品 backlog。

### Anti-Goals

| ❌ 借口 | ✅ 判断 |
|---|---|
| 「没时间做」 | 「不服务核心赌注；如果做了，会稀释 X」 |
| 「技术做不到」 | 「和另一个更强的需求矛盾；恢复条件是 Y」 |
| 「以后再说」 | 「当前证据不支持；如果出现 Z 证据，重新考虑」 |

每条 Anti-Goal 带：
- 不做什么
- 为什么不做（判断，不是资源）
- 被牺牲的价值
- 恢复条件

---

## 9. Pre-Mortem / 价值破坏

### Pre-Mortem

> 发布 90 天后，产品失败了。从第一天到第 90 天，发生了什么？

写一个完整的失败故事，然后找：
- 哪些转折点被当前范围防住了
- 哪些没有 → Blind Spot

### 价值破坏

> 做好这个需求，可能意外破坏什么？

例子：
- 做「自动提醒」→ 可能破坏「不监控」的承诺
- 做「排行榜」→ 可能把内在动机变成外部比较

每个价值破坏 → 设计约束，不是「所以不做」。

---

## 10. Plan B

### 坏 Plan B

- 「重新思考」
- 「再做一轮调研」
- 「根据数据调整」

**这是逃避，不是计划。**

### 好 Plan B

具体到「转向哪里、保留什么、放弃什么」：

| 触发 | 转向 | 保留 |
|---|---|---|
| 孩子不主动 | 难度阶梯：从「会」的一档起步 | 诊断、家长不教、纸面 |
| 故事伤害迁移 | 故事降级为一句情境锚 | 新同构、诊断闭环 |
| 打印摩擦大 | 一次准备、多次使用 | 双工件、零评价 |

## 11. PRD 活文档

### 不写 10 节大文档

PRD 是当前决策状态的快照，不是一次性交付物。结构：

1. 产品是什么（用户视角一句话）
2. 为什么做（核心 Job + 机制 + 关键证据）
3. 为谁做（核心用户 + 极端用户 + 不服务谁）
4. 做什么（本期范围 + 核心需求链接）
5. 不做什么（Anti-Goals + 恢复条件）
6. 怎么知道赌对了（成功/kill 信号 + 验证方式）
7. 已知风险与不确定性（✅/⚠️/🔮）
8. 版本历史（谁驱动了变化）

### 硬规则

- 独立可读：新人读完知道做什么、不做什么、不确定什么。
- 每个断言有证据或标 🔮。
- 版本化：V0.1 → V0.2；不覆盖旧版本。

---

## 12. 决策日志

每个关键取舍写一条：
- 决定了什么
- 为什么（证据 + 权衡）
- 考虑过但没选什么
- 什么条件下重新评估
- 谁做的决定

**只追加，不删除。** 被推翻的决策标 superseded，并写被谁取代。

---

## 13. 证据追溯

### 每个赌注/需求/决策

```
赌注 → 证据 ID → 来源
```

### 硬规则

- 没有证据 ID 的赌注 → 标 🔮，写推断依据。
- 反对证据必须列出，不能只列支持证据。
- 如果证据被推翻，赌注要更新，而不是把证据藏起来。

---

## 14. 什么时候停

### 停止条件

- 核心赌注的 kill 信号被触发
- 3 个以上关键假设同时未验证，且都承载核心价值
- 同一个问题 2 轮没解决
- 时间盒到期
- 用户明确说停

### 停下来不是失败

**在错误方向上继续才是。**
