## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **一个赌注** | 只一个，不是 5–7 个并列 | |
| 2 | **可证伪** | 成功信号 + kill 信号都具体、可观察 | |
| 3 | **机制具体** | 说清是流程成本/决策过载/意义感中的哪一个，为什么选它 | |
| 4 | **证据链接** | 引用 ≥4 个证据 ID，且列反对证据（E01/E03/E09） | |
| 5 | **不拆合并项** | 没把 51.6% 拆成「洗碗是最大断裂点」；如写具体环节，是假设句 + 验证计划 | |
| 6 | **Anti-Goals 是判断** | 每条有理由 + 被牺牲价值 + 恢复条件；不是「没时间」 | |
| 7 | **Plan B 具体** | 写清转向哪、保留什么 | |
| 8 | **PRD 可独立读** | 一页能读出是什么/为谁/赌什么/不做什么/成功标准/不确定性 | |

## 常见失败

- 选了一个赌注，但范围里塞了 10 个功能。
- 把 51.6% 拆成「洗碗最致命」。
- 成功信号是「用户喜欢」。
- Plan B 是「重新思考」。
- Anti-Goals 是「没时间」。
- PRD 是 10 节模板，读完不知道核心赌注。
