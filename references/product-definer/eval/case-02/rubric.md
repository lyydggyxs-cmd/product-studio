## Case-specific 检查

| # | 检查项 | 通过标准 | 证据位置 |
|---|---|---|---|
| 1 | **一个赌注** | 只一个，不是 5–7 个并列 | |
| 2 | **可证伪** | 成功信号 + kill 信号都具体、可观察 | |
| 3 | **机制具体** | 说清是读者侧/内容侧/制度侧中的哪一个，为什么选它 | |
| 4 | **证据链接** | 引用 ≥4 个证据 ID，且用 Stray 2016；列限制（61% 合并项、E18 8 人） | |
| 5 | **不拆合并项 / 不单源主结论** | 没把 61% 拆成「写作是最大瓶颈」；读者侧写成「优先验证」而非「最可能」 | |
| 6 | **「行动」有定义** | 成功信号是回复/决策/调整资源，不是「已读/已提交」 | |
| 7 | **Anti-Goals 是判断** | 每条有理由 + 被牺牲价值 + 恢复条件；不是「没时间」 | |
| 8 | **Plan B + PRD + 决策日志** | Plan B 具体；PRD 一页可读；决策日志有替代方案 | |

## 常见失败

- 直接写「自动聚合 + AI 摘要」功能列表。
- 没有管理者视角。
- 把「已读」当「行动」。
- 把 61% 拆成「写作太花时间」。
- 读者侧写成「最可能」，忽略 E18 只有 8 人。
- Plan B 是「继续迭代」。
- Anti-Goals 是「没时间」。
