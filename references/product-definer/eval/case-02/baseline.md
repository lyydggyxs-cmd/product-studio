# Baseline · Product Definer Eval Case 02

> 一个**没有能力包**的通用 Agent 通常会写出什么。评分时先读这个，避免把「更完整的 PRD」误判为「能力包有效」。

## 典型产出

1. **10 节 PRD**：背景、目标、用户、功能、竞品、排期、风险、指标、里程碑、附录。
2. **功能列表**：自动聚合、AI 摘要、模板库、定时提醒、飞书/Notion 集成、数据看板、移动端。
3. **赌注**：「团队需要更自动化的周报工具，因为写周报太花时间。」
4. **成功标准**：「周报提交率提升、用户满意度提升」——不可观察。
5. **Kill 信号**：无。
6. **Plan B**：「如果失败，继续迭代。」
7. **Anti-Goals**：「不做绩效，因为没资源。」
8. **证据**：引用 1–2 条行业数据，没有 ID，没有反对证据。

## 它缺什么

- 不是一个赌注，是 7 个功能。
- 不可证伪：成功是「提交率/满意度」，不是行动。
- 没有区分写作者和读者。
- 没有机制：只有「太花时间」这个现象。
- 没有 kill 信号。
- Plan B 是「继续迭代」。
- Anti-Goals 是资源借口。
- 没有「已读 ≠ 行动」。
- 没有证据 ID，没有反对证据。

## 评分提示

如果产出和 baseline 的差别只有「更长、更完整」，以上缺项仍在 → 能力包没有生效。
如果产出在一个赌注、读者侧/内容侧机制、「行动」定义、kill 信号上有明显改善 → 记录具体改善项。
