# Expected Output · Design Critic Eval Case 01（个人习惯工具 UI）

> 一份合格评审必须包含以下内容。不要求发现完全一致；要求「范围清晰、意图对齐、证据可定位、分级校准、覆盖完整、不给方案、路由正确、判断明确」。

## 1. 评审范围

- 评审对象：UI 设计稿 + 设计系统 + 状态页
- 保真度：高保真
- 评：意图对齐 / 一致性 / 状态覆盖 / 可访问性 / 视觉层级 / AI slop
- 不评：品牌识别 / 营销页 / 生产代码 / 审美裁决（标 ⚪）
- 输入：bet-book / prd / ia-flows / requirements / design-system / ui-spec

## 2. 意图对齐

逐条对照并给证据：
- 赌注 B1：视觉语法是否服务「三级平等 + 中断不焦虑 + 体感高光」
- 核心 Job J1–J4：界面是否有自然入口
- 关键 AC：AC1.1–AC5.2 是否能在界面上验证
- 品牌温度 / 信息密度：是否与设计意图一致
- 结论：通过 / 有保留 / 不通过

## 3. 问题清单

至少 3–5 条，覆盖不同严重度：
- 🔴 阻断（如有）：不改不能交付；必须能回答「不改会怎样」
- 🟡 重要：影响品质但不阻断
- 🟢 建议：可选优化
- ⚪ 无法判断：需人眼/真机/真人

每个问题必须有：
- 位置（页面/组件/状态/截图/源码行）
- 观察到什么（具体可见事实）
- 原则/场景（Nielsen / 状态矩阵 / AC / 可访问性标准）
- 影响（用户会怎样）
- 路由（Definer / Architect / UI / Validation / Requirements）

**可接受的发现示例**（不要求全部命中）：
- 保存失败态缺 `role="alert"` 或「数据是否保留」说明
- 暗色模式只有令牌、没有出图
- 极端数据/部分失败只有规格层
- 习惯列表 / 「我」页未设计
- 「1/3」的分母/语义可能被误读
- 三级 chip「完整在左」仍有位置偏差
- 宋体在非 Apple 设备的回退未验证
- 对比度/触控/焦点等可访问性问题

## 4. 覆盖检查

逐项 ✅/❌ + 证据：
- 空 / 错 / 加载 / 中断 / 极端 / 响应式 / 可访问性
- 不能只打勾；缺失项要写「缺什么」
- 不覆盖的项要写「为什么这轮不测」

## 5. 不给方案

- 不写「改成 X」「加一个 Y」「用 Z 字体」
- 只描述问题与影响
- 方向性建议必须标「建议，不是评审结论」，且不与评审结论混在一起

## 6. 路由

每个发现标归属：
- 价值/赌注 → Product Definer
- 结构/IA/状态矩阵 → Product Architect
- 交互/视觉/文案 → UI Designer
- 需真人验证 → Validation Researcher
- 需求不可测/AC 缺失 → Requirements Analyst

## 7. 无法判断

诚实列出：
- 审美判断（暖度、字体配对、苔绿语义）
- 动效节奏（静态截图不能判断）
- 字体回退（非 Apple 设备）
- 真实用户行为（需真人测试）

## 8. 总判断

- ✅ 可进入下一阶段 / ⚠️ 有保留 / ❌ 退回修改
- 列出「必须修」「记录但不阻断」「不评」三类
- 总判断必须被问题清单支撑；不能「整体不错」但没有证据

## 9. 如果证据不足

如果无法判断某个维度，**标 ⚪ 并说明需要什么条件**（人眼/真机/真人/更多截图），不要假装能判断。把「无法判断」写成「没问题」是失败。
