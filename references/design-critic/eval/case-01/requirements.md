## 信号卡（先读这 10 行）

- **结论方向**：B1 可以拆成 5 条 P0，构成「打卡 → 中断回归 → 完成反馈 → 回顾 → 暂停」的最小验证闭环。
- **置信度**：中低。3 个个人案例 + MVP 设计约定，全部证据为 ⚠️/🔮，没有 ✅；5 人试点只能做方向性判断，不能做统计检验。
- **如果前提错了**：A1（3 次点击）不成立 → R01 的点击预算和流程要重写；A5（不焦虑提高回归）不成立 → R02 要加轻量提醒，但不能用失败语言；A3（体感高光有意义）不成立 → R03/R04 降为可选，产品退回普通打卡。
- **最大的矛盾**：C4「本轮不提醒」与「48 小时回归率 ≥40%」——没有回归触发，中性中断态可能根本没有机会被看到；这个指标可能测不到 B1 的效果。
- **需要先决策**：C1 中断态默认预选微型 vs 三档平等；C2 记录次数 vs 完整次数；C3 体感步骤是否计入 3 次点击；C4 提醒；C5 巩固期连续天数 vs Anti-goal。
- **下游先别做**：在 C1–C5 决策前，不要把默认档、计数语义、体感步骤位置、提醒、连续天数写死进 IA / 原型 / 设计。
- **本包不包含**：IA、用户流、视觉、组件、文案、排期、功能 backlog。

## 0. 赌注锁定

### 0.1 B1 一句话复述

**如果** 打卡反馈采用「阶段感知 + 三级完成度视觉平等 + 中断不渲染焦虑 + 体感高光回顾」，
**那么** 启动期用户在第 14 天的回访率会达到 ≥50%，
**因为** 反馈回路不再用「连续天数 / 中断警报」制造羞耻，而是把注意力放回「今天这个微小行动」和「身体已经体验过的好处」。

**置信度**：⚠️ 方向有 3 个案例与 MVP 设计支持，但没有实验证据。

### 0.2 成功信号与本包的对应关系

| 信号 | 阈值 | 测量 | 本包中对应 |
|---|---|---|---|
| 14 天回访率 | ≥50% | 5 人小样本试点 | R01–R05 整体闭环 |
| 打卡完成率 | ≥70% | 试点期 | R01 / R02 |
| 「没有被评判」自评 | ≥4/5 人 | 半结构化访谈 | R02 / R04 / R05 |
| 中断后 48 小时内回归率 | ≥40% | 试点期 | R02（受 C4 影响） |

### 0.3 Kill 信号与本包的处理

| 信号 | 阈值 | 行动 | 本包中对应 |
|---|---|---|---|
| 14 天回访率 | <20% | 停掉当前反馈设计，回到访谈 | 整个闭环失败；不能只改一条需求 |
| 焦虑/羞耻自评 | ≥2/5 人 | 立即移除连续天数/中断提示，重做 | R02 / R04 / R05 的失败线 |
| 打卡完成率 | <40% | 检查门槛与提醒，不先改视觉 | R01 的失败线 |
| 体感记录被跳过 | ≥70% | 体感日志降为可选，不占主流程 | R03 / R04 的失败线 |

### 0.4 本包的范围与证据底线

- **只服务 B1**：本包不写第二个赌注，也不写生产发布所需的全量需求。
- **没有 ✅ 证据**：B1 的所有环节都是 ⚠️ 或 🔮；本包的 AC 是「可验证」，不是「已验证」。
- **5 人样本的边界**：所有通过线都是方向性阈值，不做统计显著性；A2 原本的 A/B 在 5 人下不可行，见 §9.5。
- **追溯规则**：每条需求必须能回答「服务哪个赌注 / 依据哪条证据 / 如果不做会怎样 / 怎么算满足」。答不上来的，删掉或标 🔮。

## 1. 核心 Job Story

> 格式：When [具体情境：时间/地点/情绪/设备/认知负荷/社会情境] / I want to [动机，不是功能] / so I can [可感知的结果]。
> 5 条 Job Story 分别对应 5 条 P0；情境六要素逐条列在表里，方便下游直接使用。

### JS1 · 日常完成（服务 R01）

> **When** 周三 21:40，厨房灯还亮着、碗刚洗完，孩子已经睡了，我靠在沙发上只剩 2 分钟，单手拿手机，脑子不想再做任何选择，
> **I want to** 用最小的动作把今天这件事记下来，并且不管我做的是完整版、简化版还是只走了一小步，都算数，
> **so I can** 不让这一天无声地断掉，也不觉得我在骗自己。

| 情境要素 | 内容 |
|---|---|
| 时间 | 周三 21:40，一天快结束时 |
| 地点 | 家里，厨房/客厅沙发 |
| 情绪 | 累、想快点结束、不想被评判 |
| 设备 | 手机，单手 |
| 认知负荷 | 极低；不想做选择、不想读说明 |
| 社会情境 | 孩子睡了，一个人 |

- **服务赌注**：B1；A1（3 次点击）、A2（三档平等）、A4（阶段标签可理解）
- **证据强度**：E02 ⚠️ / E07 ⚠️ / E08 ⚠️；A1 / A2 / A4 均为 🔮（E01 是锚点证据，不直接支持点击预算/三档平等，不挂在本条）
- **如果错了**：如果用户连 3 次点击都不愿意，A1 不成立，需要降到 1 次点击并砍掉体感记录（bet-book 的回退）。

### JS2 · 中断后回归（服务 R02）

> **When** 周四早上 7:20，地铁上刷手机，发现昨天没有记录，心里冒出「又断了，算了吧」的念头，周围都是人，我不想被任何东西提醒我失败了，
> **I want to** 看到今天仍然可以正常开始、三个档位都还在，而不是一个失败警报或归零的连续天数，
> **so I can** 把一次中断当成一次普通的停顿，而不是放弃的理由。

| 情境要素 | 内容 |
|---|---|
| 时间 | 周四 7:20，通勤早高峰 |
| 地点 | 地铁 |
| 情绪 | 懊恼、想放弃、怕被评判 |
| 设备 | 手机，单手 |
| 认知负荷 | 低；只想快速确认「还能不能继续」 |
| 社会情境 | 周围有人，不想被看到/被提醒 |

- **服务赌注**：B1；A5（中断不渲染焦虑会提高回归率）
- **证据强度**：E08 ⚠️（中断消息只在中断日出现、不渲染焦虑）/ E10 🔮（连续天数、失败警报可能制造羞耻）；A5 🔮
- **如果错了**：如果中性状态让用户觉得「被放任」，A5 不成立，需要加一个轻量提醒，但不能使用失败/指责语言（bet-book 的回退）。

### JS3 · 完成后的体感（服务 R03）

> **When** 刚做完 10 分钟散步、身体还有点热、站在玄关换鞋，手机在手里，我不想写日记也不想被打分，
> **I want to** 用一个词记下刚才身体的感觉，或者明确地跳过而不被追问，
> **so I can** 让这次行动留下一个身体记得的痕迹，而不是只留下一个勾。

| 情境要素 | 内容 |
|---|---|
| 时间 | 刚完成行动，晚上 |
| 地点 | 玄关/家门口 |
| 情绪 | 放松、微微发热、有点满足 |
| 设备 | 手机 |
| 认知负荷 | 低；不想写长文、不想被评分 |
| 社会情境 | 一个人 |

- **服务赌注**：B1；A3（体感高光回顾对用户有意义）
- **证据强度**：E04 ⚠️（体感是内在奖励）/ E09 ⚠️（体感记忆系统，设计假设）；A3 ⚠️
- **如果错了**：如果用户觉得这是作业，或跳过率 ≥70%，A3 不成立，体感日志降为可选（kill signal）。

### JS4 · 一周回顾（服务 R04）

> **When** 周日晚上 21:00，一周忙完，我有点怀疑「这几周到底有没有变化」，坐在床上，愿意花 2 分钟看看，
> **I want to** 看到这一周我实际记录了几次、以及我自己写过的身体感受，而不是「你还差几天」，
> **so I can** 感到我确实走了几步，并且愿意下周继续。

| 情境要素 | 内容 |
|---|---|
| 时间 | 周日 21:00，周末快结束 |
| 地点 | 床上 |
| 情绪 | 怀疑、疲惫、需要一点证据 |
| 设备 | 手机 |
| 认知负荷 | 愿意花 2 分钟，但不想分析图表 |
| 社会情境 | 一个人 |

- **服务赌注**：B1；A3（体感高光回顾）
- **证据强度**：E03 ⚠️（意义重构）/ E04 ⚠️（体感）/ E09 ⚠️（体感高光）；A3 ⚠️（E05/E06 是身份阶段与阶段演化，不直接支持回顾页，不挂在本条）
- **如果错了**：如果用户只看数字不读体感高光，体感高光降为可选（bet-book 的回退）；如果用户把数字读成「我很差」，R04 的框架失败，需要重写。

### JS5 · 暂停（服务 R05）

> **When** 出差/生病/项目忙到第 3 周，我知道自己这几天做不到，打开 app 想「干脆删掉算了」，但又不想把之前的记录一起抹掉，
> **I want to** 暂时停下一个习惯、保留已经留下的记录，并且不被标记为失败，
> **so I can** 不带负罪感地离开，也知道想回来时从哪里接上。

| 情境要素 | 内容 |
|---|---|
| 时间 | 忙碌/生病期的某个晚上 |
| 地点 | 酒店/家里 |
| 情绪 | 疲惫、内疚、想放弃 |
| 设备 | 手机 |
| 认知负荷 | 低；只想做一个「停还是继续」的决定 |
| 社会情境 | 可能一个人 |

- **服务赌注**：B1（不制造羞耻）；Anti-goal（不做连续天数归零/失败文案）；OQ7（暂停/放弃是否需要）
- **证据强度**：E10 🔮（游戏化机制可能制造羞耻，间接推断）；OQ7 未决；没有直接用户证据 → 整条标 🔮
- **如果错了**：如果暂停让用户更容易彻底离开（而不是回来），A5/B1 的回归假设不成立，需要重新评估「允许停」与「保持牵引」的平衡。

| 候选 | 删掉它，B1 还能验证吗？ | 判断 |

| **R01 打卡闭环** | 不能。没有打卡就没有反馈回路，后面的中断、体感、回顾都无从发生。 | P0 |

| 数据导出/设置/关于 | 能。不是 B1 的变量；但导出是用户权利，生产前必须补。 | P2 / 生产前 |
| 徽章/等级/积分 | 能，但外部奖励会污染 A3/A2 的归因，且容易变成比较。 | 不做（见 §5） |

**结论**：这 5 条覆盖了用户实际经历的一个完整循环——今天做（R01）→ 断了回来（R02）→ 记住为什么值得（R03）→ 一周后看到积累（R04）→ 允许停（R05）。删掉任意一条，B1 都只能被部分验证，且无法解释失败发生在哪一环。

**P0 归因风险（诚实声明）**：R01 同时承载 A1/A2/A4，R03/R04 是 A3 的两半；5 人试点里若结果混合，无法归因到单个假设。缓解：AC 分列、逐条记录；若试点显示归因困难，下一轮把 R01 拆成 R01a（点击预算）/ R01b（三档平等）/ R01c（阶段可理解），或加条件。

## 3. 需求详情与验收标准

> 每条 AC 只测一个假设；每条都有通过线 / 证伪线 / 需要更多数据。

### 3.0 中间带规则（所有数字型 AC 适用）

> **只写通过线/证伪线不够。** 5 人样本最常见的落点是中间带（3/5、40–70% 等），必须预先写「中间带怎么判」。

| 情况 | 判定 | 动作 |
|---|---|---|
| 达到通过线 | 支持该 AC 标注的假设 | 记录证据 |
| 落在中间带 | **不判，不写成支持或反驳** | 先检查是否被理解/呈现/样本问题拖累；再加样本或改设计；不得事后调整阈值 |
| 达到证伪线 | 反驳该 AC 标注的假设 | 记录证据，触发对应回退 |
| 样本/效度不足 | 不判 | 记为「需要更多数据」，与中间带分开 |

**灰区不是「需要更多数据」的同义词**：灰区是结果落在两条线之间；「需要更多数据」是样本不足/效度失败/理解失败。两者必须分开记录。

**判定顺序（证伪优先）**：任何一条证伪条件成立 → 判证伪；所有通过条件成立 → 判通过；其余 → 灰区。这条规则优先于表中的单一计数分区；正文的证伪条件不能被表覆盖。**表中的「灰区 N=k」仅当剩余的人不属于证伪类型（没注意/说不清）时成立；否则按证伪优先判证伪。**

**具体灰区**（N = 满足该 AC 正向条件的人数）：

| AC | 通过 | 灰区（不判） | 证伪 |
|---|---|---|---|
| AC1.1 | ≤30 秒 | 30–60 秒 | >60 秒或 ≥2 人问「点哪里」 |
| AC1.2 | N ≥4/5 | N = 3/5 | N ≤2/5 |
| AC1.3 | N ≥4/5 | N = 3/5 | N ≤2/5（无法解释，或理解为「落后/不够好」） |
| AC1.4 | N ≥3/4（访谈：非完整档算完成；分母 = 用过非完整档的 ≥4 人） | N = 2/4 | N ≤1/4；或 ≥2 人说「像在骗自己」 |
| AC1.5 | 完成率 ≥70% | 40–70% | <40% |
| AC2.1 | N ≥4/5 | N = 3/5 | N ≤2/5；或 ≥1 人看到失败/归零警报 |
| AC2.2 | N ≥4/5（正常完成、不觉补偿、旧记录可见） | N = 3/5 | N ≤2/5；或旧记录不可见 |
| AC2.4 | ≥40% | 20–40% | <20% |
| AC3.1 | N ≥4/5（10 秒内完成/跳过）且 ≥3 人 7 天 ≥2 次 | N = 3/5，或仅 2 人 ≥2 次 | N ≤2/5；或跳过率 ≥70% |
| AC4.1 | N ≥4/5 | N = 3/5 | N ≤2/5 |
| AC4.2 | N ≥3/5（有意义） | N = 2/5 | N ≤1/5 |
| AC4.3 | N ≥4/5 | N = 3/5 | N ≤2/5 |
| AC5.1 | N ≥4/5（且 5/5 无失败语义） | N = 3/5 | N ≤2/5；或 ≥1 人看到失败语义 / ≥2 人说内疚 |
| AC5.2 | N ≥4/5 | N = 3/5 | N ≤2/5 |

**比较性假设的额外规则**：A2「平等不降低动机」、A5「中性态提高回归率」都是比较命题，单臂绝对阈值不能检验。本包只检验它们的**设计前提**（用户是否把非完整档当完成、是否理解中性态并愿意回来）；比较命题需要 A/B 或基线，本轮不检验，见 §9.5。
> 5 人原型测试或试点中，用「可观察的行为/访谈原话」判断，不用「体验流畅」这类形容词。

### R01 · 今天的记录闭环（三档完成度 + 阶段感知）

**需求陈述**：用户在一次日常情境中打开后，能在 3 次点击内完成当天的一次记录；完整/简化/微型三档都算完成，且没有任何一档被呈现为「正确/推荐/高级」；用户能看到与当前阶段对应的进度说法，并能用自己的话解释它；同一天同一习惯只保留 1 次有效记录。

- **Job Story**：JS1
- **服务赌注**：B1；A1（点击预算）、A2（三档平等）、A4（阶段标签可理解）
- **证据**：E02 ⚠️（降低门槛）、E07 ⚠️（三级阶梯，设计约定）、E08 ⚠️（阶段标签 + 三档平等，设计假设）；A1/A2/A4 🔮。E01 只支持「锚点存在」，不直接支持点击预算或三档平等，不挂在本条。
- **如果不做**：B1 的「三级完成度视觉平等 + 阶段感知」没有可观察载体；A1/A2/A4 无法验证；14 天回访率的变化无法归因于反馈设计。

#### AC1.1 · A1（点击预算）

- **Given** 用户已有 1 个习惯，今天尚未记录，手机在单手可及处
- **When** 从打开 app 到看到「今天已完成」的状态
- **Then** 全程 ≤3 次点击、≤30 秒，且不需要阅读说明
- **通过线**：5 人里 ≥4 人在 30 秒内完成，且没有人问「点哪里」
- **证伪线**：5 人里 ≥2 人问「点哪里」或 >60 秒
- **需要更多数据**：≥2 人说不清三档区别 → 先修标签，不能判 AC1.1（这不是点击问题）
- **备注**：不含可跳过的体感步骤；是否计入见 C3。

#### AC1.2 · A2（三档平等感知）

- **Given** 用户刚用任意一档完成今天的记录
- **When** 被问「哪一档才算真正完成了今天」
- **Then** ≥4/5 说三档都算，或无法指出一个「正确档」
- **通过线**：≥4/5 说三档都算 / 没有正确档
- **证伪线**：≥2/5 指出某一档才是「真的」，或说用微型档「像在骗自己」
- **需要更多数据**：用户说不出区别但也不认为有高低 → 不能判平等感知，改测命名/呈现
- **备注**：本 AC 不测默认档；默认档见 C1。

#### AC1.3 · A4（阶段标签可理解）

- **Given** 今天的记录上下文显示用户当前阶段的进度说法
- **When** 展示 5 秒后，请用户用自己的话解释「我现在在积累什么」
- **Then** ≥4/5 能用自己的话解释，且不把它理解为等级、批评或「你还不够好」
- **通过线**：≥4/5 解释正确且中性
- **证伪线**：≥2/5 无法解释，或 ≥2/5 理解为「我落后了 / 我不够好」
- **中间带（N=3/5）**：不判 A4；先检查标签用词与呈现，再决定加样本或改成更具体的行为描述
- **需要更多数据**：用户能解释但不喜欢这个说法 → A4 通过，文案问题交给 UI / 后续迭代
- **判定口径**：「中性」= 不理解为等级/批评/「我不够好」；只是不喜欢用词，不算 A4 失败。

#### AC1.4 · A2（试点：设计前提，不是比较命题）

- **Given** 5 人试点完成 7 天，三档在呈现上平等，且至少 4 人使用过非完整档
- **When** 访谈使用过非完整档的用户（分母 = 至少 4 人，不是全体 5 人）
- **Then** ≥3/4 说「那也算完成了今天，不觉得在骗自己」
- **通过线**：N ≥3/4 说非完整档算完成
- **证伪线**：N ≤1/4，或 ≥2 人说「用微型/简化档像在骗自己」
- **中间带（N=2/4）**：不判 A2；先检查用户是否理解三档（AC1.3），再决定加样本或改命名/呈现
- **需要更多数据**：使用非完整档的用户 <4 人 → 样本不足，不能判 A2
- **备注**：本 AC 只检验 A2 的**设计前提**（用户是否把非完整档当完成）；A2 的**比较命题**（平等不降低动机）本轮不检验——单臂绝对阈值不能证明「不降低」，需要 A/B 或基线，5 人下不可行，见 §9.5。完成率是产品级信号，见 AC1.5，不作为本 AC 的通过条件。

#### AC1.5 · 产品级信号（不是 A2 的 AC）

- **Given** 5 人试点完成 7 天，三档在呈现上平等
- **When** 统计每日完成率
- **Then** 每日打卡完成率 ≥70%
- **通过线**：≥70%
- **证伪线**：<40%（bet-book 的 kill 阈值）
- **中间带（40–70%）**：不判；先检查点击/理解问题（AC1.1/AC1.3），再决定加样本或改设计
- **备注**：这是 B1 的产品级成功信号，不是 A2 的比较证据；不能把完成率变化归因于三级平等。

**本需求的边界**：空（首次使用/当天首次）、错（保存失败）、极端（同日重复记录、3 个习惯）、成长（阶段变化）。

**待决策**：C1（默认档）、C3（体感是否计入 3 次点击）、OQ1（平等的具体维度）、OQ5（多习惯今天屏，影响点击分母）。

### R02 · 中断后的中性回归态

**需求陈述**：当用户有 ≥1 天没有记录后打开 app，首先看到的是中性状态：不出现失败/危险/归零的警报语义，不显示累积中断天数，不要求补卡或从头开始；三个档位都可到达并可用于今天的记录；中断提示不追着用户重复出现；中断前的记录仍然存在。

- **Job Story**：JS2
- **服务赌注**：B1；A5（中断不渲染焦虑会提高回归率，而不是放任）
- **证据**：E08 ⚠️（中断消息只在中断日出现、不渲染焦虑）、E10 🔮（连续天数/失败警报可能制造羞耻，设计推断）；A5 🔮
- **如果不做**：A5 无法验证；用户中断后只能面对失败信号；B1 与普通打卡产品没有可观察差异；48h 回归率无法解释。

#### AC2.1 · A5（不羞辱感知）

- **Given** 用户昨天没有记录
- **When** 今天首次打开
- **Then** 首先看到的内容不出现失败/危险/归零的警报语义，不出现「失败 / 断了 / 又没做 / 归零」语义，不显示被清零的连续计数；用户能用一个动作开始今天的记录
- **通过线**：≥4/5 无上述元素且能立即说出「今天可以继续」
- **证伪线**：≥1 人看到失败/危险/归零警报，或 ≥2/5 说「我觉得被指责了」
- **中间带（N=3/5）**：不判 A5；先检查中断是否被感知、文案是否被理解，再决定加样本或改设计
- **需要更多数据**：用户没注意到中断 → 不能判「不焦虑」，先确认中断是否被感知

#### AC2.2 · A5（回归被正常接纳）

- **Given** 用户中断 1–2 天后打开
- **When** 完成今天的记录
- **Then** 这次记录被当作当天正常记录，不要求补卡、不要求「从头开始」，中断前的记录仍可见
- **通过线**：N ≥4/5 正常完成、不觉得需要补偿，且旧记录可见
- **证伪线**：N ≤2/5，或旧记录不可见
- **中间带（N=3/5）**：不判 A5；先检查用户是否理解「中断不是失败」，再决定加样本或改文案
- **需要更多数据**：用户只完成记录但不打开回顾 → 旧记录可见性无法判，补一个任务

#### AC2.3 · A5（中断态不累积）

- **Given** 用户中断后第 2 天仍未记录
- **When** 再次打开
- **Then** 首先看到的内容仍不出现累积指责 / 中断天数 / 「你已经几天没做」，也不出现新的催促；用户仍能直接记录今天
- **通过线**：5/5 无累积指责
- **证伪线**：≥1 人看到中断天数/累积催促，或 ≥2/5 说「被追着」
- **需要更多数据**：用户没有再次打开 → 无法观察，记录为流失，不做 AC 判断

#### AC2.4 · A5（试点：设计前提，不是比较命题）

- **Given** 试点用户中出现 ≥1 天中断
- **When** 中断后 48 小时内
- **Then** ≥40% 的中断用户完成一次新记录
- **通过线**：≥40%
- **证伪线**：<20%（**本轮试点的描述性阈值**；不是 bet-book 的 14 天回访 kill 信号）
- **中间带（20–40%）**：不判 A5；先检查中断态是否被看到、是否被理解，再决定加样本或改设计
- **需要更多数据**：中断事件 <5 次 / 中断用户 <3 人 → 样本不足，不能判
- **备注**：本 AC 只检验 A5 的**设计前提**（中性中断态是否被理解、是否愿意回来）；A5 的**比较命题**（中性态提高回归率）本轮不检验——单臂绝对阈值不能证明「提高」，需要对照/基线。前提是 C4 决策为「本轮无提醒」；若有中性提醒，此 AC 测的是「中性中断态 + 提醒」的组合效果，不能单独归因 A5。

**本需求的边界**：离开-回来（主场景）、空（昨天没有记录）、极端（30 天中断后回来）、放弃（暂停路径）。

**待决策**：C1（中断态默认预选微型 vs 三档平等）、C4（提醒 vs 48h 回归率）、C5（连续天数/累计计数）。

### R03 · 完成后的体感记录（可跳过）

**需求陈述**：用户在完成记录后，能用一次轻量动作留下一个身体感受词/短句，或用一次明确动作跳过；跳过不产生失败态、不重复追问、不影响当天记录的有效性；不出现评分、等级、健康评价；体感记录不是完成打卡的前置条件。

- **Job Story**：JS3
- **服务赌注**：B1；A3（体感高光回顾对用户有意义）
- **证据**：E04 ⚠️（体感是内在奖励）、E09 ⚠️（体感记忆系统，设计假设）；A3 ⚠️；kill signal「体感记录被跳过 ≥70% → 体感日志降为可选」
- **如果不做**：B1 的「体感高光回顾」没有原料；A3 无法验证；回顾只能显示数字，产品退回普通打卡。

#### AC3.1 · A3 前置（采用 / 负担；meaningfulness 由 AC4.2 测）

- **Given** 用户刚完成一次记录
- **When** 完成态出现
- **Then** 用户能在 10 秒内留下一个体感词/短句，或用一次明确动作跳过；不需要阅读说明
- **通过线**：N ≥4/5 能在 10 秒内完成或跳过；7 天试点里 ≥3 人至少留下 2 次体感记录
- **证伪线**：N ≤2/5，或 ≥2/5 说「像作业 / 想不出词」，或试点期跳过率 ≥70%（触发 kill signal）
- **中间带（N=3/5，或仅 2 人留下 ≥2 次）**：不判 A3 前置；先检查体感提示的长度/位置、是否被理解，再决定加样本或精简
- **需要更多数据**：用户能留但从不回看 → 不判 A3，转到 AC4.2
- **备注**：本 AC 只测「采用 / 负担」（用户能不能、愿不愿意留一个词）；A3 的「体感高光对用户有意义」由 AC4.2 测，不由本条代替。

#### AC3.2 · A5 / 边界（跳过不被惩罚）

- **Given** 用户选择跳过体感
- **When** 回到今天的记录
- **Then** 当天记录仍显示为已完成，不出现「未完成 / 待补充」标记，也不再次追问
- **通过线**：5/5 无惩罚提示
- **证伪线**：≥1 人看到待补充标记或再次被追问
- **需要更多数据**：用户跳过但之后主动回来补 → 说明有需求，不能判「跳过无价值」

**本需求的边界**：空（没什么感觉 / 不想说）、错（文本保存失败）、放弃（跳过）。

**待决策**：C3（体感是否计入 3 次点击）、OQ4（微型档是否精简体感步骤）。

### R04 · 一周回顾：走了多远 + 体感高光

**需求陈述**：用户在一周回顾中能看到自己实际记录的情况（具体计数语义待 C2 决策）和至少一条自己留下的体感内容；回顾不出现他人比较、失败/归零警报、「还差 N 天」的压力框架；数据量增长时，首先看到的仍是有限摘要，不是流水账。

- **Job Story**：JS4
- **服务赌注**：B1；A3（体感高光回顾）
- **证据**：E03 ⚠️（意义重构）、E04 ⚠️（体感）、E09 ⚠️（体感高光）；A3 ⚠️。E05/E06 是身份阶段与阶段演化，不直接支持回顾页，不挂在本条。
- **如果不做**：B1 的「把注意力放回身体已经体验过的好处」没有载体；A3 无法判断；用户只能看到记录，看不到意义；回顾只剩数字，和普通打卡产品无差异。

#### AC4.1 · B1（回顾可读性；计数语义见 C2）

- **Given** 用户本周有 ≥3 天记录（原型用种子数据）
- **When** 打开一周回顾
- **Then** 能在 10 秒内正确说出「本周记录了几次/几天」以及这个数字的含义，不把有缺口的周理解为失败
- **通过线**：≥4/5 正确读出数字并说出含义
- **证伪线**：≥2/5 读错，或把数字解释为「我很差 / 我又失败了」
- **需要更多数据**：用户看到数字但说不出含义 → 不是计数语义问题，是呈现问题；先修呈现再判 C2
- **备注**：本 AC 不测「记录次数 vs 完整次数」，见 C2；决策后补 AC4.4。

#### AC4.2 · A3（体感高光有意义）

- **Given** 用户有 ≥2 条**自己**在 7 天试点里留下的体感记录（**不用种子数据**；种子数据测不出「我的身体记得」）
- **When** 打开一周回顾
- **Then** 能看到至少一条自己写过的体感内容，并能指出一个具体的身体变化或时刻
- **通过线**：N ≥3/5 能指出具体内容，并说它对自己有意义
- **证伪线**：N ≤1/5（≥4/5 忽略高光或说「没什么感觉」）→ A3 不成立，体感高光降为可选（kill signal）
- **中间带（N=2/5）**：不判 A3；先检查高光是否被看到、是否与用户原话一致，再决定加样本或改呈现
- **需要更多数据**：用户自己的体感记录 <2 条 → 样本不足，先补 R03；**不得用种子数据代替**

#### AC4.3 · B1（无压力框架）

- **Given** 用户本周有 2 天没有记录（原型用种子数据）
- **When** 打开一周回顾
- **Then** 不出现失败/危险/归零警报，不出现「漏了 2 天 / 你落后了 / 还差 N 天」语义，不出现他人比较
- **通过线**：≥4/5 说「没有被评判」
- **证伪线**：≥2/5 感到被指责或被比较
- **需要更多数据**：用户没注意到缺口 → 不能判「无压力」，先确认缺口是否被感知

**本需求的边界**：空（没有任何记录）、成长（阶段变化改变回顾重点）、极端（90 天 × 3 个习惯）。

**待决策**：C2（记录次数 vs 完整次数）、C5（巩固期连续天数 vs Anti-goal）。

### R05 · 暂停与回归：允许停，不抹掉记录

**需求陈述**：用户能暂停一个习惯；暂停后该习惯不在今天的记录中出现；已有记录保留，并在回顾中可见；暂停不被标记为失败/中断/归零；用户能恢复该习惯并从已有记录继续，不被要求重新开始；暂停/恢复不产生羞辱性语义。

- **Job Story**：JS5
- **服务赌注**：B1（不制造羞耻）；Anti-goal（不做连续天数归零/失败文案）；OQ7（暂停/放弃是否需要）
- **证据**：E10 🔮（游戏化机制可能制造羞耻，间接推断）；OQ7 未决；没有直接用户证据 → 整条标 🔮
- **如果不做**：用户可能只能通过删除退出，删除会抹掉记录，直接违反「不制造羞耻」；边界「放弃」没有出口；14 天回访率可能被「想停但不能停」的用户污染。

#### AC5.1 · B1 / Anti-goal（暂停不是失败）

- **Given** 用户有一个已有 ≥5 条记录的习惯
- **When** 选择暂停
- **Then** 该习惯不再出现在今天的记录中，且不出现失败/危险/归零/「你放弃了」语义
- **通过线**：5/5 无失败语义；≥4/5 访谈说暂停「是被允许的」，而不是「我失败了」
- **证伪线**：≥2/5 说感到内疚/失败
- **中间带（N=3/5）**：不判 B1；先检查暂停入口是否被找到、文案是否被理解，再决定加样本或改文案
- **需要更多数据**：用户找不到暂停的方式 → 不是暂停语义问题，是可用性问题；先修路径再判

#### AC5.2 · B1（恢复保留历史）

- **Given** 一个已暂停 ≥7 天的习惯（原型用种子数据）
- **When** 用户恢复它
- **Then** 暂停前的记录仍能在回顾中看到，习惯回到今天的记录，且不出现「从零开始 / 重新计数」提示
- **通过线**：≥4/5 能看到旧记录，并说「我的进度还在」
- **证伪线**：≥2/5 认为记录丢了，或必须重新开始
- **需要更多数据**：试点内无人恢复 → 不能判，延长观察或做原型任务

**本需求的边界**：放弃（主场景）、离开-回来（恢复）、成长（不同阶段暂停）。

**待决策**：C5（如果存在连续天数，暂停可能把它归零）；OQ7（Definer 确认暂停是否在范围内）。

## 4. 边界条件

> 边界不是附录，是需求的一部分。每条 P0 至少覆盖「空 / 错 / 离开-回来」中的两个；不覆盖的写明「为什么这轮不测」。

### 4.1 空（第一次使用 / 无数据）

- **具体情境**：第一次打开，0 个习惯、0 条记录；回顾没有任何数据；从未记录过体感。
- **需求应该做什么**：提供预置习惯前的空状态引导（习惯创建的完整流程由研究者在试点前预置，不在本轮 AC）；回顾在没有记录时说明「第一条记录后这里会出现什么」，不显示 0% 完成率/空图表/空体感评价；不把「没有数据」说成「你还没开始」。
- **对应**：R01 前置；R04 空状态。
- **边界验收**：Given 新用户首次打开，When 看完首先出现的内容，Then ≥4/5 能说出下一步（确认预置习惯 / 开始第一天），且不出现「暂无数据」；证伪线：≥2/5 不知道下一步。
- **不覆盖会怎样**：用户在 B1 生效前就在空状态流失；AC1.1 的点击预算也无法测。

### 4.2 错（网络断 / 保存失败 / 数据异常）

- **具体情境**：本地保存失败、存储满、app 被杀死、记录写入中断；回顾数据读取失败或数据不完整；暂停操作保存失败。
- **需求应该做什么**：记录不丢；明确告诉用户「这次记录还在本机，没有丢」；可重试或稍后；失败不产生「未完成」状态；不重复计数；体感文本在失败后仍保留；回顾读取失败时不显示 0% 或空白失败态，明确告知数据还在、可重试；暂停保存失败时习惯状态不变，不产生半暂停状态。
- **对应**：R01、R03、R04（回顾数据读取失败）、R05（暂停保存失败）。
- **边界验收**：Given 模拟保存失败，When 用户完成打卡/体感，Then 5/5 能看到「没有丢」+ 可重试，且恢复后只有 1 条记录；证伪线：≥1 人认为记录丢了，或看到重复记录。
- **回顾补充验收**：Given 回顾数据读取失败，When 用户打开一周回顾，Then 5/5 看到「数据还在本机 / 可重试」，不出现 0% 或空白失败态；证伪线：≥1 人认为记录丢了。
- **暂停补充验收**：Given 暂停操作保存失败，When 用户尝试暂停一个习惯，Then 5/5 看到「没有停成功 / 可重试」，习惯状态不变，不出现半暂停或记录丢失；证伪线：≥1 人认为习惯已暂停但实际未保存，或记录丢失。
- **不覆盖会怎样**：数据丢失会直接制造焦虑，和 B1 的核心相反；「一次中断就放弃」的机制会被技术错误放大。

### 4.3 离开-回来（中断后重新开始）

- **具体情境**：中断 1 天、7 天、30 天后打开；中途离开未完成记录。
- **需求应该做什么**：中断 ≥1 天 → R02 的中性状态；不累积中断天数、不要求补卡、不从头开始；中断前记录仍可见；中途离开未确认的记录不产生半完成状态，也不惩罚用户。
- **对应**：R02、R05。
- **边界验收**：Given 用户中断 7 天后打开，When 完成今天记录，Then 5/5 不看到累积指责/中断天数，且能正常记录；证伪线：≥1 人看到中断天数或「补卡」要求。
- **不覆盖会怎样**：回归是 B1 的核心场景；不覆盖等于没测 B1。

### 4.4 放弃（用户想停）

- **具体情境**：想暂停一个习惯；想删除；不想记录体感。
- **需求应该做什么**：暂停是一等选项（R05）；删除需明确确认，且不渲染失败；体感可跳过且不追问（R03）；暂停/删除不产生失败警报、归零或「你放弃了」语义。
- **对应**：R03、R05。
- **边界验收**：Given 用户选择暂停，When 确认后，Then 5/5 不看到失败提示，≥4/5 访谈说「被允许」；证伪线：≥2/5 感到内疚/失败。
- **不覆盖会怎样**：没有暂停，用户可能只能删除；删除会抹掉记录，直接违反 no-shame。

### 4.5 成长（从新手到熟练）

- **具体情境**：从第 1 天到第 3 周、第 3 月；阶段说明变化；体感记录从少到多。
- **需求应该做什么**：阶段说明随实际使用事实变化，不是用户手动选择的等级；进入新阶段只改变「在积累什么」的说法，不制造「升级/降级」；回顾重点从锚点触发逐步转向体感积累，但不取消三档平等；不出现「你已连续 30 天，不能断」的压力框架。
- **对应**：R01（阶段说明）、R04（回顾重点）。
- **边界验收**：Given 用户使用 3 周后进入下一阶段，When 看到新的阶段说明，Then ≥4/5 能用自己的话解释「现在在积累什么」，且不理解为「我升级了 / 我必须保持」；证伪线：≥2/5 理解为等级或压力。
- **不覆盖会怎样**：阶段感知是 B1 的组成部分；不覆盖成长，A4 只测了第一天，没测阶段变化。

### 4.6 极端（超多数据 / 极端高频 / 超长文本）

- **具体情境**：3 个习惯 × 90 天 = 270 条记录；同一天重复打开/重复记录；体感文本很长（如 200 字）；连续 30 天无中断。
- **需求应该做什么**：回顾首先看到的仍是有限摘要（本周 + 一条高光），不变成流水账；同一天同一习惯只计 1 次；体感文本有长度上限或折叠，但不丢原文；连续 30 天不触发「不能断」的压力框架。
- **对应**：R01、R04。
- **边界验收**：Given 用户有 90 天、3 个习惯的记录，When 打开一周回顾，Then 首先看到的是本周摘要 + 至少一条体感高光，且 5/5 能在 10 秒内说出本周记录数；证伪线：需要滚动超过 2 屏才能找到本周数字，或 ≥2 人说不清。
- **不覆盖会怎样**：数据量增长会让回顾变成流水账，B1 的「意义」被淹没；重复计数会让 AC1.1 / AC4.1 的数字失真。

- **没有任何 ✅ 证据**：E01–E09 都是 ⚠️（三案例归纳或设计假设），E10 是 🔮；A1–A5 中 A3 是 ⚠️，其余是 🔮。

- **A2 的验证方法不匹配**：bet-book 写的是「A/B 对比（完整/简化/微型）」，但 5 人样本做 A/B 不可行；本包把 A2 的设计前提交给访谈（AC1.4），完成率是产品级信号（AC1.5），不归因于 A2（见 §9.5）。
- **R02 的 48h 回归率受 C4 影响**：没有提醒时，这个指标可能测不到设计效果；见 C4。
- **证据不能外推**：3 个个人案例不是大样本；本包的 AC 是「可以判断通过/不通过」，不是「已经证明」。

### 8.1 冲突汇总

| C1 | 中断态「默认预选微型」vs「三档视觉平等」 | A 不预选 / B 中断态预选+标注 / C 隐藏默认（不建议） | Product Definer | R02 的默认/顺序 |

### C1 · 中断态「默认预选微型」vs「三档视觉平等」

**冲突双方**：R02 的中断回归（降低门槛，让用户更容易开始） vs A2 / R01 的三档平等（不设默认推荐档）。来源：OQ2。

**为什么是真冲突**：如果中断后默认选中「微型」，这个默认值本身就是一种推荐——它告诉用户「今天你只该做微型」。这与「三档视觉平等」直接矛盾；如果用户感知到被降级，还可能产生新的羞耻。反过来，不预选会让用户在最低落、最不想做选择的时刻多做一个选择，可能降低回归率（A5）。

**选项**：
- **A（不预选）**：中断态只做中性说明，三档平等呈现，用户自己选。优点：与 A2 一致，A5 的测试干净。代价：回归那一刻的选择负担最高。
- **B（只在中断态预选微型，并明确标注「这是建议，不是唯一选择」）**：优点：降低门槛，可能提高回归。代价：A2 的「平等」要改写成「除中断态外」；A2 和 A5 在同一轮里无法独立验证。
- **C（不预选，但把微型放在第一个位置）**：这是隐藏的默认，仍然有推荐效果，不建议作为「平等」的实现。

**建议（非约束）**：如果本轮首要验证目标是 A2（三级平等），选 A；如果首要目标是 A5（回归率），选 B，并在分析时把 A2 的解释范围限定为「非中断态」。这个优先级是 Definer 的赌注取舍，不是需求分析师能定的。

**需要谁决策**：Product Definer（A2 vs A5 的优先级）。Prototype/UI 在决策后实现。

**决策前 AC 怎么处理**：R02 的 AC2.1–AC2.3 只断言「三档都可到达、无失败语义、不累积指责」，不断言默认状态或顺序。决策后补 AC2.5，专门测默认/顺序是否被感知为推荐。

### C2 · 回顾计数语义：「记录次数」vs「完整次数」

**冲突双方**：R04 需要一个可读的数字；B1/A2 说三档都算完成；E08 的巩固期说法「自然连续天数」暗示按完整天计数。来源：OQ3。

**为什么是真冲突**：
- 只算完整次数：微型/简化记录变成二等，直接违反 R01 的三档平等和 B1 的「微小行动也算」。
- 全部记录都算：与「三档平等」一致，但用户在巩固期可能觉得数字不反映「真正的进步」；E08 的「自然连续天数」又暗示另一种语义。
- 阶段化计数：启动/形成算记录，巩固算完整——语义随阶段变化，A4 的理解负担增加，且微型日可能被悄悄打折。

**选项**：
- **A（记录次数，三档等权）**：回顾显示「本周记录了 N 天/次」，不区分完整/微型。与 B1 / E02 / E07 一致，最简单。
- **B（双数字）**：显示「记录 N 天 / 其中完整 M 天」。信息更全，但重新引入高低 hierarchy，可能制造「我不够完整」的羞耻。
- **C（阶段化）**：启动/形成按记录次数，巩固按完整次数。贴近 E08 的说法，但同一动作在不同阶段意义不同，A4 更难，且微型日被折扣。

**建议（非约束）**：A 与 B1 的机制最一致（「今天这个微小行动」+「退行被允许」）。如果 Definer 选 A，R04 的计数表述固定为「记录天数/次数」，不再出现完整/微型的拆分；如果选 B/C，需要重写 AC4.1 和 AC4.4。

**需要谁决策**：Product Definer。Validation 需要在试点前知道用哪个数字做分析。

**决策前 AC 怎么处理**：AC4.1 只测「用户能正确读出屏幕上的数字并说出含义」，不测数字代表哪种语义；C2 决策后补 AC4.4（计数语义理解 + 不产生二等感）。

### C3 · 体感步骤是否计入「3 次点击」/ 是否按档位精简

**冲突双方**：R01 的 A1（3 次点击） vs R03 的 A3（体感是每日核心仪式） vs OQ4（微型档是否精简）。来源：PRD J1「3 次点击内完成一次打卡，并留下一个体感词」。

**为什么是真冲突**：
- 如果体感在 3 次点击内：档位 → 确认 → 体感（或跳过）= 3 次，刚好；但跳过也必须是第 3 次点击，任何额外的「稍后再说」都会超预算。
- 如果体感在 3 次点击外：打卡本身 ≤3 次，但用户总动作是 4–5 次，PRD 的 J1 表述不成立。
- 如果微型档跳过体感：三档的仪式不再平等，A2 被污染；微型用户永远不积累体感记忆，A3 只对完整/简化用户成立。

**选项**：
- **A（体感计入 3 次点击，跳过是一等动作）**：J1 保持字面成立；体感是仪式的一部分。代价：用户可能习惯性跳过，A3 采用率下降。
- **B（3 次点击只算打卡，体感是完成后的独立可选步骤）**：保护 A1；体感更轻。代价：J1 的表述要改成「3 次点击打卡 + 可跳过体感」；体感采用率可能更低。
- **C（按档位精简：微型档跳过体感，完整/简化保留）**：符合「微型 = 最小」的逻辑。代价：三档不平等，A2 和 A3 的归因都变复杂。

**建议（非约束）**：B 最保护 A1（A1 是 🔮 致命假设，A3 只是 ⚠️）；但需要在试点里单独看体感采用率，避免 kill signal 被 B 的设计放大。A 更符合 PRD 原文的「每日核心仪式」。这是 A1 vs A3 的取舍，交给 Definer。

**需要谁决策**：Product Definer；Prototype/UI 在决策后定交互。

**决策前 AC 怎么处理**：AC1.1 只测「到打卡完成态」的点击，不把体感算进去；AC3.1 单独测体感步骤。决策后补 AC1.6（若体感计入，则总点击 ≤3）或 AC3.3（若体感独立，则总动作预算写清楚）。

### C4 · 「不打扰的中断设计」vs「48 小时回归率需要回归触发」

**冲突双方**：R02 的中性中断态（不提醒、不施压） vs B1 的成功信号「中断后 48 小时回归率 ≥40%」和 A5 的验证。来源：OQ6。

**为什么是真冲突**：中性中断态只有在用户再次打开 app 时才起作用。如果本轮没有任何提醒/回归触发，很多中断用户根本不会看到它；48 小时回归率会由「用户原本的打开习惯」决定，而不是由「不焦虑设计」决定。反过来，如果加提醒，回归率上升时无法区分是「中性状态」还是「被提醒」的效果，A5 的因果检验被污染。

**选项**：
- **A（本轮不加提醒）**：只测自发回归；48 小时回归率作为描述性指标，不作为 A5 的因果证据；预注册「本轮不能单独归因」。优点：A5 测试干净。代价：可能误杀 B1；样本小，回归用户可能 <5 人。
- **B（所有试点用户都加中性提醒：不含失败/指责语义、每天 ≤1 条、可关闭）**：把「中性中断态 + 中性提醒」作为一个组合包测试。优点：回归率可测，体验更接近真实产品。代价：A5 的纯效应无法分离；提醒本身可能被感知为压力。
- **C（两臂试点：无提醒 vs 中性提醒）**：能分离效果。优点：因果最干净。代价：5 人样本分两臂后严重不足；运营更重，本轮不现实。

**建议（非约束）**：本轮选 A + 预注册描述性解释；把 C 留给下一轮（更大样本）。如果 Definer 认为「没有提醒的试点不代表真实使用」，选 B，并把结论写成「组合包有效/无效」，不要写成「A5 被验证/证伪」。

**需要谁决策**：Product Definer + Validation Researcher。这是赌注级 + 验证设计级的联合决策。

**决策前 AC 怎么处理**：R02 不写任何提醒需求；AC2.4 的备注明确「无提醒前提」。C4 决策后，如果加提醒，补 AC2.6（提醒语义/频率/可关闭），并把 AC2.4 的解释改成组合效果。

### C5 · 巩固期「自然连续天数」vs Anti-goal「不做连续天数归零」

**冲突双方**：E08 的设计假设「巩固期说法 = 自然连续天数」 vs bet-book Anti-goal「不做会因一次中断而归零的连续天数机制」和 B1 的 no-shame 前提。来源：E08 / Anti-goals。

**为什么是真冲突**：「连续天数」这个说法天然暗示一次中断就归零；如果归零，它就是 B1 要移除的机制。如果不归零，它就不是用户理解的「连续天数」。E08 是 ⚠️ 设计假设，Anti-goal 是明确的产品判断；两者不能同时按字面实现。

**选项**：
- **A（不做任何归零计数）**：所有阶段都用累计「记录天数/次数」；阶段说法只改变「在积累什么」，不显示会归零的连续数。与 Anti-goal 一致。
- **B（显示连续，但永不归零）**：中断时显示「最长连续 N 天 / 累计 M 天」，不出现失败警报/归零。保留连续性的激励，但仍可能制造损失感。
- **C（只在巩固期允许归零连续）**：直接违反 Anti-goal，除非 Definer 明确改赌注；不建议。

**建议（非约束）**：A 最符合 B1；如果 Definer 想保留「连续」的激励，B 是折中，但要在 AC 里测「中断后用户是否感到损失/羞耻」。E08 的「自然连续天数」需要改写。

**需要谁决策**：Product Definer。

**决策前 AC 怎么处理**：R01/R04 不写任何连续天数/streak 的展示；AC1.3 的阶段说法用「在积累什么」的中性表述。决策后补 AC1.7 / AC4.5。

## 9. 交接

### 9.1 硬约束（不可调整，来自 B1 / Anti-goal）

1. 三档完成度在颜色、尺寸、位置、顺序、默认状态、命名上不得有高低暗示；具体维度和默认档见 C1 / OQ1。
2. 中断/回归不出现失败、危险、归零、指责性语义；不显示累积中断天数；不做「补卡」要求。
3. 体感记录不是打卡的前置条件；跳过不产生失败态、不追问。
4. 回顾不做他人比较、不做「还差 N 天」、不做失败警报；体感高光必须来自用户自己的记录。
5. 暂停是一等选项；暂停/恢复不抹掉记录、不要求从头开始。
6. 同一天同一习惯只计 1 次。
7. 不做社交 / 排行榜 / 健康评价 / 订阅 / 多用户。

> 上面第 1 条列的是「需要检查的感知维度」，不是视觉方案；具体形式由 UI 决定。需求只约束「不能有高低暗示」，不规定怎么做。

### 9.2 可调整（下游可决定，但不能违反硬约束）

- 三档的命名、顺序、呈现形式——在 C1 决策后。
- 回顾的具体可视化形式、计数表述——在 C2 决策后。
- 体感步骤的位置、长度、是否按档位精简——在 C3 决策后。
- 多习惯今天屏的组织方式——OQ5，Architect 决定，但必须保证单习惯也满足 AC1.1。
- 阶段说法的具体用词——A4 的 5 秒测试是硬 AC，用词可调。
- 空状态 / 错误状态的具体呈现。

### 9.3 给 Product Architect

- **必须覆盖的状态**：空、错、离开-回来（1/7/30 天）、放弃（暂停/删除/跳过体感）、成长（阶段变化）、极端（3 习惯 × 90 天、同日重复记录）。
- **必须解决的 IA 问题**：OQ5 多习惯今天屏如何组织，同时保证单习惯的 3 次点击预算；多习惯的分母要在 AC 里写清楚。
- **不要引入**：连续天数归零、失败警报、比较性数据、社交入口。
- **状态机提示**：中断态 → 常规态；暂停态 → 恢复态；体感跳过不是失败态；同日重复记录是幂等，不是新记录。

### 9.4 给 Prototype Designer / UI Designer

- 用 5 人原型测试逐条跑 AC1.1–AC5.2；必须覆盖六种边界，不只快乐路径。
- 三档平等要在 OQ1 的六个维度上逐项检查（颜色/尺寸/位置/顺序/默认/命名）；不要用颜色区分高低。
- 中断态和暂停态是必做状态，不是可选页；体感跳过是一等动作。
- 阶段说法用用户语言，不用内部术语；做 5 秒理解测试。
- **不要抢跑冲突决策**：C1–C5 未决前，不要把默认档、计数语义、体感步骤位置、提醒、连续天数写死进原型。

### 9.5 给 Validation Researcher

- **可测的 AC**：AC1.1–AC5.2，每条有通过/灰区/证伪/需要更多数据四态（见 §3.0）。
- **样本边界**：5 人只做方向性判断，不做统计显著性；A2 原本的 A/B 在 5 人下不可行，建议 within-subject 7 天 + 访谈，或把 A2 降级为定性 + 行为描述。
- **A2/A5 的比较命题本轮不检验**：AC1.4 / AC2.4 只检验设计前提（用户是否把非完整档当完成、是否理解中性态），不检验「平等不降低动机」「中性态提高回归率」这两个比较命题；后者需要 A/B 或基线。§3 的 AC 标题已标「设计前提，不是比较命题」，与本节对齐。
- **四个成功信号**：14 天回访率、打卡完成率、「没有被评判」、48h 回归率；kill 信号见 bet-book。
- **C4 的解释**：本轮不把提醒写进需求；48h 回归率的报告必须写明「是否有中性提醒」；如果没有提醒，把 40% 当作下限，不作为 A5 的因果证据。
- **体感**：跳过率 ≥70% 触发 kill signal；「记录了但从不回看」不等于 A3 成立，必须看 AC4.2。
- **访谈**：「没有被评判」用具体事件问（「昨天没记录，今天打开时你看到了什么/感觉如何」），不用抽象量表；避免引导性问题。
- **不可测的部分**：习惯创建的完整流程、多设备、无障碍、多人共用——见 §4.8，本轮不做 AC。§4.1 的空状态验收只测「预置前空状态是否给出下一步」，不测创建流程本身。

### 9.6 向 Product Definer 反哺

**需要决策（按优先级）**：
1. **C1**：中断态「默认预选微型」vs「三档视觉平等」——A2 与 A5 的优先级。
2. **C2**：回顾计数语义「记录次数」vs「完整次数」——B1 的「微行动也算」与 E08 的「自然连续天数」冲突。
3. **C3**：体感步骤是否计入「3 次点击」/ 是否按档位精简——A1 与 A3 的优先级。
4. **C4**：「不打扰」vs「48h 回归率需要回归触发」——这可能在 5 人样本里让 A5 不可测。
5. **C5**：巩固期「自然连续天数」vs Anti-goal「不做连续天数归零」。
