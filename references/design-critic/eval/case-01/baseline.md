# Baseline · Design Critic Eval Case 01（个人习惯工具 UI）

> 一个**没有能力包**的通用 Agent 通常会产出什么评审。评分时先读这个。

## 典型产出

1. **范围模糊**：不写评什么/不评什么；直接把所有页面看一遍。
2. **意图对齐缺失**：不读 bet/IA/requirements，只看截图。
3. **主观评价**：「整体设计简洁、温暖，配色和谐，视觉层级清晰。」
4. **没有证据**：「空状态可以更好」「按钮可以更醒目」，不指页面/组件/状态。
5. **给方案**：「建议加一个插画」「把主色改成橙色」「用 Inter 字体」。
6. **全绿或全红**：所有问题都是「建议」，或所有问题都是「必须改」。
7. **只评快乐路径**：不看空/错/加载/中断/极端。
8. **越界评上游**：「这个产品方向可能不对」，没有用户证据。
9. **把「无法判断」写成「没问题」**：动效、字体回退、审美都敢下结论。
10. **总判断模糊**：「整体不错，建议继续优化。」

## 它缺什么

- 没有范围锁定与保真度匹配。
- 没有意图对齐；评审与赌注/IA/AC 脱节。
- 没有可定位的证据；无法复现/验证修复。
- 没有严重度校准；下游无法排优先级。
- 给方案、越界、审美裁判。
- 覆盖检查缺失；只评快乐路径。
- 没有路由；问题留在原地。
- 没有明确的 go / 有保留 / no-go。

## 评分提示

如果产出和 baseline 的差别只有「语气更专业、格式更整齐」，但缺少证据、严重度、覆盖、路由或明确判断，以上缺项仍在 → 能力包没有生效。
