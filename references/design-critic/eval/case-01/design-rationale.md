# 设计理由 · 个人习惯工具 v0.1

> 一句话方向：**像一本每天只翻一页的纸书——环是书签，苔绿是墨水，完成是合上书的那一下。**
> 置信度标记：✅ 有上游证据 / ⚠️ 从场景推断 / 🔮 设计直觉或待验证。
> 本文只讨论「为什么这样设计」，不重复 `design-system.md` 的令牌表与 `ui-spec.md` 的状态表。

## 1. 关键决策

| # | 决策 | 为什么 | 追到哪 | 置信度 |
|---|---|---|---|---|
| D1 | **今天屏用「一个主角环卡 + 0–2 条支持行」，不用 2 列等权网格** | 产品只服务 1–3 个习惯。Streaks 的 2 列网格服务 6+ 习惯；照搬到 1–3 个习惯，会把「今天唯一重要的事」稀释成模板网格。主角 = 当前最该做的那件；支持行 = 其余，不抢注意力 | PRD 范围「1–3 个习惯」；IA「今天优先」；参考板 Streaks 的失效场景 | ✅ 范围；⚠️ 构图 |
| D2 | **今日环编码「今天完成几件」（1/3），不编码连续天数** | 连续天数的语义是一次中断就归零——直接违反 B1 与 anti-goal。按天重置、不惩罚；昨天的记录留在周条和回顾里，不作为今天的负债 | B1；bet-book Anti-goals；E10 | ✅ 硬约束 |
| D3 | **默认预选「简化」，不是「完整」** | 目标是让今天的行动发生。默认值是最强的隐性推荐；把「完整」设为默认，等于每天先要求一个高门槛。「简化」是可持续版本，「完整」仍然一等公民 | E02 降门槛；PRD J1；MVP 三级阶梯 | ⚠️ 方向有支持；🔮 具体默认值待 A/B |
| D4 | **三级版本次等宽、等高、同字号，只有选中态（底 + 边 + 对勾）** | 视觉平等是硬要求。任何「完整更大/更亮」都会把「微型」变成偷懒选项，破坏 B1。对勾是形状编码，不是颜色编码 | brief 硬规则；A2；E08 | ✅ 硬约束；⚠️ 位置偏差未消除 |
| D5 | **「完整在左」的位置偏差没有消除，显式标为待验证** | 三等分仍然让最左的「完整」获得阅读优先。真正的消除需要随机顺序，但那会破坏肌肉记忆和可预期性。这是一个诚实的取舍，不假装解决 | A2 / V1；人眼检查点 | ⚠️ 已知偏差 |
| D6 | **微型完成 = 迷你环满格 + 对勾 + 「今天 · 微型」** | 完成度不靠环的填充比例区分；做微型和做完整在「今天」的视觉结果相同。这比一句「也算数」更有说服力 | E07；E08；brief「三级视觉平等」 | ✅ 硬约束 |
| D7 | **中断零红色：空心发丝点、中性 banner、微型预选、内联「补记昨天」** | 红色 + 「中断 N 天」会把一次遗漏变成失败。文案说「昨天没有记录」，不说「你中断了」；说「今天从微型版开始」，不说「重新开始」 | B1；Anti-goals；IA J2 | ✅ 硬约束；⚠️ 可能被读成放任（A5） |
| D8 | **回顾大数字用完成率 81%，并把「回来 2 次」当成正面统计** | 用户需要看到「我走了多远」，但荣誉不能建立在「没断」上。完成率、体感词数、回归次数都是累积的、不会归零的 | B1；E04/E09；IA J3 | ✅ 方向；⚠️ 指标选择 |
| D9 | **回顾用 14 日面积 + 折线为主图，7 日小柱为次级；不画 y 轴网格** | 一屏最多一个主图。直接标注端点（11.04 / 11.10 / 今天）比坐标轴更快读；0 值用基线而不是红色缺口 | 参考板 Streaks 统计三段式；方法库「直接标注、不要图表垃圾」 | ✅ 参考结构；⚠️ 图表类型 |
| D10 | **习惯详情大数字用「21 次」，不用「28 天」** | 大数字 + 「天」是 streak 的视觉语法，哪怕语义上是「记录天数」。累计次数不归零、不暗示连续；28 天放在副信息里，作为上下文 | B1 / E10；anti-goal | ✅ 避免语义误读；⚠️ 21 次是否够有力量 |
| D11 | **serif（宋体）只给习惯名、屏标题、体感引语；正文全无衬线；字重上限 600** | 温度来自书写感，不来自圆角或渐变。宋体在中文里是「书/纸」的联想，正好服务「每天翻一页」；全站用会变成文艺海报，所以只给 3 个角色 | 参考板 Craft 的 serif 角色；方法库「serif 是温度，不是装饰」 | ⚠️ 设计判断；🔮 字体回退待真机 |
| D12 | **暖纸白 + 暖石墨 + 深苔绿；强调色只做数据、完成与主行动** | 用户对打卡有抵触；界面要像纸，不像计分板。苔绿=生长，但压到深色，避免「健康/医疗」的薄荷绿。强调色预算：环、对勾、图表、热力图、主按钮；chrome 全中性；tab 激活点只做一处标点。这样苔绿出现多次，但每次都在表达同一件事——进度/完成 | PRD §2 用户；参考板 Things 3 的中性纪律；方法库强调色配给 | ⚠️ 温度推断；🔮 色相 |
| D13 | **发丝线 + 只有主角卡有柔影；行、统计卡、图表卡零阴影** | 高程是层级工具，不是装饰。所有卡都浮起来 = 没有东西突出。Things 3 的列表靠发丝线和留白分组，Apple 的卡只在需要时抬升 | 参考板 Things 3；方法库高程机制 | ✅ 参考结构；⚠️ 具体参数 |
| D14 | **用户界面不出现「打卡」，用「记下 / 记录」** | 「打卡」自带考勤与考核语义。同一件事换一个词，能把关系从「向上级交差」改成「给自己留一笔」 | PRD 用户抵触；B1 语气 | ⚠️ 文案判断；🔮 需 5 人读测 |
| D15 | **空状态是一枚种子弧 + 一个动作 + 三个小到不可能的模板** | 第一次打开是最低成本的教学位置。「暂无数据」浪费它；营销 hero 又过度承诺。种子弧把「还没开始」画成「还没闭合」，不是空白 | 参考板 Routinery 一屏一事；方法库空状态规则 | ✅ 方向；⚠️ 插画风格 |
| D16 | **完成庆祝是 900ms 一次性柔光 + 两行字，不是 confetti / 弹窗 / 音效** | 个人工具每天被打开，庆祝必须有，但不能表演。一次性的光 + 「今天到这儿」是收束，不是奖励爆炸；用户可关 | 参考板 Routinery 的安静收束；B1 不制造压力 | ⚠️ 设计判断；🔮 动效时序 |

## 2. 哪些可以大胆 / 哪些留退路 / 哪些等验证

### ✅ 可以大胆设计（本轮做满）

| 项 | 依据 |
|---|---|
| 今日环编码「今天完成几件」而非连续天数 | B1 + Anti-goals 是硬约束，不是审美选择 |
| 三级版本次等宽等高、微型完成=满格 | brief 硬规则；E07/E08 |
| 中断零红色、中性 banner、内联补记 | B1；IA J2 |
| 微型的完成与完整的完成视觉同权 | brief；A2 的核心 |
| 回顾页把「回来 2 次」作为正面统计 | 把 B1 从「不说坏话」变成「主动数好事」 |
| 习惯详情用累计次数而非天数 | 避免 streak 语义 |

### 🔮 要留退路（结构上可切换）

| 项 | 退路 |
|---|---|
| 默认预选「简化」 | 一个 token / 一个 `aria-checked` 切换回「完整」或「不预选」；A/B 结果出来前不锁死 |
| 身份路径（3 节点） | 若被读成等级，整块替换为一句行为描述 + 一个小图标；不改变页面结构 |
| 体感词（6 个） | 若跳过率高，改为每周一次；体感卡从今天屏移到回顾页 |
| 庆祝条 | 若被报告「打扰」，默认关闭，只保留「今天到这儿」的静态文案 |
| 主角 + 支持行构图 | 若习惯数增长到 4+，今天屏可切回 2 列环网格（Streaks 模式在 6+ 时是合适的）；当前结构不预留 4+ 的视觉 |
| 回顾主图 | 若用户只看数字，降级为「一个大数字 + 一句话」（IA 的回退规则） |

### 等验证结果（A2 / A4 / A5 / A1 / A3）

| 假设 | 本设计怎么体现 | 如果错了怎么改 |
|---|---|---|
| A2 三级视觉平等不降低动机 | 等宽 chip、微型满格 | 恢复完成度差异（V1 回退），但保留「微型也算数」文案 |
| A4 阶段标签可理解 | 已用行为描述（刚开始 / 有点感觉 / 已经很自然），不用内部术语 | 若仍不可理解，删掉路径，只留「你已经记了 21 次」 |
| A5 中断不焦虑提高回归率 | 中性 banner + 微型预选 + 补记 | 加一条轻量提醒（「今天从微型版开始？」），仍不用红色/失败语言 |
| A1 3 次点击内完成 | 预选简化后实际 2 次点击 | 若仍嫌重，砍掉体感（打卡 1 次点击），体感降为可选 |
| A3 体感高光有意义 | 今天仪式 + 回顾引语 + 详情记账 | 若跳过率高，每周一次，不占每日流程 |

### 如果上游变了，哪些决策要重做

| 变化 | 要重做的 |
|---|---|
| 习惯数上限从 3 提到 6+ | 今天屏构图（D1）→ 2 列网格；主角卡降为「置顶卡」；环从 1/3 变 N/M |
| 加入社交/排行榜 | 与本设计方向冲突：强调色配给、庆祝、匿名性都要重做；建议先重审 B1 |
| 加入 Apple Health / 健康数据 | 回顾页加数据源标签与单位；环的颜色语义要避免与健康 App 的红/绿冲突 |
| 从本地改为账号 + 云同步 | 今天屏加同步状态；空状态加「登录/恢复」；「数据只留在这台设备」文案删除 |
| 平板成为目标 | 回顾页双列；今天仍单列；习惯详情可左轨 + 右侧详情 |

## 3. 人类检查点（审美不能由 AI 判）

**形状**：≤5 屏 × 3 变量；总抛光精力约 15–20%。通过标准是「与两个参考系统的专家比较」，不是「我觉得好看」。

| 屏 | 变量 | 看什么 | 通过标准 |
|---|---|---|---|
| 01 今天 | 中性色暖度 | 暖纸白在日光 / 夜间 / 冷屏下是否「暖得刚好」，会不会显脏或偏黄 | 与 Things 3 并排，纸面不比它更黄；不是奶油色 |
| 01 今天 | 字体配对 | 宋体「晚读」+ 无衬线正文是否有「书页」感，而不是「文艺海报」 | 与 Craft 的 serif/sans 并排，温度接近但更克制 |
| 01 今天 | 动效时序 | 环 260ms / 对勾 160ms 是否「轻」，会不会像进度条 | 真机 3 人盲评，≥2 人说「轻/不打扰」 |
| 02 完成 | 庆祝强度 | 900ms 柔光是否太弱（没感觉）或太强（表演） | 3 人看一次，0 人说「打扰」，≥2 人说「有收束感」 |
| 03 回顾 | 图表可读性 | 不看数字，能否在 3 秒内说出「这周比上周好」 | 3 人 5 秒测试，≥2 人正确 |
| 06 回归 | 语气 | 中性 banner 是否被读成「被理解」而不是「被放任」 | V2 情景测试，≥4/5 说明天愿意再试，0 人说被评判 |
| 全站 | 苔绿色相 | 152° 深苔绿是否「生长」，还是「医疗/健康」 | 与 Streaks 的红、Habitify 的蓝并排，属于「自然/植物」而不是「医院」 |

**签名层（不由我决定）**：宋体最终选型（系统宋体 vs 购买/嵌入）、是否保留「日迹」这个名字、品牌图形语言（种子弧是否成为品牌资产）。

## 4. 需人眼确认（未验证，诚实列出）

1. **暖纸白的暖度**（hue 86 / chroma 0.007）：⚠️ 可能在夜间偏黄，或在冷暖屏上不一致。
2. **宋体在非 Apple 设备的回退**：🔮 Songti SC 在 Android/Windows 会回退到 Noto Serif SC 或 Georgia，字面与字重会变；必须真机看。
3. **苔绿的语义**：🔮 152° 深苔绿在中文语境里可能读作「健康/医疗」；需要与参考系统并排。
4. **三级 chip 的位置偏差**：⚠️ 等宽等高解决了大小/颜色，但「完整在左」仍有阅读优先；这是已知未解决问题。
5. **1/3 的压力感**：⚠️ 环内数字可能被读成「只完成三分之一」；需要 5 秒测试。
6. **中性中断的语气**：⚠️ 可能被读成「没发生」或「被放任」；V2 未做。
7. **庆祝的呼吸感**：🔮 静态截图无法验证 900ms 柔光；必须真机。
8. **回顾页的身份路径**：⚠️ 三个节点可能仍被读成等级；A4 的回退方案本身也未测。
9. **21 次 vs 28 天**：⚠️ 21 次避免了 streak 语义，但是否足够有力量、是否让人想回来，未知。
10. **空状态种子的「未闭合」**：🔮 可能被读成「没做完」而不是「正在长」；需要 5 人联想测试。

## 5. 没设计什么

- **「我」/ 设置页**：提醒、体感开关、数据导出、关于（P2）。
- **习惯列表页（一级 tab「习惯」的首屏）**：1–3 个习惯时与今天屏的支持行高度重复，本轮只画了详情；如果 Critic 认为需要独立列表，下一轮补「列表 + 新增」屏。
- **新增习惯的完整流程**：类型 → 锚点 → 三级阶梯 → 提醒（IA J4）；本轮只做了空状态的入口。
- **编辑 / 暂停 / 归档习惯**：详情页「更多」只有视觉位。
- **首次引导的多步流程**：只有一张空状态；没有账号、权限、通知授权。
- **暗色模式的页面**：令牌已配对，未出暗色截图。
- **平板 / 桌面布局**：本轮不做。
- **动效的可点击原型**：HTML 是静态设计件，没有 JS；交互在 `ui-spec.md` 定义。
- **通知文案与提醒策略**：属于产品/增长，不在 UI 边界。

## 7. 交接

### 这轮重点设计了什么

- 今天屏的默认态、完成态、中断回归态（3 屏）。
- 回顾屏的数据叙事：完成率、图表、回归次数、体感高光、身份路径。
- 习惯详情：三级阶梯的等权视觉、28 日热力图、身体记账。
- 空状态的邀请。
- 设计系统：三层令牌、10 个组件、10 轴锚定、暗色配对。

### 没设计什么

见 §5。尤其：「我」页、新增习惯流程、加载/错误态的视觉。

### 请 Critic 重点看

1. 三级版本次的「平等」是否只是尺寸平等，位置/顺序是否仍在暗示高低（D5）。
2. 中断 banner 是否真的不羞辱，还是只是「把红色拿掉」（D7 / A5）。
3. 回顾页的「回来 2 次」是否会被读成另一种考核（D8）。
4. 1/3 环内数字的压力感（人眼 5 秒测试）。
5. 完成态是否「太安静」——庆祝强度是否足够让人想再回来（D16）。

### 给 Definer 的反哺

- **IA 的「连续 30 天一次性庆祝」与 B1 anti-goal 冲突**。本设计把它改成「累计第 30 次记录」的反思条，不是连续天数徽章。这是一个产品级冲突，需要 Definer 确认。
- 「今天优先」的结构在 1–3 个习惯下成立；如果用户第一句话是「我有哪些习惯」，需要切到 B 结构（习惯优先）。本轮的主角卡 + 支持行在 3 个习惯内够用，4+ 会失效。
- 「补记昨天」需要一条规则：补记写历史，但不改变今天的环与「回来」叙事；否则补记会变成恢复连续天数的后门。

### 给 Architect 的反哺

- 状态矩阵缺「无锚点」：没有触发锚点的习惯无法生成今天的卡片，主按钮必须禁用并给出去设置的路。已在 `ui-spec.md` 2.3 补。
- 状态矩阵缺「部分失败」：回顾页的图、统计、体感可能分别失败；需要按块降级，不是整页错误。
- 建议 IA 增加「同步状态」节点：本地优先会带来「已存在本机，联网后同步」的常态，不是异常。

---

## 8. 一句话总结

**把「打卡」从考核改成留一笔：环数今天、不数连续；三个版本同权；中断用中性色接住；回顾用累积的好事而不是不中断的纪录。** 这套设计的风险不在视觉，在 A2/A4/A5 三个未验证假设——所以三级平等、身份路径、回归语气都留了可切换的退路，没有把 🔮 当 ✅ 做满。
