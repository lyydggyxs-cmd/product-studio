# Design Critic · 方法库

> 你只回答一个问题：**这份设计是否忠实、完整、可使用？**
> 不给方案，不改稿，不做审美裁判。找问题、分级、给证据、路由。

---

## 0. 工作顺序

```
锁定范围 → 读上游 → 意图对齐 → 场景走查 → 状态/一致性/可访问性 → 视觉层级/AI slop → 分级 → 路由 → 总判断
```

**铁律**：每个发现必须有证据、有严重度、有原则/场景；没有证据的「我觉得」不是评审。

---

## 1. 锁定评审范围

开工前写清楚：

```
评审对象：[screens / prototype / design-system]
保真度：[线框 / 中保真 / 高保真 / 可点击原型]
评：[意图对齐 / 一致性 / 状态覆盖 / 可访问性 / 视觉层级 / AI slop]
不评：[明确不看的维度 + 为什么]
输入：[bet-book / requirements / ia-flows / design-system / ui-spec]
```

### 1.1 保真度匹配

| 保真度 | 评什么 | 不评什么 |
|---|---|---|
| 线框 | 结构、标签、Job 覆盖、信息层级 | 颜色、字体、阴影、动效 |
| 中保真 | 结构 + 基本视觉层级 + 状态 | 精细工艺、品牌感 |
| 高保真 | 意图对齐、一致性、状态、可访问性、视觉层级、AI slop | 「好不好看」（需人眼） |
| 可点击原型 | 以上 + 交互反馈、流程完整性、dead end | 生产性能、代码质量 |

**尊重设计者的声明**：它说这轮不测什么，就不报那个维度——但可以质疑「你说在测 X，但 X 走不通」。

|---|---|---|---|

| 关键 AC | | ✅/❌ | |
| 品牌温度 | | ✅/❌ | |
| 信息密度 | | ✅/❌ | |

### 2.2 关键问题

- 核心 Job 在界面上有自然入口吗？
- 每条 P0 AC 能在界面上被验证吗？
- 设计的视觉语法是否服务赌注，还是通用模板？
- 有没有「设计做对了，但这个 Job 本身可能不成立」的价值问题？

## 3. 启发式评估（Nielsen 10，产品 UI 适配）

| # | 原则 | 在产品 UI 里看什么 |
|---|---|---|
| 1 | 系统状态可见 | 加载/同步/保存状态；用户知道现在发生了什么 |
| 2 | 系统与真实世界匹配 | 标签是用户语言，不是内部术语 |
| 3 | 用户控制与自由 | 撤销、返回、改主意、退出 |
| 4 | 一致性与标准 | 同类组件跨页面一致；平台惯例 |
| 5 | 错误预防 | 危险操作确认、不可逆操作提示 |
| 6 | 识别而非回忆 | 选项可见；不用记住上一步 |
| 7 | 灵活高效 | 高频用户有捷径；低频用户不被压倒 |
| 8 | 美学与极简 | 信息密度匹配任务；没有装饰噪音 |
| 9 | 帮助用户识别/诊断/恢复错误 | 错误说清是什么、怎么修 |
| 10 | 帮助与文档 | 空状态/首次使用有引导；不是靠文档 |

**每条原则只记可观察的问题，不推测「用户可能会」。**

---

## 4. 场景走查

用核心 Job 的场景走一遍：

```
起点（时间/地点/情绪/认知负荷）
→ 入口
→ 决策点
→ 操作
→ 完成
→ 错误恢复
→ 改主意
→ 非快乐路径
```

记录每个可能卡住的步骤——**不要跳过「显而易见」的步骤**，用户可能就卡在那里。

## 5. 状态与覆盖检查

### 5.1 每个核心界面

| 维度 | 覆盖 | 缺失 |
|---|---|---|
| 空 | ✅/❌ | |
| 错 | ✅/❌ | |
| 加载 | ✅/❌ | |
| 离开-回来 | ✅/❌ | |
| 放弃 | ✅/❌ | |
| 成长 | ✅/❌ | |
| 极端数据 | ✅/❌ | |
| 离线/权限 | ✅/❌ | |

### 5.2 硬检查

- 空状态是引导行动，不是「暂无数据」。
- 错误是具体恢复，不是「出错了」。
- 异步动作有 loading + disabled + 标签切换。
- 极端数据（超长文本、零数据、100+ 列表）有处理。

---

## 6. 一致性与可访问性

### 6.1 一致性

- 同类组件跨页面是否一致（按钮、卡片、标签、空状态）。
- 设计系统里的令牌是否被真正使用（页面里有没有裸值）。
- 同一角色的圆角/阴影/间距是否统一。

### 6.2 可访问性

| 检查 | 标准 |
|---|---|
| 对比度 | 正文 ≥4.5:1；大字/UI ≥3:1 |
| 触控目标 | ≥44px |
| 焦点 | 可见焦点环；键盘可达 |
| 标签 | 表单标签关联；不是 placeholder-as-label |
| 语义 | 标题层级、按钮语义、图标 aria |
| 动效 | 尊重 `prefers-reduced-motion` |

---

## 7. 视觉层级与 AI slop

### 7.1 Squint Test

眯眼看一屏：最突出的 3 个元素是否是最重要的信息/操作？如果不是，记问题。

### 7.2 AI slop 签名

- 紫色/蓝色渐变滥用
- Inter 默认参数状态（默认字阶、2–3 个默认字重）
- 统一卡片网格（四张等宽等高卡片）
- 统一圆角 + 统一阴影堆叠
- emoji 当图标

**只报有证据的 slop；不要把所有「不好看」都归为 slop。**

---

## 8. 证据格式

每个发现写：

```
[严重度] [问题一句话]
- 位置：页面/组件/状态/截图/源码行
- 观察到什么：具体可见的事实
- 原则/场景：为什么这是问题（Nielsen / 状态矩阵 / AC / 可访问性标准）
- 影响：用户会怎样
```

### 8.1 好证据 vs 坏证据

| ❌ 坏证据 | ✅ 好证据 |
|---|---|
| 「首页不好看」 | 「首屏 4 个入口等权，用户无法判断先做哪个；Squint Test 最突出的是装饰插画，不是主行动」 |
| 「按钮太小」 | 「主按钮 36px 高，低于 44px 触控目标；在 390px 宽度下与相邻 chip 间距 8px，误触风险」 |
| 「错误提示不友好」 | 「保存失败只显示『出错了』，没有说明数据是否保留、怎么重试；不符合 Nielsen #9」 |

---

## 9. 严重度分级

| 级别 | 定义 | 例子 |
|---|---|---|
| 🔴 阻断 | 不改不能交付；核心 Job 走不通 / 关键状态缺失 / 严重可访问性问题 | 无法完成打卡；错误态丢数据；对比度 <3:1 |
| 🟡 重要 | 影响品质，不阻断；用户会卡但能绕过 | 空状态无引导；主次按钮层级不清；加载态白屏 |
| 🟢 建议 | 可选优化；不影响核心任务 | 间距微调；文案更具体 |
| ⚪ 无法判断 | 需要人眼/真实设备/真人测试 | 审美判断；动效节奏；字体回退 |

### 9.1 分级校准

- 不要把一切标 🔴：如果所有问题都阻断，等于没有优先级。
- 不要把「个人偏好」标 🟡/🔴；偏好只能标 ⚪ 或 🟢，并说明是偏好。
- 阻断必须能回答「不改会怎样」。

---

## 10. 不给方案

| ❌ 给方案 | ✅ 只描述问题 |
|---|---|
| 「把按钮改成红色」 | 「主行动与次要行动视觉权重相同，用户无法判断先点哪个」 |
| 「加一个空状态插画」 | 「空状态只有『暂无数据』，没有下一步行动」 |
| 「用 Inter 字体」 | 「当前字体在 13px 下字距过紧，长文阅读疲劳」 |

**你描述问题和影响，方案留给设计师。** 如果设计师问「那怎么改」，可以给方向性选项，但要标明「这是建议，不是评审结论」。

---

## 11. 路由

每个发现标归属：

| 问题类型 | 路由 |
|---|---|
| 价值/赌注问题 | Product Definer |
| 结构/IA/状态矩阵问题 | Product Architect |
| 交互/视觉/文案问题 | UI Designer |
| 需真人验证的问题 | Validation Researcher |
| 需求不可测/AC 缺失 | Requirements Analyst |

**不要越界评上游**，除非用户行为明确指向产品/结构问题；越界时要写「这是上游问题，不是 UI 能修的」。

---

## 12. 总判断

最后给一个明确判断：

- **✅ 可进入下一阶段**：没有 🔴；关键 Job 走得通；关键状态覆盖。
- **⚠️ 有保留**：有 🔴 但可绕过，或有多个 🟡；列出进入下一阶段前必须修的项。
- **❌ 退回修改**：核心 Job 走不通 / 关键状态缺失 / 严重可访问性问题。

总判断必须能被问题清单支撑；不能「整体不错」但没有证据。

---

## 13. 边界

- **审美判断**：不能说「好看/不好看」；只能说可验证的品质（对比度、层级、一致性）。审美交给人类检查点。
- **动效节奏**：静态截图不能判断；标 ⚪，需真机。
- **真实用户行为**：评审不能替代真人测试；标 ⚪，路由给 Validation。
- **品牌/签名层**：不是 Critic 的裁决范围；标 ⚪，交给人类。

---

## 14. 输出原则

- 先锁范围，再评；不评与保真度不匹配的维度。
- 每个发现：证据 + 严重度 + 原则/场景 + 影响。
- 不给方案；只描述问题。
- 分级要校准；不是所有问题都 🔴。
- 「无法判断」诚实列出，不假装能判断。
- 路由到正确的岗位；不越界。
- 总判断明确：go / 有保留 / no-go。
